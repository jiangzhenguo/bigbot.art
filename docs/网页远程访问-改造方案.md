# 网页远程访问 — 改造方案

> 状态:方案(未实施,2026-10-22)。本文只定方向与边界,不含代码改动。
> 对照代码:`packages/shared/src/index.ts` 的 `BigBotArtApi`(122 个成员)、`apps/desktop/src/preload/index.ts`、`apps/desktop/src/main/index.ts` 的 116 个 `ipcMain.handle`、`apps/desktop/src/main/assets.ts` 的 `bba-asset://` / `bba-output://` 与 `rangeFileResponse`。
> 读者:实现这个功能的人。落地时同步 `CLAUDE.md` 环境变量表与 `.env.example`;节点行为不变,不必改 `docs/节点手册.md`。

## 0. 决定(先看这段)

在 Mac 上继续跑 Electron。生成(h3.c / mlxgen / ffmpeg)不搬家。浏览器不直连模型,只连这台 Mac 上**默认关闭**的远程服务。

| 项 | 决定 |
|---|---|
| 网络 | 第一期只走 Tailscale。进程绑 Tailscale IPv4(外加回环,方便在 Mac 自己的浏览器里验收)。**不绑 `0.0.0.0`**,没有 Tailscale 就不对外监听。Funnel / Cloudflare Tunnel 不在第一期。 |
| 认证 | Tailscale 之上仍要口令。Mac 上生成一次高熵令牌,浏览器提交一次,换成 `HttpOnly` + `SameSite=Strict` cookie。令牌明文不进 `settings.json`,也不进 `getSettings()`。 |
| 契约 | `BigBotArtApi` 仍是唯一类型事实来源。旁边加一份**编译期对得齐**的方法目录(通道名、事件还是 RPC、是否碰路径/对话框/长任务)。IPC 与 HTTP 调用同一套 handler,不复制业务。 |
| 传输 | `POST /rpc`(方法名 = TypeScript 方法名,参数按 IPC 的位置参数数组)+ WebSocket `/events` 推现有 6 个频道。浏览器 `<img>` / `<video>` 发不了 Authorization 头,所以媒体走 cookie,不走 query token。 |
| 媒体 | 复用 `rangeFileResponse`。HTTP 路径模仿现有自定义协议的**相对名**,不接受绝对路径。白名单 = 现有 `outputSearchRoots()` + `ASSETS_DIR` + `ffmpegReadRoots()` 那一套,再用 `realpath` 防符号链接逃逸。 |
| 渲染层 | 不改上百处 `window.bigbotart`。网页入口在没有 preload 时把同一接口的 HTTP 实现挂到 `window.bigbotart`。媒体 URL 用显式开关,默认仍是 `bba-asset://` / `bba-output://`(现有单测依赖这个)。 |
| 桌面专属 | 远程调用**禁止**弹出 Mac 上的系统对话框、禁止 `revealInFinder`。第一期这些按钮在网页里隐藏;第二期改成上传/下载。 |
| 并发 | 不引入 CRDT。沿用 `saveCanvasSnapshot` 的 version 闸和空快照闸。先把今天只推给主窗口 `win` 的事件改成扇出,否则浏览器看不到 Agent 流式事件和画布增量。 |
| 真实推理 | 红线 R2 不动。远程服务不改 `BIGBOTART_DRYRUN`。`renderMode` 仍要用户在设置里打开。 |
| 触屏 | 第二期再做,详见 §11。鼠标与触控板的现有语义保持不变;只有 `pointerType === 'touch'` 走捏合、单指平移和长按。平板把画布做完整,手机优先提交、看进度、Agent 对话。 |

和最初方向不一致、需要按代码改口的地方,集中在 §2。

## 1. 目标与非目标

单用户(机主本人)。手机、平板、另一台电脑的浏览器打开同一套 React UI,操作这台 Apple Silicon Mac 上的画布和队列。

**第一期(能用)**

- 设置里打开远程访问,看到 Tailscale 地址。
- 浏览器登录一次。
- 打开项目、看画布、改画布并保存、提交渲染、看到队列进度和 Agent 事件、用 Range 播放/查看已有产物。

**第二期(补齐文件与小屏)**

- 资产上传、封面上传、技能包上传、项目包导入。
- 成片与 `.bba` 下载(替代「另存为」)。
- 触屏与窄屏(§11)。第一期允许手机上出现桌面宽度,靠页面缩放看;手势、44px 热区和底栏在第二期。

**明确不做**

- 多用户、账号体系、把生成搬到服务器。
- 把服务暴露到公网(Funnel、Cloudflare Tunnel、路由器端口转发)。
- 改 `BigBotArtApi` 的方法语义来迁就 HTTP(位置参数、返回值、`stale` 约定都保持)。
- 协同编辑(OT/CRDT)。两个画面同时改同一画布时,后保存的一方收到 `stale` 后刷新。
- 在远程路径上默认进入真实推理。

## 2. 对照代码后要改口的前提

下面几条不是否决「主进程里加一个可选 Web 服务」,而是避免按想象去接。

### 2.1 事件今天没有全部扇出

`RenderQueue.onChange` 和风格包进度已经发给**所有** `BrowserWindow`。下面这些只发给模块级 `win`(第一个窗口):

| 频道 | 位置 | 后果 |
|---|---|---|
| `agent-event` | `index.ts` 的 `agent.onEvent`、对话终局 `done`/`failed`、自动续跑、连续性校验 | 浏览器收不到工具卡和终局;桌面窗口也收不到「从浏览器发起的那轮」以外的缺口——只要 `win` 还在,桌面收得到,浏览器收不到 |
| `canvas-snapshot-updated` | `store.onCanvasSaved` | Agent 改画布、另一端保存,浏览器状态不刷新,下一次保存会被 version 闸拒绝 |
| `video-post-progress` | `video-upscale` 的 `onProgress` | 超分进度只出现在主窗口 |
| `debug-log` | `wireDebugLog` 按窗口订阅 | 网页要单独订一次 |

第一期的第一刀是一个进程内 `EventHub`:上述 `webContents.send` 改成 hub 发布,Electron 窗口和已登录的 WebSocket 都订阅。队列那条已经扇出的路径并进同一个 hub,避免两套广播。

### 2.2 媒体服务已经有了,缺的是 HTTP 外壳

`bba-asset://` / `bba-output://` 走 `protocol.handle` + `rangeFileResponse`(`assets.ts`)。这是为了修「视频能播但进度条拖不动」:必须回 `Accept-Ranges` / `206` / `Content-Range`,并且用 `Readable.toWeb`,不能把 Node 流硬塞进 `Response`(2026-10-12 主进程弹窗事故)。

HTTP 媒体处理器**调用同一个 `rangeFileResponse`**,不要重写 Range 解析。自定义协议在网页里不存在,所以渲染层在网页模式把 URL 换成同源路径(§6),协议处理器本体留在桌面。

### 2.3 路径白名单不是「只有 `BIGBOTART_HOME`」

`DATA_DIR` 默认 `~/.bigbotart`,可被 `BIGBOTART_HOME` 覆盖。产物根 `OUTPUTS_DIR` 另有规则(`pickOutputsDir`):

- 打包版固定 `DATA_DIR/outputs`。
- 开发版会选中仓库里的 `.bigbotart/outputs`(历史产物在这里,2026-10 装过「画布视频全部消失」)。
- `BIGBOTART_H3_OUTPUTS` 可以指到数据目录之外。

若 HTTP 只允许 `BIGBOTART_HOME` 之下,开发版和自定义产物目录的预览会黑屏。白名单应与现有读路径一致:

- 资产协议:`ASSETS_DIR` + 文件名正则 `^asset-[A-Za-z0-9._-]+$`
- 产物协议:`isValidOutputRelName` + `outputSearchRoots()`(含导出目录、开发版 cwd 候选)
- 方法参数里的路径:`ffmpegReadRoots()` / `importAllowRoots()` / `isUnderRoot`(取帧、裁切、拼接、探测、归档已经这么做)

在此之上补 `realpath`:今天的 `isUnderRoot` 只用 `resolve`,符号链接可以跳出根目录。远程比本机对话框更容易被喂一条精心构造的路径,这一层要补上。拒绝清单:空串、`..`、绝对路径出现在**媒体 URL** 里、控制字符、反斜杠(与 `isValidOutputRelName` 一致,中文文件名必须继续合法——2026-10 中文成片名黑屏事故)。

RPC 参数里的绝对路径仍然要(画布 JSON 里存的就是 Mac 绝对路径,提交渲染时原样送回)。服务端用上面的根目录再验一次,**不把「客户端声明的路径」当成授权**。

### 2.4 长任务的 Promise 语义先别改

`agentChat` 已经是「立刻 `{ accepted: true }`,结果走 `AgentEvent` 的 `done`/`failed`」。队列提交返回 handle,进度走 `onQueueChanged`。`mlxgenDownload` / `exportTimeline` 也是 jobId + 轮询。

仍会把 HTTP 连接挂很久的只有少数阻塞方法,主要是 `videoUpscale`(注释写明分钟级,进度靠 `onVideoPostProgress`)和 `styleModelBuild`、`llmLoadModel`(首次可能拉模型)。Tailscale 直连没有云厂商的 100 秒空闲切断,第一期允许这些 RPC 一直等到 Promise resolve,桌面 IPC 行为不变。

Funnel / Cloudflare Tunnel **不能**沿用这个假设(边缘有空闲超时)。那一期再在 HTTP 适配器里把「阻塞等待」藏起来:服务端照旧跑完,网页客户端改听完成事件。`BigBotArtApi` 对 React 仍是一个 Promise。不要为了隧道去改 IPC 签名。

### 2.5 对话框不能在远程请求上弹到 Mac 屏幕

`uploadProjectCover`、`importAssets`(不传 `paths`)、`importSkill`、`saveExportAs`、`exportProjectPackage`(不传 `path`)、`importProjectPackage`(不传 `path`)会 `dialog.showOpenDialog` / `showSaveDialog`。若网页直接打到现有 handler,手机会让 Mac 突然弹出文件框。

远程适配器在进 handler 之前截下这些调用,返回 `{ ok: false, error: '远程不支持系统对话框' }`(或既有的 `canceled: true` 形态,二选一,实现时与现有 UI 的取消分支对齐)。不要把「调用方是网页」做成客户端自报的参数——客户端会撒谎。截断放在远程分发器,IPC 路径不经过它。

`importAssets({ paths })` 今天已有白名单。远程第一期仍走这道白名单(不能读 `DATA_DIR` 以外),但不接受浏览器随口传来的任意字符串去「导入」;第一期 UI 不提供导入。第二期上传落到 `DATA_DIR` 下的暂存目录,再调用现有 `importFromPaths`。

### 2.6 令牌不能放进 `AppSettings`

`getSettings()` 把整个 `AppSettings` 交回渲染层,并会经 HTTP 再交一次。`settings.json` 也没有 0600 的约定。访问令牌若写在这里,等于任何已登录会话(以及一份被拷走的设置文件)都能再看到明文。

设置里只放非秘密开关:`remoteAccess.enabled`、`remoteAccess.port`。令牌的哈希放在 `BIGBOTART_HOME/remote-access.json`(模式 `0600`)。生成或轮换时,明文只在桌面设置页出现一次。

HTTP 的 `setSettings` 丢弃 `remoteAccess` 字段。开关只在桌面设置页生效,避免一个已盗用的 cookie 把监听面改掉。主题、语言、`renderMode` 允许机主从浏览器改——那是一次明确操作,不是服务偷偷把 dry-run 关掉。环境变量 `BIGBOTART_DRYRUN` 远程改不了,要改仍须重启 App(与 §0.5 一致)。

### 2.7 网页里不要重写每一处 `window.bigbotart`

渲染层直接调用 `window.bigbotart` 的文件很多(画布、设置、首页、Agent、资产)。preload 在页面脚本之前把实现挂上(`contextBridge.exposeInMainWorld('bigbotart', api)`)。网页构建没有 preload。

做法:网页入口检测 `window.bigbotart`,没有则挂上 HTTP 客户端。Electron 里 preload 先执行,挂载会被跳过。这样桌面路径的运行时行为不变。类型仍是 `BigBotArtApi`(`env.d.ts`)。

媒体 URL 不能靠「有没有 `window.bigbotart`」来分支,因为网页同样会有这个对象。preload 额外暴露只读标志 `window.bigbotartShell = true`。`previewUrlOf` / `thumbSrc` / `outputUrlOf`(`pages/canvas/media.tsx`)在标志为假时产出 `/media/output/...` 与 `/media/asset/...`。Node 单测不设这个标志,断言继续是 `bba-output://` / `bba-asset://`。

### 2.8 第一期不要代理 Vite 开发服务器

`electron-vite dev` 的渲染进程依赖 preload,并且只该留在本机。远程服务只托管**已构建**的 `apps/desktop/out/renderer`,与 API 同源(cookie、`Origin` 才简单)。开发时 Electron 窗口仍走 HMR;浏览器看到的是上一次 `electron-vite build` 的渲染产物。这是有意的限制,写进设置页说明,避免把 Vite 绑到 Tailscale IP。

## 3. `BigBotArtApi` 盘点

统计自 `packages/shared/src/index.ts` 的 `interface BigBotArtApi`(与 `ipcMain.handle` 交叉核对):

- 成员 **122**
- 其中请求/响应 **116**(与 `index.ts` 里 `ipcMain.handle` 的数量一致)
- 事件订阅 **6**(preload 用 `ipcRenderer.on`,返回退订函数,没有对应的 `handle`)

事件不进 `/rpc`。WebSocket 频道沿用现有 IPC 频道字符串,避免第三套名字。

| 频道常量(现有 IPC) | 方法 | 载荷 |
|---|---|---|
| `render-queue-changed` | `onQueueChanged` | `RenderJob[]`(已是 `slimList`,无 `req` 大对象) |
| `canvas-snapshot-updated` | `onCanvasSnapshotUpdated` | `CanvasSnapshot` |
| `video-post-progress` | `onVideoPostProgress` | `VideoPostProgressEvent` |
| `style-model-progress` | `onStyleModelProgress` | `StyleModelProgress` |
| `agent-event` | `onAgentEvent` | `AgentEvent`(`tool-start` / `tool-end` / `thinking` / `done` / `failed` / `aborted` / `continuity` / `auto-start`) |
| `debug-log` | `onDebugLog` | `DebugLogEntry` |

退订只发生在客户端(从本地 Set 移除回调)。单用户、六个频道,服务端对每个已认证 socket **全量推送**,不做订阅协商。重连后的补齐靠现有的拉取方法,而不是回放缓冲:`queueStatus`、`loadProjectCanvases` / 快照推送、`videoPostRunning` + `videoPostLastProgress`、`chatThreadMessages`(Agent 终局已写入 recall)。断线期间的工具卡可能缺几拍,重进会话能看到已落盘的结果。第一期不做事件日志回放。

### 3.2 需要特殊处理的成员

其余 RPC 是「JSON 进、JSON 出」的普通调用,走同一个 `/rpc` 即可。下表是例外。

**系统对话框(远程分发器直接拒绝,不进 Electron `dialog`)**

| 方法 | 桌面行为 | 第一期网页 | 第二期 |
|---|---|---|---|
| `uploadProjectCover` | 打开图片 | 隐藏按钮 | `multipart` 上传后走现有拷贝进项目资源库 |
| `importAssets()` 无 `paths` | 打开多文件 | 隐藏 | 上传到暂存目录再 `importFromPaths` |
| `importSkill` | 打开文件夹或 zip | 隐藏 | zip 上传 |
| `saveExportAs` | 另存为 | 隐藏 | `GET` 成片,`Content-Disposition` |
| `exportProjectPackage` 无 `path` | 另存为 `.bba` | 隐藏 | 服务端写入暂存后流式下载,不把 gzip 包塞进 JSON |
| `importProjectPackage` 无 `path` | 打开 `.bba` | 隐藏 | 上传后调用现有导入(永远新建项目,不覆盖) |
| `revealInFinder` | Finder 选中 | 隐藏 | 不映射。网页没有 Finder;需要文件时走下载 |

**路径参数(服务端用现有根目录再验一次;网页不新开读权限)**

| 方法 | 路径在哪 | 现有闸门 |
|---|---|---|
| `probeMedia` | 第 1 参 | `ffmpegReadRoots` + `isUnderRoot` |
| `archiveProducts` | `items[].path` | 资产归档内部校验 |
| `extractFrame` / `extractAudio` | 视频路径 | `frames.ts` 同一组根 |
| `cropImage` / `splitImage` | `path` | 同上 |
| `stitchImages` | `paths[]` | `stitch.ts` |
| `videoUpscale` | 请求体内输入路径 | `video-post.ts` |
| `importAssets({ paths })` | `paths` | `importAllowRoots`;远程第一期 UI 不调用 |
| `accelInstall` | 本机模型目录 | 桌面设置页的本机路径。网页第一期隐藏「安装模型包」(手机上没有那个目录) |
| `exportFilePath` | 返回绝对路径 | 只解析导出目录内文件名。网页可以拿返回值去拼媒体 URL,不要把这个路径显示成可编辑文本框 |

画布、Take、资产列表的响应里**继续带 Mac 绝对路径**(`Asset.localPath`、`Take.resultPath`、节点 `data.resultPath`)。渲染层用它们提交下一步(取帧、增强、参考图),也用它们推导预览 URL。第一期不在协议层把路径改成相对名——那会破坏桌面端和已有项目文件。信息暴露面是「已登录的机主能在响应 JSON 里看到自己的用户名和目录」,可接受。不要为了隐藏用户名把路径从契约里删掉。

**流式 / 长任务**

| 方法 | 处理 |
|---|---|
| `on*` 六个 | 只走 WebSocket。HTTP 客户端的退订函数不发 RPC |
| `agentChat` | HTTP 很快返回 `accepted`。工具卡与终局全靠 `agent-event`。同一 `projectId:canvasId` 已有 `inFlightChats` 单飞锁,桌面和浏览器共用这把锁 |

## 4. 传输:一份契约,两套外壳

### 4.1 方法目录放在 `@bigbotart/shared`

新文件 `packages/shared/src/api-catalog.ts`,由 `index.ts` 再导出。目录是数据,类型用它和 `BigBotArtApi` 互相卡死:

- 目录里的每个名字 ∈ `keyof BigBotArtApi`
- `keyof BigBotArtApi` 的每个名字都在目录里
- 漏一个或多重一个,`tsc` 失败

每条记录至少包含:

- `name`
- `kind: 'rpc' | 'event'`
- `ipcChannel`(RPC 为 kebab-case;事件用 §3 的表)
- `flags`: `dialog` | `pathArg` | `long` | `large` | `secret` 的子集(给远程分发器和测试用,不给渲染层做授权判断)

preload、`ipcMain.handle` 注册、HTTP 分发都读这份目录的频道名。今天频道字符串在 preload 与 `index.ts` 各写一遍,新增方法容易只改一头。目录补上之后,`pnpm typecheck` 能抓住「接口加了方法但目录没有」。handler 对象少实现一个方法,同样由 `satisfies` 的映射类型抓住。

这是「单一事实来源」的具体含义:**类型在接口上,频道与分类在目录上,业务函数只有一份**。HTTP 不另起一套 REST 资源名(`/projects/:id/canvases` 这类会和契约分叉)。

### 4.2 Handler 只实现一次

`apps/desktop/src/main/index.ts` 已经约 1800 行,红线是不要再往里堆。新增远程服务必须是独立模块。

把 116 个 handle 的函数体移到 `apps/desktop/src/main/api-surface.ts`,导出 `createApiSurface(ctx): RpcHandlers`。闭包依赖(store、queue、agent、logger…)收成一个 `ctx`,这是移动过程中唯一允许的结构调整,行为不变。

两处外壳:

1. `registerIpc(surface)`:按目录 `ipcMain.handle(channel, (_e, ...args) => surface[name](...args))`。事件仍由 hub 推到 `webContents`。
2. `startRemote(surface, hub, settings)`:见 §4.3。

移动应当单独提交,先于任何 HTTP 行为:类型通过、现有 vitest 通过、桌面手工点一条保存和一条队列即可。不要把「搬家」和「加服务器」混在同一个 diff 里审。

`api-surface.ts` 会很长,但那是按契约生成的平面列表,比继续胀 `index.ts` 好找。若单文件超过可读范围,按 §3.1 的域拆成 `api-surface/*.ts`,由 `createApiSurface` 合并。合并结果必须 `satisfies` 完整 RPC 映射。

### 4.3 HTTP 与 WebSocket

监听见 §7。协议保持小:

**`POST /rpc`**

```json
{ "method": "loadProjectCanvases", "params": ["proj-…"] }
```

成功:`{ "ok": true, "result": <handler 返回值> }`。失败:`{ "ok": false, "error": "<message>" }`,HTTP 状态 4xx/5xx。`method` 必须在目录里且 `kind === 'rpc'`。未知方法 404。`params` 不是数组则 400。

handler 抛错时记日志总线(R6)再返回错误字符串,不要把堆栈给浏览器。

`dialog` 标志的方法不调用 surface,直接返回 §2.5 的错误。

**`GET /events`(WebSocket 升级)**

鉴权通过后,hub 的每条发布写成文本帧:

```json
{ "channel": "render-queue-changed", "payload": [] }
```

客户端 `onQueueChanged` 等只是本地订阅者。socket 关闭即停止推送。心跳用 WebSocket ping,间隔 25s,便于 NAT 和手机休眠后尽快发现死连接。

依赖:Node 22 没有 WebSocket **服务端**。引入 `ws` 这一个依赖(实现时按仓库惯例说明用途后再装)。事件全是服务端到客户端,若当时不想加依赖,可以用 `text/event-stream` 达到同等语义;首选仍是 WebSocket,与本方案的传输约定一致,也方便以后若要做客户端回传(本期不需要)。

**静态资源**

`GET /` 与静态文件只从 `out/renderer` 读,`path.relative` 必须落在该目录内。没有构建产物时,设置页开关可以打开,但页面提示「先完成一次 renderer 构建」,不要去绑 Vite。

**媒体**

见 §6。`GET /media/asset/<filename>` 与 `GET /media/output/<相对路径>`。

**会话**

`POST /session` 提交口令,成功后 `Set-Cookie`。`POST /session/logout` 清 cookie。`GET /session` 返回 `{ ok: true }` 或 401,供网页入口决定显示登录页还是主界面。登录页可以是主包里的一条路由;未登录时 `/rpc`、`/events`、`/media` 一律 401,静态 JS 本身不是秘密。

### 4.4 网页客户端

新文件 `apps/desktop/src/renderer/src/api/http-api.ts`,导出 `createHttpApi(): BigBotArtApi`。

- RPC:`fetch('/rpc', { method:'POST', credentials:'same-origin', body })`
- 事件:一条 WebSocket,按 `channel` 分给本地监听器;退订不通知服务器
- 断线重连(退避,上限 15s)。`onopen` 时不重放;调用方本来就会在挂载时 `queueStatus()` / 拉画布
- `long` 方法的 `fetch` 不设短超时
- 实现对象标注 `satisfies BigBotArtApi`

入口(`renderer` 的 main)在挂载 React 之前:

```ts
if (!window.bigbotart) {
  window.bigbotart = createHttpApi();
}
```

preload 侧增加 `contextBridge.exposeInMainWorld('bigbotartShell', true)`,渲染层用它切换媒体 URL 和隐藏桌面按钮。不要用 userAgent 猜 Electron(桌面壳里的 Chrome 与普通 Chrome 会误判)。

## 6. 媒体 URL 与路径安全

桌面今天的推导(`media.tsx`):

- 路径里含 `/outputs/` → `bba-output://` + `/outputs/` 之后的相对段(逐段 `encodeURIComponent`)
- 否则当作资产,取文件名 → `bba-asset://<filename>`

网页模式产出同样的相对段,只换前缀:

- `/media/output/<相对段>`
- `/media/asset/<filename>`

服务端解析必须复刻 `protocol.handle` 的两段逻辑(`index.ts` 里 `bba-asset` 与 `bba-output` 的 handler),包括:

- 资产文件名正则,`resolve` 之后必须仍在 `ASSETS_DIR` 下
- 产物名走 `isValidOutputRelName`,再在 `outputSearchRoots()` 里逐个拼接,前缀不匹配就 `continue`
- 命中后把 `Range` 头交给 `rangeFileResponse`

额外只做三件事:

1. `realpath` 之后再验一次仍在对应根下(防符号链接)。
2. 不接受 URL 里出现盘符、`file://`、绝对路径。客户端若只有绝对路径,先在浏览器里切出相对段再请求;切不出来就不要发请求(与今天 `outputUrlOf` 退回 basename 的行为对齐,由多根查找兜底)。
3. cookie 鉴权。`<video>` 的 Range 请求会带同源 cookie。**禁止** `?token=`(会进日志和 Referer)。

响应头沿用 `rangeFileResponse` 已有的 `content-type`、`accept-ranges`、`cache-control: no-cache`。不要加 `Access-Control-Allow-Origin: *`。媒体与页面同源,不需要 CORS。

上传(第二期)是另一条路由 `POST /upload`,字段限制扩展名与 2GB 上限(与 `AssetStore` 的 `MAX_FILE_SIZE` 一致)。文件先落在 `DATA_DIR` 下的暂存目录,再交给现有导入函数。暂存目录本身也在白名单内。处理完删除暂存。不要让上传的原始文件名参与 `join` 而未过滤。

## 7. 认证、绑定与默认关闭

### 7.1 默认关闭

- `AppSettings.remoteAccess` 缺省视为 `{ enabled: false }`。老 `settings.json` 无此字段,不需要迁移脚本。
- `enabled !== true` 时不 `listen`,不占端口。
- 启动日志写一行「远程访问关」或「远程访问开 · 地址 · 非 dry-run 与否」,便于和 R2 的启动日志放在一起看。不要把令牌写入这条日志。

桌面设置页(通用区)提供:开关、端口(默认 **47321**)、「生成新口令」、口令只显示一次的复制框、当前监听 URL(Tailscale IP 与 MagicDNS 名,解析失败就只显示 IP)。关闭开关立即 `close()` 服务器。

### 7.2 绑哪里

1. 开关打开时执行 `tailscale ip -4`(超时几秒)。
2. 成功:监听该地址 + `127.0.0.1`,同一端口。回环只为了机主在 Mac 浏览器里点验收,不替代 Tailscale。
3. 失败:**不监听** LAN 地址,设置页显示「未检测到 Tailscale,远程访问未启动」。不要静默退回 `0.0.0.0`。显式设置 `BIGBOTART_REMOTE_LOOPBACK=1` 时只绑 `127.0.0.1`,给没有 Tailscale 的 dry-run 冒烟用;不设这个变量时,失败仍是完全不监听。
4. 端口被占用:记录错误并保持关闭,不改绑随机端口(手机上的书签会悄悄失效)。

Tailscale 网卡上的 HTTP 被 WireGuard 包了一层,第一期不做应用层 TLS。cookie 因此**不能**带 `Secure`(否则浏览器在 `http://100.x` 上拒收)。`SameSite=Strict`、`HttpOnly`、`Path=/` 都要。

这带来一个边界:iOS Safari 可以打开 `http://100.x:47321` 看页面和视频。需要安全上下文的 API(剪贴板高级接口、将来若做 PWA)在纯 HTTP 上不可用,第一期用不到它们。

以后若在前面加 **Tailscale Serve**(尾网 HTTPS,反代到 `127.0.0.1:47321`):

- 浏览器的 `Origin` 是 `https://<机器>.ts.net`,应用看到的 `Host` 是回环。`Origin` 与 `Host` 字符串相等这条规则会误伤。
- 届时增加设置项 `remoteAccess.publicOrigin`(精确源站),只信任来自回环的反代,并且只在这个模式下把 cookie 标成 `Secure`。
- Funnel(公网)和 Cloudflare Tunnel 还要处理边缘超时(§2.4)和更严的锁定。第一期设置页用一句话写明「不要用 Funnel 把这个端口公布到公网」,避免口令成为唯一暴露面。

### 7.3 口令与 cookie

- 生成:32 字节 `randomBytes`,展示为 base64url。只在生成/轮换的那一次把明文交给桌面渲染层。
- 存储:scrypt 哈希 + salt,写入 `remote-access.json`(`0600`)。校验用 `timingSafeEqual`。
- 轮换:立刻使旧 cookie 失效(换哈希即可,cookie 里是随机 session id,见下)。
- cookie 的值是 session id,不是口令本身。内存中的 session 表(单用户,一张表就够)记录过期时间。默认 30 天滑动:每次成功的 `/rpc` 续期。进程重启后 session 清空,浏览器要重新输一次口令——可接受,也避免把 session 持久化到磁盘。
- 登出删 session。

### 7.4 CSRF 与来源

- cookie `SameSite=Strict`,跨站表单带不走。
- 状态变更(`POST /rpc`、`POST /session`、`POST /upload`)要求 `Origin` 缺省(非浏览器客户端)或 `Origin` 的 host+端口与请求 `Host` 一致。第一期没有反代,这条是对的。加上反代之后改查 `publicOrigin`(§7.2)。
- 不使用自定义 CORS 白名单。不反射 `Origin`。
- WebSocket 升级同样查 cookie 与 `Origin`。

### 7.5 限流

- `POST /session` 失败:同一来源 IP 15 分钟内 8 次则 429,锁定 15 分钟。成功清零。日志记失败次数,不记口令。
- `/rpc` 不做苛刻的 QPS 限制(画布保存和队列推送都是机主自己)。JSON 体 32MB 上限防误传大文件。
- `/media` 的 Range 不参与登录失败计数。视频拖动会在短时间打很多 206。
- 渲染队列本身已拒绝同一 `nodeId` 的重复在途任务,全局同时只跑一个。远程不另开并行度。

### 7.6 可选的 Tailscale 身份(建议第一期就做,成本低)

口令防的是「尾网上的其他设备」(家庭尾网、借来的手机)。再加一道:对非回环连接执行 `tailscale whois <对端 IP>`,只接受与本机同一 tailnet 用户的节点。whois 失败则拒绝,不降级成「谁都能连只要有口令」——口令仍要,whois 是附加条件。回环跳过 whois,否则本机浏览器验收会被挡住。

这一步用子进程即可,不必嵌 Tailscale SDK。

### 7.7 和红线的关系

| 红线 | 远程访问怎么守 |
|---|---|
| R1 秘密不进 git | 令牌只在本机 `remote-access.json`。`.env.example` 若增加开关,只写注释与空值。文档不贴真实口令 |
| R2 dry-run 默认 | 服务不读取、不改写 `BIGBOTART_DRYRUN`。`renderMode` 默认仍是 `demo` |
| R3 Provider 注册表 | 远程不 new Provider,只调用现有 `submitRender` |
| R4 渲染进程不碰 Node | 网页包只有 `fetch` / `WebSocket`。禁止在 renderer 里为了远程去 `import 'electron'` |
| R5 不删用户数据 | 测试用临时 `BIGBOTART_HOME`。远程不新增「清空数据目录」的接口 |
| R6 不吞错 | 远程分发器 `catch` 后走 `logger.ts`,再返回带上下文的短错误 |

## 8. 桌面窗口和浏览器同时开着

主进程一个,状态一份。两端都是客户端。

**画布。** `saveCanvasSnapshot` 已是同步函数,单线程里不会在函数中途被另一端插队。保护已经有三道,远程直接受益:

1. `version` 落后 → `{ ok:false, stale:true, current }`,并 `onCanvasSaved` 把当前快照广播出去。
2. 空节点覆盖有内容的画布 → 拒绝(除非 `allowEmpty`)。
3. 0 节点却还有边 → 拒绝,连 `allowEmpty` 也不行。
4. 画布 id 已不在容器里 → 拒绝(防止删完又被 flush 复活)。

两端的 React 必须处理 `stale`(桌面已经按这个约定写)。前提是广播到达**两端**,所以 §2.1 的 hub 是硬前置。不做字段级合并:后写的一端若基于旧 version,保存失败,用 `current` 刷新,未保存的局部编辑会丢掉。单人不同时改同一画布时这不是问题;同时改是已知限制,设置页或画布角标可以显示「还有一个客户端连着」(hub 的订阅计数),第一期可以只打日志,UI 提示放到第二期。

相等 version 的丢失更新窗口:A、B 都持有 version N,A 先写成功变成 N+1,B 再写被拒。这是正确行为。不需要再加一把互斥锁。

**队列。** 一个 `running`。两端看到的 `onQueueChanged` 应是同一份 `slimList`。手机提交、Mac 窗口上的节点徽章要一起变,反之亦然。挂载时的 `queueStatus()` 兜底保留(今天桌面还有 8 秒轮询的历史原因,hub 修好后轮询仍可留着当断线兜底)。

**Agent。** `inFlightChats` 的键是 `projectId:canvasId`。一端正在对话,另一端再发会进入现有的抢占/等待逻辑,不要为远程另写一把锁。事件必须扇出,否则手机上发起的对话,Mac 上的面板一直停在旧内容,直到手动刷新。`threadId` 过滤逻辑渲染层已有,两端各看各的当前会话即可。

**自动续跑。** 任务完成后主进程会再推 `agent-event`。扇出之后两端都会看到「自动推进」卡。不要在网页客户端里再实现一份自动续跑。

**设置与主题。** 浏览器改 `theme` / `language` / `renderMode` 会写同一份 `settings.json`,桌面窗口下次 `getSettings` 或现有订阅能看到。`renderMode: 'real'` 仍要本机 `BIGBOTART_DRYRUN=0` 才会真的 spawn。远程只是多了一个能拨动这个开关的 UI,不降低 R2。

**视频增强。** 全局串行。一端已在跑,另一端 `videoPostRunning()` 能看到,避免重复发起(这正是该 API 的用途)。进度频道纳入 hub 后两端进度条一致。

## 11. 触屏优化(第二期)

画布是自研的:节点是 DOM(`.node`),连线是 SVG(`.edges`, `pointer-events: none`),视口是 `.world` 上的 `translate(var(--vx), var(--vy)) scale(var(--vz))`。平移和缩放期间直接写这三个 CSS 变量,不 `setState`(P3,见 `CanvasPage` 的 `applyViewLive`)。节点拖动仍是每帧 `setNodes`。本节只改交互和布局,不改节点数据模型。

分档(用指针类型 + 宽度,不用 UA 字符串):

| 档 | 判定 | 做到什么程度 |
|---|---|---|
| 桌面鼠标 / 触控板 | `pointerType` 为 `mouse` 或 `pen`,或细指针 | 保持今天的语义,包括 2026-10 起「左键拖空白不再平移」 |
| 平板 | `pointerType === 'touch'`,且视口宽度 ≥ 900px | 画布完整可用:平移、捏合、框选、连线、分组、撤销 |
| 手机竖屏 | 触控且宽度 < 900px | 优先提交任务、看进度和成片、Agent 对话。画布只保留基本编辑:点选、拖动节点、删除、平移和捏合 |

外接键盘的 iPad 同时会发出鼠标事件和触控事件。判定按**这一次** `pointerType`,不要用一次探测把整页锁成「触控模式」,否则触控板捏合(`wheelIntent` 的 ctrl+wheel)会被换掉。

### 11.1 现在只有鼠标能完成的操作

节点拖动、连线、「+」按下、框选、小地图、检查器遮罩已经是 Pointer Events。缺的是触控没有对应的平移/缩放通道,以及右键、悬停、键盘和过小的热区。

**滚轮 / 触控板(触控点上不会发生)**

| 动作 | 现在怎么判 | 位置 |
|---|---|---|
| 触控板双指滑动 → 平移 | `wheelIntent`:像素级 `deltaMode === 0` 且没有 Ctrl/⌘ → `pan` | `pages/canvas/wheel-intent.ts`;执行在 `CanvasPage` 的 `onWheelPan` |
| 触控板捏合 → 缩放 | Chromium 把捏合合成 `ctrl+wheel`,`wheelIntent` 返回 `zoom` | 同上。注释写明这是浏览器暴露捏合的唯一标准方式,所以**没有**自己的多指状态机 |
| 鼠标滚轮 → 缩放 | `deltaMode !== 0`(行/页)→ `zoom` | 同上 |
| 缩放锚点 | 最近一次 `pointermove` 的坐标;没有则舞台中心 | `CanvasPage` 里 `lastPointerRef`,`stage` 上非 passive 的 `wheel` 监听(`preventDefault`) |
| 缩放范围 | `z` 夹在 0.4–1.3,因子 `zoomFactorFor` | `onWheelPan` |

`StageView` 的 `.world` 上也挂了 `onWheel`,舞台上另有一道捕获。弹层(`.add-pop, .pop, .ctx`)内的滚轮被放过,留给列表自己滚。

**按下 / 移动(已是 pointer,但按鼠标键位分支)**

| 动作 | 行为 | 位置 |
|---|---|---|
| 空白左键,框选关 | **什么都不做**。2026-10 起取消「拖空白平移」,避免和框选打架 | `onStagePointerDown`(`CanvasPage` 约 1049 行);光标注释在 `design-pages.css` 的 `.stage` |
| 空白左键,框选开 | 拖出矩形,命中组内任一节点则整组选中;Shift 为追加 | `beginMarquee` / `applyMarquee`;开关在 `Toolbar` 的 `canvas-marquee-toggle`,`marqueeMode` 默认 `false` |
| 中键拖空白,或空格按住再拖 | 平移。`beginPan` 记起点,移动时只写 CSS 变量 | `onStagePointerDown` 的 `e.button === 1 \|\| spacePan` |
| 标题栏或节点主体按下 | `beginNodeDrag`。`e.button !== 0` 直接返回。已选中则拖整块选区;组内节点扩张为整组;移动超过 3px 才算拖动;位移除以当前 `z` | `CanvasPage` `beginNodeDrag` 与其后的 `pointermove` |
| 「+」 | `pointerdown` 进入连线预备;移动超过 4px 才画预览线,松手命中则建边;没超过则 `click` 打开添加弹层 | `handleNodeAddPointerDown` / `handleNodeAddClick`;全局 `pointermove` 在 connectDrag effect |
| 小地图 | `pointerdown` + `setPointerCapture`,拖动把视口中心对准 | `StageView` `.minimap` |
| 双击空白 | 视口回到 `DEFAULT_VIEW` | `StageView` `onDoubleClick` → `CanvasPage` |
| 双击调色板一项 | 在画布中心加节点。拖到画布上是 HTML5 drag(`application/x-bigbotart-palette`) | `Palette.tsx` |
| 点组名 / 组徽标 | 选中整组。点单个节点只选它自己,不扩张 | `selectGroup` / `selectNode` |

空白处的命中判定是:事件目标是 `.stage` 自己、`.world` 或 `svg`。节点、组框、弹层各自 `stopPropagation`。右键菜单的挂载点必须在 `.stage` 上,因为 `.world` 只有固定 1600×1000,用户看到的空白大多在 stage 上(2026-10-10 右键失效事故,见 `StageView` 注释)。

**悬停才出现或才好看懂的东西**

| UI | 现状 | 位置 |
|---|---|---|
| 节点视频上的播放钮 | `.nthumb .play` 默认 `opacity: 0`,`.nthumb:hover` 才显示 | `design-pages.css` |
| 首页项目卡上的操作 | `hoverId` + `onMouseEnter` / `onMouseLeave`,离开即收起 | `HomePage.tsx` |
| 「+」连线钮 | **一直显示**,但只有 26×26,且 `right: -13px` 挂在卡片外;悬停只是变色放大 | `.node-add` |
| 入点圆点 `.port` | 10×10,纯装饰,没有点击处理 | `NodeCard.tsx` |
| 顶栏图标钮 `.ibtn` | 30×30;缩放条里的 +/- 还用内联改成 26×26 | `Toolbar.tsx`、`StageView` `.zoomctl` |

悬停变色(按钮、列表行)可以留着,触控点一下仍然有 `:active`。要改的是「不悬停就没有这个控件」和「热区小于手指」。

**右键**

| 节点 `contextmenu` | 菜单:复制、重命名、另存为、在 Finder 中显示、添加到聊天、删除。`NodeCard` 上 `stopPropagation` | `ContextMenu.tsx` |

### 11.2 手势:和鼠标共用 Pointer Events

不新写一套 touch 监听。`pointerdown` / `pointermove` / `pointerup` / `pointercancel` 继续是唯一的按下通道。鼠标、笔、触控都进同一套 `beginPan` / `beginMarquee` / `beginNodeDrag`。触控和鼠标的差别收成纯函数,风格对齐 `wheel-intent.ts`(判定和执行分开,执行侧直写 DOM,单测只测判定)。

新文件 `pages/canvas/gesture-intent.ts`,输入是指针类型、当前触点数、按下时长、位移、命中(空白 / 节点标题 / 「+」/ 已有控件)。输出是这一帧该交给哪个现有入口:

| 条件 | 结果 | 交给 |
|---|---|---|
| `pointerType !== 'touch'` | `desktop` | 现有分支原样:滚轮走 `wheelIntent`,左键空白看 `marqueeMode`,中键和空格平移 |
| 触控,空白,单指,移动 | `pan` | `beginPan`。这是触控板上「双指滑动」在手指上的对应物。鼠标左键拖空白仍然不做平移 |
| 触控,两指 | `pinch` | 以两指中点为锚点缩放(复用 `onWheelPan` 里那套 `mx - (mx - v.x) * k`),两指中点的平移同时改 `--vx/--vy`。松成一指后不再把剩余那一指变成框选 |
| 触控,空白,按下超过约 500ms 且位移仍 &lt; 8px,然后拖动 | `marquee` | `beginMarquee`。不要求用户先去顶栏打开「框选」 |
| 触控,空白,长按后没有拖动就抬起 | `clear-selection` | 与空白右键相同:清空选区 |
| 触控,节点上长按(未进入拖动) | `context-menu` | 打开现有 `ContextMenu`,坐标用触点。随后的兼容 `click` 要吞掉,避免菜单刚开又被点选关掉 |
| 触控,节点上移动超过 3px(与现拖动阈值一致) | `drag-node` | `beginNodeDrag`。长按计时取消 |
| 触控,「+」上移动超过 4px | `connect` | 现有 connectDrag。不足 4px 的抬起仍算打开添加弹层 |

`wheel` 监听保留。触控板捏合继续走 `ctrl+wheel`,不要在触控路径里再解释一遍 wheel。iOS Safari 的捏合**不会**可靠地变成 `ctrl+wheel`,它会去缩放整个页面,所以捏合必须从 Pointer Events 的双指来,并在舞台上挡住浏览器自己的缩放(§11.5)。

`pointercancel`(系统手势把触摸抢走、来电、浏览器边缘返回)与 `pointerup` 同一条收尾:视口 `commitView`,节点拖动结束并清空 `dragging` 类。丢弃这次手势会把节点留在半路且 `will-change` 不卸。

长按期间手指已经在拖节点时,不再升级成菜单。菜单项里的「在 Finder 中显示」「另存为」在网页仍按 §2.5 隐藏。

调色板的 HTML5 drag 在触控上不会发生。平板给每一项加单击添加(双击保留给鼠标)。手机竖屏默认收起调色板,用一个「添加」按钮打开同一列表。

### 11.3 热区约 44px,并且按屏幕像素算

`.world` 带 `scale(var(--vz))`,`z` 最小 0.4。写在节点里的 44px,缩到最小时屏幕上只剩大约 18px。热区要抵消缩放:控件放在 `.world` 里面时加 `transform: scale(calc(1 / var(--vz)))`,让屏幕尺寸稳定在约 44px。缩放条、顶栏、底栏不在 `.world` 里,直接用 44px 即可。

| 控件 | 现在 | 触控档 |
|---|---|---|
| `.node-add` | 26px,每张卡常驻 | 选中的节点才加强显示(未选中保持小而淡,避免一屏几十个加号);选中后热区 44px |
| `.zoomctl` 的 +/- 和百分比 | 26px,点百分比复位 | 44px。复位是双击空白的替代,双击在手机上会触发页面缩放 |
| `.ibtn`(撤销、重做) | 30px | 44px |
| 删除 | 无按钮 | 有选区时顶栏出现 44px 删除,调用现有 `deleteNodes` |
| `.agent-icon-btn`、`.insp-close`、发送钮 | 28 / 26 | 44px |
| `.agent-grip` / `.insp-grip` | 宽 12px | 手机改底栏后不再靠这条缝拖宽度;平板把可点宽度扩到 44px,视觉条可以仍是 2px |
| `.port` | 10px 装饰 | 不加大。连线只走「+」 |

选中节点时播放钮常显(`.nthumb .play`),不要等 `:hover`。首页项目卡的操作改成卡上常驻的「…」,`onMouseEnter` 那套可以留作鼠标的提前展开。

### 11.4 手机竖屏的布局

今天的画布页是一层绝对定位叠在舞台上:

- 顶栏 `.topbar`:悬浮,高 46px,一行里塞了返回、画布切换、撤销、重做、框选、分组、重跑、运行全部、调试
- 调色板 `.palette`:左,宽 200px,可折叠
- Agent `.agent`:右,宽 344px 起(`setAgentWidth` 的下限就是 344),上 66px、下 12px
- 检查器 `.insp-panel`:左,宽 `--insp-w`(约 300px),选中节点才从 `opacity: 0` 变成可见,会把调色板往右推
- 队列条 `.queue`:高 44px
- `App.tsx` 顶部 `.titlebar-drag` 高 34px(`-webkit-app-region: drag`),各页高度是 `calc(100vh - 34px)`

手机竖屏(宽度 < 900px)改成:

- 不渲染 `.titlebar-drag`(网页没有红绿灯)。高度不再扣 34px。
- 顶栏只留:返回、画布名、撤销、重做、有选区时的删除。框选、分组、调试收进溢出菜单。平板仍显示框选和分组。
- Agent 与检查器改成底部抽屉,不同时占满两块。收起时是一条约 56px 的条(Agent 输入框 + 发送,或检查器的运行按钮 + 标题)。上拉展开到约 45vh,再点一次铺满(全屏切换),铺满时舞台只留顶栏。检查器在有选中节点时盖住 Agent 条,关闭检查器回到 Agent。
- 队列进度放在顶栏下方的细条上,点开展开现有 `queue-panel`。手机的首要任务是看见「在跑」,而不是把队列埋在底栏下面。
- 小地图在手机隐藏(140×90,和底栏抢位置)。平移靠手势,跳转靠点选节点后现有的 `revealNode`。
- 检查器里的运行按钮(`.action-bar .btn-p`)在抽屉收起态也要能点到,这是「提交任务」的入口。

平板(≥ 900px)保持左右栏,允许把 Agent 收成一条竖边。不要在平板上强制底栏。

### 11.5 浏览器滚动、缩放和 iOS

舞台 `.stage` 设 `touch-action: none`,这样单指拖动不会带动页面滚动,浏览器也不会在舞台上解释捏合。Agent 消息列表、检查器正文、添加弹层保持 `touch-action: pan-y`(弹层已有 `overscroll-behavior: contain`)。不要给 `html` 全局 `touch-action: none`,否则聊天列表无法滚动。

`apps/desktop/src/renderer/index.html` 现在是 `width=device-width, initial-scale=1`,没有 `viewport-fit=cover`。补上 `viewport-fit=cover`。不要加 `user-scalable=no`:页面级禁止缩放会伤到无障碍,而且 iOS 有时会忽略。舞台上的捏合用 `touch-action` 加上 Safari 的 `gesturestart` `preventDefault`(只绑在 `.stage`)挡住。按钮用 `touch-action: manipulation`,去掉双击放大带来的点击延迟。

舞台另加 `user-select: none` 和 `-webkit-touch-callout: none`,避免长按节点弹出系统选单,和我们的长按菜单抢手势。输入框、contentEditable 表格不要继承这条。

`100vh` 在 iOS Safari 上包含地址栏高度,底栏会被挡。页面壳改用 `100dvh`(不支持时回退 `100vh`)。顶栏、底栏抽屉、toast(现在 `bottom: 58px`)加上 `env(safe-area-inset-top)` / `env(safe-area-inset-bottom)`。

### 11.6 节点一多时的性能

已经有的、触控必须接着用的:

- 平移/缩放不走 React,只写 `--vx/--vy/--vz`。捏合沿这条路,不要每帧 `setView`。
- `.world` 有 `will-change: transform`。节点只在拖动时挂 `.dragging`(`will-change` 常驻会让每张卡占一层,CSS 注释写了原因)。
- `NodeCard` 有 `memo`。视口变化不该重渲染卡片。
- 视口动画期间 `.pg-canvas.animating` 把毛玻璃降到 `blur(10px)`。捏合和单指平移要继续打上这个 class(`markViewportAnimating` 已经在连线和滚轮路径上)。
- `perf.ts` 已有阶段 `pan` / `zoom` / `drag-node` / `marquee` / `connect`。触控把同一套阶段打进去,用调试面板看 p95,而不是凭手感。

触控上会更疼、第二期要处理的:

- **节点拖动仍每帧 `setNodes`**,被拖的那张卡会重渲染,连线路径若随坐标重算也会跟着走。平板拖动时改成拖动期间只写该节点 DOM 的 `left/top`(或 transform),`pointerup` 再一次 `setNodes` 并记入撤销。鼠标拖动可以同一条路径,这样桌面也少一次 reconcile;若想缩小 diff,就只在 `pointerType === 'touch'` 走 DOM 直写。
- **没有视口裁剪**。`perf.ts` 头注释把「连线 imperative + 视口裁剪」标成还没做的 P4。手机上舞台外的节点仍然是完整 DOM(含视频和毛玻璃)。第二期的底线:舞台外的 `<video>` 不要处于播放,卡片保持 `memo`。裁剪整卡可以作为后续,不挡 M5。
- 手机默认收起调色板和检查器,减少舞台两侧的 `backdrop-filter` 面积。毛玻璃在低端手机上比节点数量更贵。

### 11.7 测试与风险

**vitest(纯函数,不启浏览器)**

`gesture-intent.ts` 与现有 `wheel-intent` 测试并列:

- 鼠标空白拖动 → `desktop`(调用方因此不会改去平移)
- 触控单指空白移动 10px → `pan`;不足阈值且未到长按 → 还不是框选
- 触控空白按下 500ms 内移动 20px → `pan`,长按被取消
- 触控空白按下 ≥ 500ms 且位移 &lt; 8px,再移动 → `marquee`
- 触控两指 → `pinch`;给出两指距离比时缩放因子方向正确(拉开放大)
- 节点上触控移动超过 3px → `drag-node`,不返回 `context-menu`
- 节点上长按且未过拖动阈值 → `context-menu`
- `wheelIntent` 的三条旧分支一个都不能变(已有测试继续绿)

热区抵消缩放可以抽一个 `screenSize(cssPx, z)` 纯函数: `z = 0.4` 时期望屏幕边长仍约 44。

**手工矩阵(不进 CI)**

| 设备 | 要看的 |
|---|---|
| 桌面 Chrome + 鼠标 + 触控板 | 回归:滚轮缩放、双指平移、Ctrl 捏合、空格/中键平移、框选开关、右键菜单、⌘Z。左键拖空白仍然不平移 |
| iPad Safari 横屏 | 单指平移、捏合锚点跟手指、长按框选、长按出菜单、「+」能拖出连线、撤销按钮点得中 |
| iPhone Safari 竖屏 | 底栏 Agent 能打字发送;选节点后运行按钮可见;视频可播可拖进度;地址栏收起时底栏不被 Home 指示条挡住;捏合不会把整页放大 |
| Android Chrome(一台即可) | 单指平移不被下拉刷新带走;长按不弹出系统选单 |

代理验收仍用 dry-run 起 App,不要为了摸手机去跑 `pnpm dev`。

**风险**

1. **手势判错就毁了桌面手感。** 2026-10 刚把「拖空白平移」拿掉。若 `pointerType` 在某台设备上永远是 `mouse`(部分 WebView),触控会退回「拖空白没反应」,而不是悄悄把鼠标行为改掉。失败要表现成「这块屏幕还不能平移」,并保留缩放条上的 +/-。
2. **长按与系统菜单、与拖动阈值抢。** 3px 的拖动阈值在手指上容易被抖动触发,长按菜单会很难出现。触控的「算不算拖动」用 8px,鼠标仍用 3px。两套数字都进 `gesture-intent` 的参数,单测钉住。
3. **热区做在世界坐标里。** 只把 CSS 改成 44px 而不除以 `z`,缩小后仍然点不中「+」。
4. **`pointercancel` 不清 `dragging`。** `will-change` 留在全部节点上,手机会更卡。收尾必须走和 `pointerup` 同一函数。
5. **底栏把舞台盖死。** 手机若默认展开 Agent 全屏,就看不见进度。默认是收起的一条,进度条在顶上。
6. **`100vh` 和 34px 拖拽条。** 漏改一处,iPhone 上底栏永远差一截。验收时看 Safari 地址栏收起和展开两种高度。

## 13. 风险与未决问题

**风险(实现时按这个顺序防)**

1. **事件只推主窗口。** 不先做 hub,网页上的 Agent 与画布会「能提交、看不见结果」,用户会以为生成失败。这是第一期最大的功能风险。
2. **符号链接与开发版多产物根。** 白名单抄窄了,预览黑屏;抄宽了或漏了 `realpath`,远程读到数据目录以外的文件。必须和 `outputSearchRoots` 用同一组根,再加 `realpath`。
3. **远程请求弹出本机对话框。** 分发器漏截一个 `dialog` 方法,手机点一下,Mac 弹出选择框,还可能在无人时卡住 Promise。用桩计数测试兜住清单里的每一个。
4. **M1 搬家引入行为差。** 缓解:单独提交、不改逻辑、全量测试。特别注意 `saveCanvas` 与 `saveCanvasSnapshot` 两条保存路径都还在,版本闸只在后者完整;搬家时不要「顺便」删掉旧方法。
5. **长 HTTP 在将来的隧道上被切断。** 第一期 Tailscale 直连可以接受。写进设置文案,避免有人用 Funnel 当成已支持。
6. **口令进了 `settings.json` 或日志。** 评审时搜 `remote-access` 与 `credentialSet` 的日志参数。
7. **手机休眠。** 页面被系统冻结后 WebSocket 死掉。重连 + 挂载时的 `queueStatus` / 会话拉取能恢复;进行中的工具卡可能要重进会话才完整。生成在 Mac 上继续,不依赖手机页面活着。
8. **双端同时编辑丢稿。** 接受,并在方案里写明。不要在第一期加 CRDT。
9. **`ws` 依赖。** 落地前按仓库约定确认再装。不想加依赖时,M2 改用 SSE,客户端接口形状不变。
10. **触屏改到手感。** 细节和缓解在 §11.7。第一期不要顺手改 `onStagePointerDown`。

**未决(不阻塞第一期动工,默认按括号里的选择)**

1. 尾网 HTTPS 用 Tailscale Serve,还是第一期一直用 `http://100.x`(默认后者)。
2. whois 允许列表是「同一 tailnet 用户的全部设备」还是「仅本机登录的那几个节点名」(默认同一用户;机主的手机本来就是另一台设备)。
3. 端口 47321 是否要做成设置项(默认要,避免和本机其他服务冲突;冲突时不自动换端口)。
4. 浏览器是否允许把 `renderMode` 拨到 `real`(默认允许,因为是机主的明确动作;dry-run 环境变量仍只有本机启动命令能关)。若希望真实推理只能在 Mac 前确认,则 HTTP `setSettings` 同时丢弃 `renderMode`。实现前若没有新的意见,按「允许」做,并在设置文案里写清后果(内存与耗时,见 AGENTS §0.5)。
5. 调试日志频道对网页是否默认推送(默认推,与桌面一致;单用户流量可接受)。若日志里出现过路径以外的敏感片段,再在 hub 上对 `debug-log` 做网页侧过滤。

## 15. 第一期实现时的修正

实现在 `cursor/web-remote-phase1-b3d3`,与本方案分开。下面这些是对照代码之后改过的地方,以实现为准。

1. **契约多两个方法。** `remoteAccessStatus` 与 `remoteAccessRotatePassphrase`。口令哈希不能进 `getSettings()` 的返回值,所以不能只靠 `AppSettings.remoteAccess`(那里只有 `enabled` 和 `port`)。目录是 **124**:118 个 RPC + 原来的 6 个事件。轮换口令只在桌面 IPC 上可用,远程 `/rpc` 直接拒绝。
2. **无路径才拒绝对话框。** `importAssets` / `exportProjectPackage` / `importProjectPackage` 已经带了明确路径时,仍进入原来的 handler(白名单在 handler 里)。没有路径、以及封面、Skill 导入、另存为、Finder,远程一律 403,不调用 `dialog`。
3. **写死的 `bba-asset://` 不只有 `media.tsx`。** 资源卡、首页封面、Agent 附件、资产选择弹层也要走 `assetUrlOf`,否则网页缩略图是空的。桌面在 `bigbotartShell === true` 时仍用原来的自定义协议。
4. **`BIGBOTART_REMOTE_STATIC`。** vitest 里的主进程 `__dirname` 不是 `out/main`,冒烟用这个变量指向已构建的 `out/renderer`。正式运行不设,静态页在主进程旁边的 `renderer` 目录。
5. **whois 每次请求都查,没有缓存。** 失败拒绝,不降级。回环跳过。单测通过注入查询函数,不调用本机的 `tailscale`。
