## A.1 `mlxgen generate`(文生图)✅ 基本兼容

Provider 构造:`generate --model M --prompt P --width W --height H --steps S --guidance G [--seed <s>] --output X.png`

| 检查点 | 官方行为 | Provider | 结论 |
|---|---|---|---|
| `--model` / `--prompt` / `--width` / `--height` / `--steps` / `--guidance` / `--output` | 均存在(路由层透传到后端) | 一致 | ✅ |
| 多 seed `--seed 101 202 303` | 官方支持多值(nargs) | Provider 用 `join(' ')` 拼成**单个 argv 参数** `"101 202 303"`,后端 `--seed type=int`,实测报 `invalid int value: '42 43'` | ❌ 实测确认坏 |

## A.2 `mlxgen upscale`(超分)❌ 必挂,两处硬伤

Provider 构造:`upscale --model M --prompt P --image-path <in> --resolution <2|4> --output X.png`

1. **残留 `--prompt`**:`mlxgen upscale` 是无提示词恢复路由,整个 parser 没有 `--prompt`(README 官方示例从未带过)→ 后端 argparse 报 `unrecognized arguments: --prompt …`,**实测确认先于任何模型加载即失败**(见 A.0 #1)。
2. **`--resolution` 语义错位**:官方 `--resolution` 接受整数 = **目标短边像素**,或 `2x/3x` = 缩放倍率(api.md + 源码 `int_or_special_value` + `--help` 均确认)。检查器默认 `scale: 2/4`(数字),Provider `String(scale)` → 传 `"2"/"4"` → CLI 理解为 **2px/4px 短边**,不会报错但产物荒谬。必须传 `"2x"`。
3. ✅ `--model` / `--image-path` / `--output` 名字本身正确;去掉 `--prompt`、改传 `2x` 后命令可跑到模型下载提示(A.0 #6)。

## A.3 `mlxgen generate` 编辑四模式(统一路由)⚠️ 两可用、两错位

关键事实(源码 + 实测确认):统一 `mlxgen generate` **路由层有 `--image-path` 官方别名**(`router_options.py`:"Compatibility alias for a single input image",与证明命令日志里的 `--image` 等效);`--mask-path` 不在路由表,作未知参数**原样透传**给后端且后端接受。两者均已实测解析通过(见 A.0 #4/#5)。据此:

| 检查器模式 | Provider 实际传给 CLI | 路由结果 | 结论 |
|---|---|---|---|
| `instruction` 指令编辑 | `generate --image-path X --prompt P` | 模型带 `--image` 时自动 `edit-reference`,走 qwen/flux2 edit 后端 | ✅ **实测**解析通过、路由成功(A.0 #4) |
| `inpaint` | 上述 + `--mask-path` | 自动 masked-edit 路由(qwen.inpaint / z-image.inpaint / flux2.inpaint) | ✅ **实测**解析通过、路由成功(A.0 #5) |
| `img2img` | 与 instruction **完全相同**(无 `--i2i-mode` / 无 `--image-strength`) | 路由为 `edit-reference`,**不是 latent img2img** | ❌ 语义错位(静默) |
| `outpaint` | 只传 `--image-path` + prompt | 无 `--outpaint-padding` → `has_outpaint=False` → 路由为普通 edit-reference,**不会扩图**;`outpaintSides` 参数定义了但 Provider 从不消费 | ❌ 语义错位(静默) |

补注:
- 官方 latent img2img 需要 `--i2i-mode latent` 或 `--image-strength`;官方 outpaint 需要 `--outpaint-padding <top,right,bottom,left>`;
- 编辑默认模型 `qwen-image-edit`(短别名)**实测可解析**为 `Qwen/Qwen-Image-Edit`(A.0 #4);官方证明行多用 `AbstractFramework/qwen-image-edit-*-8bit` 全名,两者皆合法;
- 真实执行时 Provider 丢弃 stderr/stdout、未用 `--json-events`,进度只能看到 RUNNING → 结束,无百分比(**粗糙但非错误**)。
