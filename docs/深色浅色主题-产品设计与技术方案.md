## 第一部分:给设计 Agent 的需求

## 1. 产品目标

1. 设置页「外观」提供 **跟随系统 / 浅色 / 深色** 三档,选择即时生效、持久化、重启保持;
2. 「跟随系统」时随 macOS 外观实时切换(无需重启),说明文案显示**真实的**当前外观;
3. 深色模式覆盖全部页面与弹层,**不出现白块、不出现看不清的文字**;
4. 启动不闪屏(窗口底色与最终主题一致)。

**非目标**:自定义强调色、多套主题皮肤、按项目/画布单独设主题、定时切换。

## 2. 设计语言约束(延续现有体系)

- 设计语言仍是 **Apple HIG + Liquid Glass**(见 `colors_and_type.css` 头注释与 `DESIGN.md §2`):
  **玻璃只属于导航/控件层,内容层保持实色**——深色下同样遵守。
- **只改颜色类 token 的取值,不新增布局/字号/间距差异**。深浅两套界面结构必须完全一致,方便实现层只换变量。
- 单一强调色原则不变;深色下强调色可提亮(参考 Apple 深色 systemBlue)。
- 对比度目标:正文 ≥ 4.5:1,次级文字/元信息 ≥ 3:1,禁用态不作要求。

### 3.4 需要设计特别关注的点

1. **玻璃在深色下的质感**:浅色靠「白半透明 + 顶部高光」,深色要换成「深灰半透明 + 极弱白描边」,否则看起来像脏灰块。
2. **层级表达**:浅色靠阴影分层,深色阴影几乎不可见,通常改为「越上层越亮」(表面色逐级提亮)+ 细描边。
3. **用户产物优先**:画布上大量是生成的图片/视频,深色底不能偏色(建议中性灰,不带蓝调),以免影响用户判断出图色彩。
4. **品牌图标**:首页/引导页的品牌图是透明底 PNG(`design-pages.css:145` 注释),请确认深色底上是否需要反色版。
5. **状态色在深底上的可读性**:成功/警告/危险的文字与小圆点,深色下需提亮。
6. **设置页「外观」行**:说明文案改为「跟随系统(当前:深色/浅色)」动态显示,chip 交互不变。

### 3.5 交付格式

- 一份 token 表(可直接写成 CSS:`:root{…}` 浅色 + 深色块),**只含颜色类变量**;
- P0 区域的深色高保真稿(浅色稿已有,保持结构一致);
- 新增语义 token 的命名如与 3.2 暂名不同,请注明映射。

## 第二部分:技术方案

## 4. 总体设计:一个开关源,两条生效路径

```
设置页 chip ──setSettings({theme})──▶ 主进程 settings.patch
                                         │
                                         ├─ nativeTheme.themeSource = theme   (系统层:菜单/对话框/原生控件)
                                         │        │
                                         │        └─▶ 渲染层 CSS `prefers-color-scheme` 自动跟着变
                                         │              └─▶ token 深色块生效,全部 var(--…) 翻转
                                         └─ 持久化 settings.json
```

**关键选择:以 Electron `nativeTheme.themeSource` 为唯一开关源,CSS 用 `@media (prefers-color-scheme: dark)` 承接。**

理由:
- `themeSource` 设为 `'dark' | 'light' | 'system'` 后,渲染进程的 `prefers-color-scheme` 媒体查询**立即**跟随,
  「跟随系统」时 macOS 切外观也自动生效——不用自己监听系统事件、不用写 IPC 推送。
- 系统菜单、文件对话框、右键原生菜单、滚动条一并跟随,这些是纯 CSS 方案做不到的。
- 主进程在**创建窗口前**就能设好 `themeSource`,并用 `nativeTheme.shouldUseDarkColors` 决定窗口底色 ⇒ 天然无闪屏,
  不需要渲染层异步读设置后再补一刀。

备选(不采用):渲染层读设置后给 `<html data-theme>` 打标。缺点是首帧前设置还没读到会闪一下,且原生 UI 不跟随。
但实现时仍给 `<html>` 同步一个 `data-theme` 属性(由 `matchMedia` 驱动),**仅供调试和 E2E 截图定位**,样式不依赖它。

## 5. 改动清单

### 5.1 契约与存储(`packages/shared`)

- `AppSettings` 新增 `theme?: 'system' | 'light' | 'dark'`,缺省按 `'system'`(老 settings.json 无此字段照常工作,无需迁移)。
- 不新增 IPC 方法:沿用既有 `getSettings` / `setSettings`(`ipcMain.handle('set-settings')`)。
  ⇒ 不触发 AGENTS.md §2.1 的契约三处联动。

### 5.2 主进程(`apps/desktop/src/main`)

1. 启动时(`createWindow` 之前)读 `settings.theme` → `nativeTheme.themeSource = theme ?? 'system'`。
2. `BrowserWindow` 的 `backgroundColor` 由写死 `'#14161a'` 改为按 `nativeTheme.shouldUseDarkColors` 取深/浅底色
   (与 `--bg` 的两套值一致)。
3. `set-settings` 的 patch 含 `theme` 时同步更新 `themeSource`,并 `win.setBackgroundColor(...)`(防窗口缩放时露底色)。
4. `theme` 值校验:非三者之一 → 回落 `'system'` 并经 `logger` 记 warn(R6:不静默吞)。
   建议抽一个纯函数 `normalizeTheme()` 放进独立模块(如 `main/theme.ts`),便于单测,不继续堆 `index.ts`。

### 5.3 Token 层(`apps/desktop/src/renderer`)

1. **先收敛重复定义**:删除 `design-pages.css` 第 4–80 行与 `colors_and_type.css` 重复的 `:root` 块,
   以 `public/design/colors_and_type.css` 为唯一 token 来源(对比两边分叉的值,以当前实际生效的
   `design-pages.css` 版本为准合并回去,避免收敛时视觉回归)。
2. 在 `colors_and_type.css` 追加:
   ```css
   :root { color-scheme: light dark; }
   @media (prefers-color-scheme: dark) {
     :root { /* 设计 Agent 定稿的深色颜色 token */ }
   }
   ```
   `@supports not (backdrop-filter…)` 降级块同样补深色版本。
3. 补 §3.2 的新语义 token(浅色值 = 现硬编码值,保证浅色零视觉变化)。
4. `styles/design.ts`:`colors` 里的十六进制改为 `'var(--bg)'` 这类字符串,`glassStyles` 改用 `var(--glass-*)`;
   这样 `ProjectsPage` 的内联样式无需逐个改动即可跟随。(注意 `color-mix(in oklab, ${colors.fg} 8%, transparent)`
   代入 `var(--fg)` 后仍是合法 CSS。)

### 5.4 设置页(`SettingsPage.tsx`)

- `appearance` 由组件内 `useState` 改为读写 `AppSettings.theme`(同 `language` 的接线方式:App 启动回填 + 切换即 `setSettings`)。
- 内部值改用 `'system' | 'light' | 'dark'`,不要再用中文字面量当状态值(现在的 `'系统' | '浅色' | '深色'`)。
- 新增 hook `useColorScheme()`(`matchMedia('(prefers-color-scheme: dark)')` + `change` 监听,返回清理函数),
  说明文案改为 `t('跟随系统(当前:{mode})', { mode: t(isDark ? '深色' : '浅色') })`,同步 `i18n/en/settings.ts`。
- 同一个 hook 负责给 `<html>` 写 `data-theme`(仅调试/E2E 用)。

## 9. 风险与注意

1. **token 收敛的回归风险**:两份 `:root` 已分叉,删错一份会让浅色观感变化。收敛前先 diff 两边,以当前实际生效值为准。
2. **`color-mix` 派生色在深色下的强度**:现有 `color-mix(var(--fg) 8%)` 之类的 hover/选中底,在深色下会变成「白 8%」,
   通常效果正确但可能偏弱/偏强,P2 走查时按需微调百分比。
3. **用户产物观感**:深色底会让同一张图看起来更亮,这是正常的视觉对比效应,不是 bug;但画布底色不宜纯黑。
4. **主进程改动需重启 App 生效**(CLAUDE.md 2026-10-12 事故教训):验证时先清残留实例再起。
5. 落地后同步 CLAUDE.md「关键约定」一节(主题开关源 = `nativeTheme.themeSource`,样式只依赖 `prefers-color-scheme`)。
