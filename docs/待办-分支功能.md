## 1. 为什么隐藏

工具栏上的「**分支：v2 实验**」按钮点开会弹出一个三项弹层,但**三项全是静态占位,没有任何行为**:

| 弹层项 | 现状 |
|---|---|
| `main · 主版本` | 纯文字,无 onClick |
| `v2 实验 · 当前` ✓ | 纯文字,勾选标记是**写死的**,不代表真实状态 |
| `＋ 从当前画布新建分支…` | 灰字占位,无 onClick |

这与项目里已处理过的两类「假入口」是同一性质:

- 旧的「连线」按钮 —— 从未接线的静态占位,已移除(Toolbar 顶部注释有记录);
- `director` / `workflow-input` / `workflow-output` 三类节点 —— 面板藏入口、定义保留(见 `packages/shared/src/connector-map.ts` 的 `HIDDEN_NODE_KINDS`)。

留着它的实际危害:用户点一次发现没反应会当成 bug 上报;更糟的是会**误以为画布已支持分支工作流**,从而按"应该有分支"去理解后续所有行为。

## 2. 处置方式(隐藏入口,非删定义)

与 `HIDDEN_NODE_KINDS` 同一手法:

- 按钮 **+** 弹层整段包进 `{BRANCH_FEATURE_ENABLED ? (...) : null}`。
  ⚠️ 必须整段包住,只藏按钮会留下一个永远打不开的 `.pop` 节点。
- `openPop` / `setOpenPop` props 与样式**全部保留** —— 接线已就位,实现分支时不必重新接线。
- 顶部 flag 注释里写明了"恢复的前置条件是先实现分支",防止后来者直接把它改回 `true` 就交差。

## 3. 恢复入口的前置条件

**先把分支做成真的**,再把 `BRANCH_FEATURE_ENABLED` 改回 `true`。需要落地的最小闭环:

1. **数据模型**:`CanvasSnapshot` 上加分支概念(或引入 `branchId`),明确定义"分支"是
   画布级快照分叉、还是同画布内的节点子集。这一步没定,后面全是空中楼阁。
2. **主进程持久化**:`ProjectStore`(`apps/desktop/src/main/store.ts`)+
   `workspace-paths.ts` 落盘结构,注意**版本防护与写盘广播**的既有约定(落后版本拒绝覆盖)。
3. **建分支动作**:`＋ 从当前画布新建分支…` 的真实 handler(克隆当前画布快照 → 新分支 id)。
4. **切换分支**:弹层列表改为**读真实分支清单**渲染,勾选标记由当前分支派生(不能再写死),
   并接上 `onSwitchCanvas` 同款的重载流程。
5. **与既有功能的交叉**,逐条确认:
   - **stale / 仅重跑受影响**([cascade.ts](apps/desktop/src/renderer/src/pages/canvas/cascade.ts))—— 分支切换后 stale 标记的归属;
   - **撤销/重做**(`HistoryStack`)—— 切分支必须清历史换基线(与切画布同口径);
   - **视口持久化**(`CanvasSnapshot.viewport`)—— 每个分支各自记视角;
   - **Agent 记忆**(`canvasMemory[canvasId]`)—— 分支是否共享对话上下文。
6. **文档**:同步 `PRD` §5.1.3 与 `docs/节点手册.md` 的分支相关章节。
