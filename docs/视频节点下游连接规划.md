## 1. 背景与目标

shot(镜头/视频生成)节点是画布上**单次运行成本最高的节点**(h3.c 推理 8–10 分钟),
它的产物是一个 MP4(内嵌 h3.c 同步音轨,落 `BIGBOTART_H3_OUTPUTS`,节点自带 `resultPath`)。
所有下游连接的本质问题只有一个:**怎么消费这个 MP4 / 它的帧 / 它的音轨**。

现状:`COMPAT` 查不到新节点 id 时兜底放开全部下游,即 **UI 上"能连"但不代表"有用"**。
本规划定义 shot 节点下游连接的**许可集、用途、优先级与落地机制**。

## 2. 下游连接矩阵

| # | 下游节点 | 连上后干什么(用视频来干啥) | 现状 |
|---|---|---|---|
| 1 | `shot`(镜头接续) | 上游尾帧自动作为下游 `--first-frame`,形成**连续镜头链**(动作/运镜连续,H3「动作连续链」);每段可各自锁 `--ref-image` 角色 | 🟠 已声明未接线:refs 自动注入只处理 asset→shot,尾帧→首帧桥接是 TODO |
| 2 | `timeline`(入线剪辑) | N 个镜头的 Take 按序入线 → 裁切/转场/响度 → **FFmpeg 导出成片**(保留内嵌音轨) | 🟠 UI + `ExportService` 在,`shotNodeIds` 不随连线自动填充,纯提示占位 |
| 3 | `image-edit`(取帧再编辑) | 从视频**抽一帧**当输入图 → 指令编辑 / I2I / Inpaint / Outpaint → 修复版回灌当首帧,形成「生成→检查→修复」闭环 | 🟠 手册允许,但**无 ffmpeg 抽帧能力** |
| 4 | `workflow-output`(收口交付) | 工作流模式下把镜头产物归档到 `runs/<runId>/final/`,作为交付物(kind='video' 的 output) | 🟠 设计落定代码未落;`sourceNodeIds` 不随连线自动填充 |
| 5 | `asset`(发布回资产中心)⭐ 建议补 | 生成视频**归档为资产**,之后可:被别的 shot 当 `--ref-video`(Ref2VA 风格/动作参考)、入另一工作流 input 槽位、拖到时间线直接做媒体源 | ❌ 手册/COMPAT 均未声明;PRD「画布↔资产中心双写」正好落在这 |
| 6 | `audio-ref`(音轨复用)⭐ 建议补 | 提取视频产物音轨 → 当 `--ref-audio` 回灌其他镜头(带声直出) | ❌ 未声明(audio-ref 目前只做上游) |
| 7 | `director`(运镜提炼)🟡 可选 | 把已验证镜头的运镜抄进导演台 prompt,生成运镜参考小样 | ❌ director 本身 P1 占位,可后续接 |
| 8 | `document`(镜头/剪辑说明)🟡 可选 | 导出镜头说明 Markdown(时间码/参数/提示词);timeline→doc 已有同型设计 | ❌ 未声明但低成本 |

### 不建议连接

| 下游 | 原因 |
|---|---|
| `image-upscale` | 超分只吃图(视频超分 P2) |
| `image-gen` | 文本→图节点,与视频产物无数据流关系 |
| 任何 → `workflow-output` 之外的多层循环 | 骨架期不做环校验,避免死循环 |

## 3. 优先级规划

### P0 — 把已声明的 4 条真正接通(#1 #2 #3 #4) ✅ 已落地

> 统一边分派机制已实现(`CanvasPage.tsx` 的 dispatch effect,依赖 `[edges, nodes]`,幂等收敛、删除边自动撤销派生态):

```
对每个下游节点,遍历其入边:
  asset  入边(label=ref-audio/ref-image) → 注入 refs[](auto 标记,手动 refs 保留)     ✅
  shot   入边(接续)                      → 注入 refs[role='first-frame', path=上游尾帧] ✅
  timeline 入边                          → shotNodeIds 入线(按边序去重)              ✅
  workflow-output 入边                   → outputs[].sourceNodeIds(按 kind 匹配)      ✅
  wf-input 入边(label=slot-<name>)       → slots[name].value(asset/inline-text)       ✅
  shot → image-edit                      → inputFrameSource(取帧源,首/尾帧可选)       ✅
```

- **shot → asset 发布**:产物 MP4 写资产中心 → 后续可做 `--ref-video`(Ref2VA 风格/动作参考,调研报告已列此能力)。

### P2 — 锦上添花(#6 #7 #8)

## 4. 一句话总结

视频节点的下游价值排序:

```
接续(链式成片) > 入线(剪辑导出) > 取帧(修复重绘再回灌) > 收口(交付归档) > 发布为资产(复用为 ref-video / 素材)
```

当前骨架只做到了「线能画」;四项头号用途的自动桥接(尾帧→首帧、shot→shotNodeIds、视频→抽帧、产物→sourceNodeIds/资产)均为占位,是下一阶段最有价值的接线点。
