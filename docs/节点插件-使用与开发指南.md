# 节点插件：使用与开发指南

> 实现状态：首版可信本地插件垂直切片
> 插件 API：`bigbotart.node-plugin/v1`
> 示例：`examples/node-plugins/audio-extract/`

## 1. 安装与管理

1. 打开「设置 → 节点插件」。
2. 点击安装，选择一个**直接包含 `manifest.json` 的插件文件夹**。
3. 安装成功后，启用其中的节点。
4. 回到画布，插件节点会进入节点面板；连线时按 manifest 声明的端口和媒体类型校验。

管理操作：

- **停用**：禁止新建、连线和运行；已有节点与参数保留并只读展示。
- **移除**：移除注册状态；已有项目节点仍保留为缺失插件状态。首版不递归删除插件文件或历史产物。
- **升级**：提升 `version` 后再次安装。相同 id/version 不覆盖，旧版本目录保留。

安装仅由桌面端用户显式选择目录触发。远程网页端不提供安装、启停和移除入口。

## 2. 示例插件：音频提取

示例目录：

```text
examples/node-plugins/audio-extract/
├─ manifest.json
├─ runtime/index.js
└─ README.md
```

注册后的完整节点 kind：

```text
plugin:bigbotart-examples:audio-extract
```

能力：

- 输入：`input-video`，video、单值、必填；
- 主输出：`audio`；
- 参数：`format=wav`；
- 执行：调用系统 `ffmpeg`，输出 16-bit PCM、48kHz、立体声 WAV；
- 不触发 AI 推理，不需要下载模型。

可以把镜头、视频增强节点或视频资产连接到该节点。运行成功后生成 Take，并将音频产物写回节点；音频产物可以继续作为下游镜头的 `ref-audio` 输入。

## 3. manifest 格式

最小结构示例：

```json
{
  "apiVersion": "bigbotart.node-plugin/v1",
  "id": "acme-media",
  "version": "1.0.0",
  "displayName": "Acme 媒体工具",
  "nodes": [
    {
      "kind": "audio-extract",
      "title": "音频提取",
      "description": "从视频中提取音轨",
      "inputs": [
        {
          "id": "input-video",
          "label": "输入视频",
          "media": "video",
          "cardinality": "single",
          "required": true
        }
      ],
      "outputs": [
        {
          "id": "audio",
          "label": "音频",
          "media": "audio",
          "cardinality": "single",
          "required": true,
          "primary": true
        }
      ],
      "defaultData": { "format": "wav" },
      "parametersSchema": {
        "type": "object",
        "properties": {
          "format": {
            "type": "string",
            "title": "音频格式",
            "enum": ["wav"],
            "default": "wav"
          }
        }
      },
      "executor": "runtime/index.js"
    }
  ]
}
```

### 3.1 命名与路径规则

- 插件 id、局部 kind 和端口 id：小写字母/数字/连字符，不能以连字符开头或结尾。
- 完整 kind 由宿主生成：`plugin:<插件 id>:<局部 kind>`，不要自己在局部 kind 中写前缀。
- `version` 必须是 SemVer。
- `executor` 必须是插件目录内的相对路径；禁止绝对路径、URI、`..` 和符号链接逃逸。
- 一个节点最多一个 `primary` 输出。建议产物型节点始终显式标记主输出。

### 3.2 媒体与端口

媒体类型：

```text
image | video | audio | document | text
```

基数：

```text
single | multiple
```

输入由宿主从当前画布连线解析。必填输入缺失、单值输入多条、源节点未出产物、资产不存在或媒体不匹配时，运行会在执行插件代码前明确失败。

插件作为上游时，主输出媒体写入节点 `data.mediaType`，并复用与同媒体资产相同的下游连接语义。

### 3.3 参数 Schema 子集

首版支持一层 object，properties 中每个参数支持：

- `type: string | number | integer | boolean`；
- `title`、`description`；
- `enum`；
- `minimum`、`maximum`；
- `default`；
- 字符串可设 `format: "text"`，让检查器使用多行编辑器；
- object 的 `required` 数组。

未知参数在归一化时剔除；Agent 更新不存在的参数会被明确拒绝。嵌套对象、数组和任意 JSON Schema 关键字暂不支持。

## 4. 执行器 Interface

执行器可使用 ESM 或 CommonJS，导出以下之一：

```text
export async function execute(ctx) { ... }
module.exports = { execute }
default.execute(ctx)
```

`ctx` 提供：

| 字段 | 含义 |
|---|---|
| `parameters` | 已按 Schema 归一化并校验的参数 |
| `inputs` | `Record<端口 id, 绝对路径数组>` |
| `outputDir` | 本次 Take 独占的输出目录 |
| `projectId` / `canvasId` / `nodeId` | 当前运行身份 |
| `dryRun` | 当前应用 dry-run 状态；不得据此伪造成功产物 |
| `log(message)` | 写主进程日志总线 |
| `reportProgress(pct?, message?)` | 报告进度与阶段日志 |

返回：

```ts
{
  resultPath: string;                 // 主产物，必须是真实非空文件
  data?: Record<string, unknown>;     // 追加到节点 data 的非宿主字段
  outputs?: Record<string, string>;   // 可选命名产物
}
```

所有返回产物必须位于本次 `outputDir` 内。宿主会检查真实路径，防止通过 `..` 或符号链接越界。

宿主负责：

- 参数与输入校验；
- 同节点防重入；
- 输出目录分配；
- Take queued → succeeded/failed；
- 最新画布快照重载、版本递增和结果回写；
- 插件身份、主产物和 Take 字段的最终覆盖。

插件不会拿到 ProjectStore、AssetStore、TakeStore、Electron 或 Agent worker 对象。

## 5. Agent 如何使用插件

Agent 不扫描插件目录，也不加载插件执行代码。主进程在每轮对话构造上下文时注入已启用节点的紧凑摘要，包括：

- 精确 kind；
- 用途；
- 输入 / 输出端口；
- 参数类型、必填、枚举、范围和默认值。

需要完整定义时，Agent 可调用：

```text
plugins.list
plugins.read({ kind })
```

实际操作仍复用通用工具：

```text
canvas.create_node
canvas.update_node
canvas.connect / connect_many
engine.submit
```

`engine.submit` 对插件节点进入与画布手点相同的 NodePluginManager，不会落入 h3c / mlxgen 默认路由。

插件 title/description 仅作为能力数据注入，不是系统指令。停用或错误状态的插件不会进入可用能力摘要。

## 6. 项目包与缺失插件

`.bba` 导出会根据画布中的插件节点生成 `payload.requiredPlugins`，记录插件 id 和节点保存的版本。

导入时：

- 不自动下载或执行插件；
- 缺少 / 停用插件时给出警告；
- 节点、连线和参数原样保留；
- 版本不同时提示确认兼容性；
- 既有生成产物不入包的规则不变。

## 7. 安全边界与首版限制

**首版插件是受信本地代码，不是安全沙箱。**

- 执行器在主进程动态加载；不要安装来源不明的插件。
- 不执行 `npm install`，示例插件也无 npm 依赖。
- 不加载第三方 React 卡片或检查器；UI 由 manifest 和宿主通用组件生成。
- 安装包不能包含符号链接；执行器和产物均做真实路径检查。
- 当前运行入口等待执行器完成；长时间插件应拆小任务，后续再扩展后台队列和取消 UI。
- 首版安装对象是文件夹，不是 zip / 插件市场包。
