# 节点插件：使用与开发指南

> 实现状态：首版可信本地节点插件
>
> 插件 API：`bigbotart.node-plugin/v1`
>
> 更新日期：2026-11-04
>
> 官方示例：[`examples/node-plugins/audio-extract/`](../examples/node-plugins/audio-extract/)

本文介绍如何为 BigBotArt 制作一个**可安装、可连线、可运行的画布节点插件**。如果你只想快速验证插件能力，可以直接安装仓库中的音频提取示例；如果要开发自己的插件，按第 2 节从零实现即可。

节点插件与 Agent 技能、Provider 不是一回事：

- **节点插件**：增加新的画布节点、参数、端口与执行行为，本文的主题。
- **Agent 技能**：给 Agent 的操作说明或画布模板，不提供新的节点执行器。
- **Provider**：为既有图片/视频节点增加模型或引擎后端，不等同于完整节点插件。

## 1. 插件的组成与工作流程

一个首版插件至少包含两个文件：

```text
my-media-tools/
├─ manifest.json          # 节点、端口、参数与执行入口声明
└─ runtime/
   └─ index.cjs           # 真正干活的 execute(ctx)
```

建议再带上 `README.md` 和 `LICENSE`，说明用途、依赖、安装方法与许可。

安装和运行的分工如下：

1. 用户在桌面端「设置 → 节点插件」中显式选择插件文件夹。
2. 宿主严格校验 `manifest.json`，检查执行器与文件路径，再把整个文件夹复制到版本化安装目录。
3. 已启用的插件节点进入节点面板，检查器由 `parametersSchema` 自动生成，不需要编写 React UI。
4. 运行时，宿主校验参数、解析连线输入、创建 Take 和本次独立输出目录，然后调用 `execute(ctx)`。
5. 执行器生成真实文件并返回 `resultPath`；宿主验证产物后，将 Take 置为成功，并把产物写回节点。
6. 任一步骤失败都应抛出明确错误；宿主会将已创建的 Take 置为失败，不接受空文件或伪造成功。

## 2. 从零制作第一个插件

下面制作一个 `my-media-tools` 插件：接收一个视频，调用本机 `ffmpeg` 提取第一条音轨，输出 16-bit PCM、48kHz、立体声 WAV。它不触发 AI 推理，也不需要 npm 依赖。

### 2.1 准备环境

- 使用 BigBotArt 桌面端；远程网页端不能安装或管理本地插件。
- 安装 `ffmpeg`，并确认其在 `PATH` 中：

```bash
ffmpeg -version
```

- 准备一小段**包含音轨**的测试视频，先用短文件验证，避免长时间等待。

### 2.2 创建目录

在你自己的开发目录中创建：

```text
my-media-tools/
├─ manifest.json
├─ runtime/
│  └─ index.cjs
└─ README.md
```

选择安装目录时，应选择直接包含 `manifest.json` 的 `my-media-tools/`，而不是它的父目录或 `runtime/`。

### 2.3 编写 manifest.json

```json
{
  "apiVersion": "bigbotart.node-plugin/v1",
  "id": "my-media-tools",
  "version": "1.0.0",
  "displayName": "我的媒体工具",
  "nodes": [
    {
      "kind": "audio-extract",
      "title": "音频提取",
      "description": "从视频中提取第一条音轨，生成 16-bit PCM、48kHz 立体声 WAV",
      "inputs": [
        {
          "id": "input-video",
          "label": "输入视频",
          "media": "video",
          "cardinality": "single",
          "required": true
        }
      ],
      "outputs": [
        {
          "id": "audio",
          "label": "音频",
          "media": "audio",
          "cardinality": "single",
          "required": true,
          "primary": true
        }
      ],
      "defaultData": {
        "format": "wav"
      },
      "parametersSchema": {
        "type": "object",
        "properties": {
          "format": {
            "type": "string",
            "title": "音频格式",
            "enum": ["wav"],
            "default": "wav"
          }
        },
        "required": ["format"]
      },
      "executor": "runtime/index.cjs"
    }
  ]
}
```

安装后，这个节点的完整 kind 是：

```text
plugin:my-media-tools:audio-extract
```

`manifest` 使用严格白名单校验，未知字段也会被拒绝。例如首版根节点不支持自行添加 `author`、`homepage`、`icon` 等字段；这些信息请写进 `README.md`。

### 2.4 编写执行器

把下面内容写入 `runtime/index.cjs`：

```js
'use strict';

const { spawn } = require('node:child_process');
const { existsSync, statSync } = require('node:fs');
const { join } = require('node:path');

async function execute(ctx) {
  const input = ctx.inputs['input-video']?.[0];
  if (!input) throw new Error('缺少 input-video 输入');
  if (!existsSync(input) || !statSync(input).isFile()) {
    throw new Error(`输入视频不存在: ${input}`);
  }

  const format = ctx.parameters.format;
  if (format !== 'wav') throw new Error(`不支持的音频格式: ${String(format)}`);

  const outputPath = join(ctx.outputDir, 'audio.wav');
  const args = [
    '-y',
    '-i', input,
    '-vn',
    '-map', '0:a:0',
    '-acodec', 'pcm_s16le',
    '-ar', '48000',
    '-ac', '2',
    outputPath,
  ];

  ctx.log('开始提取音轨：16-bit PCM / 48kHz / 立体声');
  ctx.reportProgress(0, '正在提取音轨');

  await new Promise((resolve, reject) => {
    const child = spawn('ffmpeg', args, {
      stdio: ['ignore', 'ignore', 'pipe'],
    });
    let stderr = '';

    child.stderr.on('data', (chunk) => {
      stderr += chunk.toString('utf8');
      // 长任务只保留日志尾部，避免 stderr 无限占用内存。
      if (stderr.length > 64 * 1024) stderr = stderr.slice(-32 * 1024);
    });
    child.on('error', (error) => {
      reject(new Error(`无法启动 ffmpeg: ${error.message}`));
    });
    child.on('close', (code) => {
      if (code !== 0) {
        const tail = stderr
          .split(/\r?\n/)
          .filter(Boolean)
          .slice(-12)
          .join('\n')
          .slice(-4000);
        reject(new Error(`ffmpeg 退出码 ${code ?? '未知'}${tail ? `:\n${tail}` : ''}`));
        return;
      }
      if (!existsSync(outputPath) || !statSync(outputPath).isFile() || statSync(outputPath).size === 0) {
        reject(new Error('ffmpeg 未生成有效音频；请确认输入视频包含音轨'));
        return;
      }
      resolve();
    });
  });

  ctx.reportProgress(100, '音轨提取完成');

  // 推荐使用相对 outputDir 的路径；宿主会解析并验证真实文件。
  return {
    resultPath: 'audio.wav',
    outputs: { audio: 'audio.wav' },
    data: { sampleRate: 48000, channels: 2 },
  };
}

module.exports = { execute };
```

关键点：

- 必须导出 `execute(ctx)`；CommonJS 使用 `module.exports = { execute }`。
- 输入路径从 `ctx.inputs[端口id]` 读取。即使声明为 `single`，值仍然是路径数组，所以取 `[0]`。
- 只把产物写进本次 `ctx.outputDir`，不要写到插件安装目录或任意系统目录。
- 外部命令失败、输入无音轨、输出为空时都必须抛错，不能返回假产物。
- `outputs` 的键建议与输出端口 id 一致；`resultPath` 始终是必需的主产物。
- `data` 只放插件自己的附加信息。`resultPath`、`currentTakeId`、`mediaType`、`__plugin` 等宿主字段最终由宿主覆盖，插件不能伪造它们。

### 2.5 可选：不启动应用，先单测执行器

在插件根目录执行下面命令，把最后的视频路径换成真实绝对路径：

```bash
node -e '
const { mkdtempSync } = require("node:fs");
const { tmpdir } = require("node:os");
const { join } = require("node:path");
const { execute } = require("./runtime/index.cjs");
const outputDir = mkdtempSync(join(tmpdir(), "my-media-tools-"));
execute({
  parameters: { format: "wav" },
  inputs: { "input-video": [process.argv[1]] },
  outputDir,
  projectId: "dev-project",
  canvasId: "dev-canvas",
  nodeId: "dev-node",
  dryRun: true,
  log: console.log,
  reportProgress: (pct, message) => console.log(`${pct ?? ""}% ${message ?? ""}`),
}).then((result) => {
  console.log("输出目录:", outputDir);
  console.log("执行结果:", result);
}).catch((error) => {
  console.error(error);
  process.exitCode = 1;
});
' "/absolute/path/to/input.mp4"
```

这种测试只验证执行器本身，不会验证 manifest、画布连线、Take 或结果回写；完整链路仍应在应用中运行一次。

### 2.6 安装并在画布中运行

1. 打开 BigBotArt 桌面端的「设置 → 节点插件」。
2. 点击「安装本地插件…」，选择 `my-media-tools/` 文件夹。
3. 确认插件状态为「已启用」；安装失败时按页面显示的具体原因修正。
4. 回到画布，从节点面板添加「音频提取」。
5. 将一个包含音轨的视频资产、已完成的镜头或视频增强节点连接到 `input-video`。
6. 点击运行。成功后应生成 WAV 和一条成功的 Take，节点显示产物，音频还可继续连接下游的音频参考端口。

如果节点面板没有立即出现新节点，先确认插件已启用，再重新进入画布；仍不显示时重启应用并查看插件状态与主进程日志。

### 2.7 修改与升级

**不要直接编辑安装目录来迭代。** 修改源目录后，按以下流程重新安装：

1. 修改源代码或 manifest。
2. 提升 `version`，例如 `1.0.0` → `1.0.1`。
3. 再次选择源文件夹安装。
4. 用一个小型测试项目验证参数、输入、输出与旧画布兼容性。

首版规则：

- 相同 `id + version` 不覆盖，重复安装会被拒绝。
- 新版本安装后切换当前注册版本，旧版本目录保留用于回查。
- 保持插件 `id` 和节点局部 `kind` 稳定，否则旧画布中的完整 kind 会失配。
- 修改必填参数、端口 id、媒体类型或输入语义可能破坏旧节点；升级时优先增加带默认值的可选参数，并在 README 写明不兼容变化。

## 3. 使用现成示例与插件管理

仓库自带一个已测试的音频提取插件：

```text
examples/node-plugins/audio-extract/
├─ manifest.json
├─ runtime/index.js
└─ README.md
```

它的完整节点 kind 为 `plugin:bigbotart-examples:audio-extract`，能力与本教程类似。可以直接安装该文件夹验证完整链路。

仓库还带一个**受控 UI** 示例（可视化姿势选择器，见第 6 节）：

```text
examples/node-plugins/pose-selector/
├─ manifest.json
├─ runtime/index.cjs
├─ catalog/
│  ├─ poses.json
│  └─ thumbs/*.png
└─ README.md
```

管理操作：

- **停用**：禁止新建、连线和运行；已有节点与参数保留并只读展示。
- **移除**：只移除注册状态；已有项目节点保留为缺失插件状态，不递归删除插件文件或历史产物。
- **升级**：提升 `version` 后再次安装；相同 id/version 不覆盖。

安装只由桌面端用户显式选择目录触发。远程网页端不提供安装、启停和移除入口。

## 4. manifest 完整参考

### 4.1 根字段

| 字段 | 规则 |
|---|---|
| `apiVersion` | 当前固定为 `bigbotart.node-plugin/v1` |
| `id` | 1–64 位小写字母、数字或连字符，首尾不能是连字符 |
| `version` | 合法 SemVer，例如 `1.0.0`、`1.1.0-beta.1` |
| `displayName` | 1–120 字符的插件显示名 |
| `nodes` | 至少一个节点定义；同一插件内局部 `kind` 不能重复 |

### 4.2 节点字段

| 字段 | 说明 |
|---|---|
| `kind` | 插件内局部节点名，不带 `plugin:` 前缀 |
| `title` | 节点面板与画布中的显示名，1–120 字符 |
| `description` | 用途说明，1–4000 字符；Agent 摘要只保留压缩后的前 160 个 Unicode 字符，因此应先说核心用途 |
| `inputs` / `outputs` | 输入、输出端口数组 |
| `defaultData` | 节点默认参数，只能包含 schema 中声明的参数，且值必须合法 |
| `parametersSchema` | 检查器与运行参数使用的 Schema 子集 |
| `executor` | 相对插件根目录的执行器路径 |
| `ui` | 可选的受控 UI 声明（首版只有 `picker`，见第 6 节）；缺省走 Schema 自动生成的原生控件 |

路径与命名约束：

- 完整 kind 由宿主生成：`plugin:<插件 id>:<局部 kind>`。
- 插件 id、局部 kind、端口 id 都使用小写字母/数字/连字符，不能以下划线或冒号命名。
- `executor` 禁止绝对路径、URI、空路径段与 `..` 穿越；安装包不能包含符号链接。
- 每个节点最多一个 `primary: true` 输出。产物型节点应显式标记主输出，供画布预览与下游连线使用。

### 4.3 端口字段

每个端口必须声明：

| 字段 | 可选值 / 含义 |
|---|---|
| `id` | 执行器读取输入、返回命名输出时使用的稳定标识 |
| `label` | UI 显示名，1–120 字符 |
| `media` | `image`、`video`、`audio`、`document`、`text` |
| `cardinality` | `single` 或 `multiple` |
| `required` | 是否必填；输入缺失会在调用执行器前失败 |
| `primary` | 仅输出端口可用，最多一个主输出 |

宿主从当前画布连线构造 `ctx.inputs`：

- `single` 输入收到多条边会失败；`multiple` 输入按连线解析为多个路径。
- 源可以是资产，也可以是具有 `resultPath` 的上游产物节点。
- 源文件不存在、资产被删除、产物未生成或媒体类型不匹配时，运行会在执行插件代码前明确失败。
- 当前输入契约是**文件路径**，不是任意内联 JSON 数据。

### 4.4 参数 Schema 子集

首版只支持一层 object，每个属性支持：

| 字段 | 说明 |
|---|---|
| `type` | `string`、`number`、`integer`、`boolean` |
| `title` / `description` | 检查器中的名称与说明 |
| `enum` | 非空枚举数组，成员类型必须与 `type` 一致 |
| `minimum` / `maximum` | 仅用于 `number` / `integer` |
| `default` | 默认值；`required` 参数也可由默认值满足 |
| `format: "text"` | 仅用于字符串，让检查器使用多行文本编辑器 |
| `required` | object 级字符串数组，只能引用已声明参数 |

暂不支持嵌套对象、数组参数或任意 JSON Schema 关键字。未知参数在归一化时剔除；Agent 更新未声明参数会被明确拒绝。`number` 必须是有限数字，`integer` 还必须是整数。

## 5. 执行器 Interface 参考

执行器可使用 ESM 或 CommonJS，支持以下导出形式。下面是三个独立示例，不要把它们合并到同一个文件：

```js
// ESM
export async function execute(ctx) { /* ... */ }

// CommonJS
module.exports = { execute };

// 或 default.execute
export default { async execute(ctx) { /* ... */ } };
```

为了避免安装目录祖先 `package.json` 的模块类型影响，CommonJS 文件推荐使用 `.cjs`，ESM 文件推荐使用 `.mjs`。

### 5.1 运行上下文

| 字段 | 类型与含义 |
|---|---|
| `parameters` | 已按 Schema 归一化并校验的参数对象 |
| `inputs` | `Record<端口 id, string[]>`，值为已验证的绝对文件路径数组 |
| `outputDir` | 本次 Take 独占的输出目录，所有返回产物都必须位于其中 |
| `projectId` / `canvasId` / `nodeId` | 当前运行身份 |
| `dryRun` | 当前应用 dry-run 状态；**不是自动跳过插件执行的开关**，不得据此伪造成功产物 |
| `log(message)` | 写主进程日志总线 |
| `reportProgress(pct?, message?)` | 报告进度与阶段日志；首版主要用于日志留痕 |

插件不会拿到 `ProjectStore`、`AssetStore`、`TakeStore`、Electron 或 Agent worker 对象。

### 5.2 返回值

```ts
{
  resultPath: string;                 // 必需：主产物，必须是真实非空文件
  data?: Record<string, unknown>;     // 可选：追加到节点 data 的插件字段
  outputs?: Record<string, string>;   // 可选：命名产物，键建议对应输出端口 id
}
```

`resultPath` 和 `outputs` 中的路径可以是 `outputDir` 内的相对路径，也可以是仍位于该目录内的绝对路径。推荐返回相对路径，例如 `resultPath: 'audio.wav'`。

宿主会检查：

- 主产物是否存在、是普通文件且非空；
- 所有返回产物是否位于本次 `outputDir` 内；
- 是否通过 `..` 或符号链接越出输出目录；
- `data` 是否为对象，`outputs` 是否为字符串路径映射。

默认产物目录形态为：

```text
~/.bigbotart/outputs/plugins/<pluginId>/<nodeId>/<takeId>/
```

如配置了应用数据目录或产物目录环境变量，实际根路径会随配置变化。

### 5.3 宿主负责的生命周期

- 参数与输入校验；
- 同一节点防重入；
- 输出目录分配；
- Take `queued → succeeded/failed`；
- 执行完成后重新加载最新画布快照、推进版本并回写结果；
- 最终覆盖插件身份、主产物、媒体类型与 Take 字段。

执行期间如果画布或节点被删除、节点 kind 改变，结果回写会明确失败，不会把结果写到别的节点上。

## 6. 受控 UI：可视化选择器（picker）

如果节点参数不是「一个字符串枚举」而是「一堆带缩略图的候选项」（姿势库、镜头库、素材库、预设模板），逐项塞进 `enum` 会很难用。插件可以在 manifest 节点上声明 `ui`，由**宿主渲染通用选择器**：搜索、字段筛选、分组 tab、缩略图网格、选中预览。

首版只有一种控件 `picker`。**插件不提供任何 UI 代码**：宿主不加载第三方 React，卡片与检查器由宿主统一实现，插件只提供「清单数据 + 图片文件」。

### 6.1 manifest 声明

```json
{
  "ui": {
    "type": "picker",
    "title": "姿势选择器",
    "valueParam": "pose",
    "variantParam": "angle",
    "variantField": "angle",
    "catalog": "catalog/poses.json",
    "searchFields": ["id", "label", "description"],
    "filterFields": ["system", "category"],
    "tabField": "angle",
    "thumbnailField": "thumb"
  }
}
```

| 字段 | 含义 |
|---|---|
| `type` | 固定 `picker` |
| `title` | 控件标题 |
| `valueParam` | 选中项写入的节点参数名，**必须**在 `parametersSchema.properties` 里声明 |
| `valueField` | 可选：写入 `valueParam` 的是清单项的**哪个字段**；缺省写条目 `id` |
| `variantParam` | 可选：把清单项某个字段写入第二个参数（例如 `angle`） |
| `variantField` | `variantParam` 对应的清单字段；缺省时用 `tabField` |
| `catalog` | 清单 JSON 路径（相对插件根目录，禁止绝对路径与 `..`） |
| `searchFields` | 搜索命中的字段；缺省 `["id","label"]` |
| `filterFields` | 渲染成下拉筛选的字段（例如体系、分类） |
| `tabField` | 渲染成分组 tab 的字段（例如视角） |
| `thumbnailField` | 缩略图字段；其值是相对**清单文件所在目录**的图片路径 |

`valueParam` / `variantParam` 未在 `parametersSchema` 声明时，安装会被拒绝——选择结果无处落盘，参数会被归一化丢掉。

由选择器接管的参数不再重复渲染成原生控件，避免出现「下拉框 + 网格」两套入口；其余参数照旧走 Schema 表单。

#### `valueField`：参数值不等于条目 id 时

清单条目 `id` 只是**清单内部的唯一标识**，而参数值未必是它。典型场景：参数是一个长枚举值（`"full_sexy_P001 | 全身单人・性感系 | 站姿 | S形站姿・胯部侧顶"`），清单条目 id 是短 id（`full_sexy_P001`）。这时声明 `valueField`，宿主就把该字段的值写进 `valueParam`：

```json
{
  "ui": {
    "type": "picker",
    "title": "姿势选择器",
    "valueParam": "pose",
    "valueField": "poseValue",
    "catalog": "data/picker-catalog.json"
  }
}
```

声明了 `valueField` 后，**选中态匹配也按该字段的值走**——参数里存的是 `poseValue`，宿主按它回找选中条目，缩略图高亮才对得上。

### 6.1.1 picker 独占参数与「建节点那一刻」

选择器接管的参数（`valueParam` / `variantParam`）的值**由用户在检查器里挑**，建节点那一刻必然还是空的。因此宿主在这两个时机用不同口径校验：

| 时机 | 校验口径 |
|---|---|
| 建节点 | picker 独占参数**允许为空**；其余必填参数照常要求齐全，非法取值照常拒绝 |
| 运行插件 | 全部必填参数都必须齐全，缺一个就明确失败，不产出假结果 |

这条规则是为了让 picker 真的能用：早先建节点也按 `required` 校验，插件声明 `required: ["pose"]` 时节点**根本建不出来**，检查器也就永远打不开，选择器形同虚设。

因此：

- 插件**应当**把选择器接管的参数写进 `required`（运行前确实必须有值）；
- `defaultData` 里**不必**给选择器接管的参数填默认值（用户会在检查器里挑）；
- 建节点后检查器会提示「请在「姿势选择器」中选择一项后再运行」，而不是报「参数错误」——「还没选」和「写错了」是两回事。

### 6.2 清单文件格式

```json
{
  "items": [
    {
      "id": "stand-front",
      "label": "站立",
      "description": "双脚与肩同宽，正面平视",
      "system": "人体",
      "category": "站姿",
      "angle": "正面",
      "thumb": "thumbs/stand-front.png"
    }
  ]
}
```

- `id` 必填且唯一；未声明 `valueField` 时选中后写入 `valueParam`。
- `label` 必填。
- `description` 可选。
- `thumb` 可选，相对清单文件所在目录的图片路径。
- 其余字段（`system`、`category`、`angle` …）是附加字段，值只允许 string / number / boolean，供搜索、筛选、分组使用；其中被 `valueField` 指名的那个字段就是写进 `valueParam` 的值。

清单内容非法（重复 id、缺 label、越界缩略图、非原始类型字段）时，选择器会显示明确错误，而不是给出一个空白列表。

> 缩略图路径相对**清单文件所在目录**解析，且禁止 `..` 穿越。
> 所以缩略图要么与清单同目录，要么在清单目录的**子目录**里（`thumbs/xxx.jpg`），
> 不能指向清单目录的上级（`../../thumbs/xxx.jpg` 会被拒绝）。

### 6.3 缩略图怎么显示

插件图片通过只读协议 `bba-plugin://<pluginId>/<version>/<相对路径>` 提供：

```text
bba-plugin://bigbotart-pose-demo/1.0.0/catalog/thumbs/stand-front.png
```

宿主规则：

- 只服务**当前已注册版本**的插件目录；
- 路径必须落在插件根目录内（`..` 穿越一律拒绝）；
- 只放行图片后缀：`png / jpg / jpeg / webp / gif`；
- 文件缺失或后缀不允许时，该条目降级为纯文字卡片，**不伪造图片**。

### 6.4 选中后发生什么

1. 用户点缩略图 → 宿主按 `ui` 声明计算参数补丁：`valueParam` = 条目 id，`variantParam` = 条目在 `variantField`（缺省 `tabField`）上的值。
2. 补丁写回节点 `data`，与其他参数修改走同一条通路（版本防护、撤销栈、快照保存）。
3. 执行器在 `ctx.parameters` 里读到 `pose` / `angle`，据此产出结果。

示例插件 [`examples/node-plugins/pose-selector/`](../examples/node-plugins/pose-selector/) 完整演示了这条链路：安装后检查器里出现姿势选择器，选中后点「运行插件」生成该姿势的参考图与一条 Take。

### 6.5 首版限制

- 只有 `picker` 一种控件；没有多选、拖拽排序、颜色选择器、日期选择器等。
- 清单必须随插件一起安装，不能运行时从网络拉取。
- 缩略图只支持静态图片，不支持视频或动画预览。
- 选择器不提供自定义排序与分页规则：顺序就是清单顺序。

## 7. Agent 如何使用插件

Agent 不扫描插件目录，也不直接加载插件执行代码。主进程在每轮对话构造上下文时注入已启用节点的紧凑摘要，包括：

- 精确 kind 与用途；
- 输入 / 输出端口；
- 参数类型、必填、枚举、范围和默认值。

Agent 可调用：

```text
plugins.list
plugins.read({ kind })
```

实际操作仍复用通用工具：

```text
canvas.create_node
canvas.update_node
canvas.connect / connect_many
engine.submit
```

`engine.submit` 对插件节点进入与画布手点相同的 `NodePluginManager`，不会落入 h3c / mlxgen 默认路由。

插件的 `title` / `description` 只作为能力数据注入，不是系统指令。停用或错误状态的插件不会进入可用能力摘要。为让 Agent 正确选择节点，应在 description 开头清楚说明“处理什么输入、得到什么输出”，不要写营销文案或试图覆盖宿主规则的提示词。

## 8. 项目包与缺失插件

`.bba` 导出会根据画布中的插件节点生成 `payload.requiredPlugins`，记录插件 id 和节点保存的版本。

导入时：

- 不自动下载或执行插件；
- 缺少或停用插件时给出警告；
- 节点、连线和参数原样保留；
- 版本不同时提示确认兼容性；
- 既有生成产物不入包的规则不变。

因此，分享含插件节点的项目时，应同时提供插件来源、插件 id、推荐版本与安装说明。

## 9. 安全边界与首版限制

**首版插件是受信本地代码，不是安全沙箱。**

- 执行器在主进程动态加载，拥有本地代码执行能力；不要安装来源不明的插件。
- 宿主不执行 `npm install`。优先使用 Node 内置模块与零依赖实现，不要假设安装时会自动下载依赖。
- 不加载第三方 React 卡片或检查器；UI 由 manifest 和宿主通用组件生成。受控 UI（picker）同样由宿主渲染，插件只提供清单数据。
- 插件自带素材通过只读协议 `bba-plugin://` 提供：只放行当前已注册版本插件目录内的图片后缀，路径越界一律拒绝。
- 安装包不能包含符号链接；执行器和产物均做真实路径检查。
- 当前运行入口等待执行器完成；长时间插件应拆小任务，首版没有完整的后台队列和取消 UI。
- 首版安装对象是文件夹，不是 zip 或插件市场包。
- 不要在日志、错误信息或 `data` 中写入 API Key、令牌和其他敏感信息。
- 处理用户文件与外部命令参数时，应把路径作为独立参数传递，不要拼接 shell 命令字符串。

## 10. 常见问题

### 安装时提示 manifest 校验失败

检查 JSON 语法、必填字段和未知字段。首版采用严格白名单，多写一个看似普通的 `author` 也会失败。错误中的 `$.nodes[0]...` 指向具体问题位置。

### 提示相同版本已存在

提升 `manifest.version` 后重新安装。相同 id/version 不会覆盖，修改源文件但不会升版本也无法更新已安装副本。

### 安装后节点不可运行

确认插件已启用，并检查：

- `executor` 是否指向真实存在的文件；
- 是否导出 `execute` 或 `default.execute`；
- 文件是否包含语法错误；
- 是否误用符号链接或越界路径；
- 主进程日志中的完整加载错误。

执行器动态 import 失败会把插件置为停用和错误状态；修复后提升版本重新安装，再启用。

### 运行前提示缺少输入或媒体不匹配

检查连线的目标端口 id、上游是否已有真实产物、资产是否仍存在，以及输入是否满足 `single/multiple`。这类错误发生在执行器之前，不会创建 Take。

### 执行后提示产物无效

确认文件已经写入本次 `ctx.outputDir`，不是空文件，并返回正确 `resultPath`。不要只返回输入文件路径、目录路径或不存在的占位路径。

### dry-run 下插件为什么仍然执行

节点插件当前会真实调用执行器，`dryRun` 只是上下文信息，不会自动跳过本地转码或文件处理。插件必须始终生成真实产物；没有执行或执行失败就明确失败，不能伪造成功。

### 修改了源文件，应用里为什么还是旧逻辑

应用运行的是安装目录中的副本，不是源目录。提升版本并重新安装；不要期待源文件保存后热更新。

## 11. 发布前检查清单

- [ ] `manifest.json` 能通过安装校验，且没有多余字段。
- [ ] 插件 id、节点 kind、端口 id 稳定且符合命名规则。
- [ ] 使用新的 SemVer 版本，没有尝试覆盖同版本安装。
- [ ] 执行器语法正确，并导出 `execute(ctx)`。
- [ ] 必填输入、可选输入、多值输入和参数边界均已测试。
- [ ] 外部工具缺失、输入损坏、无音轨等失败路径会给出可操作错误。
- [ ] 所有产物都写入本次 `outputDir`，主产物真实且非空。
- [ ] 没有伪造成功、吞错、记录敏感信息或修改源插件目录的行为。
- [ ] 已在桌面端完成一次“安装 → 建节点 → 连线 → 运行 → Take/产物回写”的完整验证。
- [ ] 如声明了 `ui`：`valueParam` / `variantParam` 已在 `parametersSchema` 中声明，清单文件随插件安装，缩略图路径落在插件目录内。
- [ ] README 写明用途、系统依赖、安装步骤、版本兼容性与许可。
