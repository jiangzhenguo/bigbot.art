## 1. MiniMax-H3(h3.c · 文生视频+音频)

### 1.1 官方规范来源

- MiniMax 官方提示词指南:github.com/MiniMax-AI/MiniMax-H3 `docs/` 目录(本仓已全文落为内置技能
  `apps/desktop/src/main/builtin-skills/h3-prompt-writing.md`,623 行,含附录 A/B 完整规范)。
- 引擎侧佐证:`~/ai/mlx-gen/docs/minimax-h3.md` §Prompting(MLX-Gen 版实现的同口径说明,确认
  "模型就是按三段带标签的结构化提示词训练的")。

### 1.2 核心结构:三段带标签提示词

模型**按以下结构训练**,规范 prompt 由空行分隔的三个带标签段落组成:

```text
integrated_multimodal_description: <逐镜头画面描述>

overall_soundscape: <环境音/动作音/非语言人声,全片一段>

non_diegetic_music: <配乐;无则写 N/A 或 "No non-diegetic music; natural sound only.">
```

- `integrated_multimodal_description` = 主体:视觉、动作、镜头、说话人、台词、歌声与画内同步音,按时间线展开。
- `overall_soundscape` = 全片 1–4 句英文连续段落,只写环境音/物理动作音/非语言人声(台词和画内音乐**不重复**写进这里)。
- `non_diegetic_music` = 1–3 句,写配器/速度/节奏/动态变化,**禁止抽象情绪词**;观众才能听到的音乐才归这里。

### 1.3 五种输入模式

| 模式 | 输入 | 提示词要点 |
|---|---|---|
| T2VA | 纯文本 | 直接从三字段开始,无图像对齐指令 |
| I2VA | 首帧图 | 首行固定指令:`For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.` |
| FL2VA | 首帧+尾帧 | 首行:`How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark ...; Picture 2 (from Shot N) aligns with the S.SS-second mark ...` |
| L2VA | 尾帧图 | 首行同上但只声明尾帧对齐时刻;正文推断前序状态、收敛到尾帧 |
| Ref2VA | 图/视频/音频混合参考 | 六段重写格式(见 1.5) |

### 1.4 基础模式硬规则(官方指南 §4)

- **语言**:各段一律英文;台词/歌词/画面可见文字保留原语言(`<d>[Chinese] ...</d>`)。
- **镜头记号**:`[Shot 1]` 不带时间戳;后续镜头 `[Shot 2] At 00:03.500, ...`,切点严格递增且不超总时长。
- **切镜动词**:`the camera cuts to / the shot cuts to / transitions to / changes to / switches to`;仅在用户明确要求时用 cross-dissolve/fade/wipe。
- **运镜三维度** = 运动类型 + 幅度 + 速度,写成自然英文句子而非句尾标签堆砌:
  - 类型:Zoom In/Out、Push In/Pull Out、Pan Left/Right、Truck Left/Right、Tilt Up/Down、Pedestal Up/Down、Arc Shot、Tracking Shot、Static Shot、Shake Slightly/Strongly、POV、Roll Clockwise/Counterclockwise
  - 幅度:`with small/large amplitude`;速度:`at slow/fast speed`(中幅度常速省略)
- **说话人**:稳定 ID `(S1)`/`(S2)`,跨镜头复用;首次出现要给足身份线索(年龄/性别/音高/音色/语速);台词放 `<d>[语言] 原文</d>`,逐字保留不翻译。
- **画外音**:固定短语 `says in an off-screen voiceover`,且必须紧跟一句"该角色嘴唇保持闭合"。
- **跨切台词**:`<scenetrans>` 标记 + 声明音频跨切连续(`continues seamlessly across the cut`);被片尾截断用 `<cutoff>`。
- **画面文字**:英文双引号包裹、原文保留(如 `A red neon sign reading "营业中" ...`)。
- **时长**:prompt 描述的总时长必须与请求时长(4–15 秒)精确一致——**不虚构时长是官方红线**。

### 1.5 Ref2VA 六段重写格式

按顺序:`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`。

- 四类参考标签:`<Subject N>`(可复用可见内容)/ `<Picture N>`(具体帧锚)/ `<Video N>`(整段视频关系:剪辑源/续写起点/结构参考)/ `<Audio N>`(音频信号)。**标签跨全段落保持同一指向**(红线)。
- `summary` 以方括号任务类型开头,可组合:`keyframe completion` / `reference generation` / `video editing` / `video continuation` / `audio reuse` / `audio reference`。
- `retention_analysis` 用固定关系标记:可见内容 `fully_preserved` / `partially_preserved` / `attribute_transfer` / `weak_reference`;音频 `fully_copy` / `partially_copy` / `reference` / `weak_reference`。
- `detailed_description`:生成任务通常 350–500 英文词;风格在 `[Shot 1]` **之前**用一两句建立;`<Subject N> (Sx)` 组合写法表示"该参考主体在说话"。
- 完整 623 行规范见 `apps/desktop/src/main/builtin-skills/h3-prompt-writing.md`。

### 1.6 引擎/参数侧约束(h3.c + 本仓实测)

- **无负面提示词、无 CFG**:模型是 guidance-distilled(mlx-gen minimax-h3.md 明确 "there is no negative prompt and no guidance scale")。
- **参考视频带音轨 ⇒ 输出必须 ≥2 秒(≥56 帧 @24fps)**,否则 h3 报错(h3.c:1146 truncate 分支);绕法:`--ref-silent-video`(App 里勾「忽略参考视频音轨」)。防呆实现在 `packages/providers/src/h3c-command.ts` 的 `validateParams`。
- `layers ≤ 40 + reuse ≥ 3` 被拒绝(鬼影/振铃);`reuse ≥ 2 + steps < 8` 警告。
- Turbo 加速包 = 换蒸馏模型目录(`-d`)+ 4/8 步;h3.c CLI **不接受 `--lora`**。
- token 化:提示词按原样 tokenize,**无 chat template、无特殊 token包装**,可以写很长,详细的分镜头描述有帮助(mlx-gen minimax-h3.md)。

## 2. Z-Image-Turbo(文生图默认模型)

**身份核实**:Z-Image(造相)是**阿里通义 Tongyi-MAI 团队**的开源文生图模型(6B,单流 DiT,文本编码器为 Qwen3-4B),不是智谱。官方来源:github.com/Tongyi-MAI/Z-Image、HF `Tongyi-MAI/Z-Image-Turbo` model card、官方博客 tongyi-mai.github.io/Z-Image-blog、阿里云百炼 Z-Image API 文档。

### 2.1 提示词写法(官方)

- **中英双语均官方支持**(README 原文:"bilingual text rendering (English & Chinese)";博客:"robust adherence to bilingual instructions")。
- **官方示例全部是连贯的自然语言长段落**(150–400+ 词),覆盖主体/服饰/动作/背景/光照/构图,**没有分段标签、没有固定顺序模板**。
- 长度上限 800 字符(**仅阿里云 API 文档写明**;开源 diffusers 路径官方未给上限)。
- 官方有 **Prompt Enhancer / `prompt_extend`** 机制(模型侧推理链扩写短提示词)——官方立场是"短提示词交给增强器",而非要求用户手写固定公式。
- ⚠️ **「主体/场景/构图/光影/风格/约束」六段式在官方来源中完全不存在**,是社区实践(社区教程站传播)。本机的 `image-prompt-writer` 技能把它标注为 Z-Image 官方公式,归属不准确——六段式作为写作检查清单仍然实用(产出形态与官方示例兼容),但不要宣称出自官方。

### 2.2 采样参数(官方,Turbo)

- **`num_inference_steps=9`(diffusers 写法;实际 8 次 DiT forward)/ 原生 8 NFEs**。
- **`guidance_scale = 0.0`,官方注释原文:"Guidance should be 0 for the Turbo models"**。
- 分辨率 512×512 ~ 2048×2048 任意宽高比(推荐总像素 1024×1024 ~ 1536×1536 档)。
- Model Zoo 官方对照:Turbo = Step 8 / CFG ❌ / 多样性低 / 画质很高。

### 2.3 负面提示词(官方对照表)

- **Turbo ❌ 不支持**(guidance=0 时负面提示词不生效;阿里云 API 参数列表里没有 negative_prompt 字段)。
- 基础版 Z-Image ✅ 支持且官方"强烈推荐"(steps 28–50、guidance 3.0–5.0、cfg_normalization 风格化 False / 写实 True)——本 App 未部署基础版。
- 与引擎侧观测一致但**更严**:mlx-gen 文档说 "Z-Image Turbo has a negative prompt but no guidance",官方则直接标注 Turbo 不支持负面提示词。**App 侧结论:走 z-image-turbo 时固定 steps=8、不传负面提示词**。

### 2.4 官方示例摘录

英文(Turbo,README/model card/inference.py 同一条):

> "Young Chinese woman in red Hanfu, intricate embroidery. ... Soft-lit outdoor night background, silhouetted tiered pagoda (西安大雁塔), blurred colorful distant lights."

中文(基础版 model card):

> "两名年轻亚裔女性紧密站在一起,背景为朴素的灰色纹理墙面...休闲时尚摄影,中等景深,面部和上半身对焦清晰..."

官方示例特征(观察归纳):连贯段落、细节密度高(服饰/材质逐一点名)、结尾常带镜头与画质语、中英可混排。

## 3. Qwen-Image-2.1(文生图 / 参考编辑)

**身份核实**:官方确切名称 `Qwen/Qwen-Image-2.1`(GitHub `QwenLM/Qwen-Image-2.1`,2026-09-20 发布,Qwen Research License)。7B 单流 DiT(32 层)统一文生图+编辑模型:原生 RGBA、最多 10 张参考图、prefix KV cache、文本编码器为 Qwen3-VL 8B(带 vision tower——参考编辑用视觉塔编码参考图的官方出处)、64 通道 RGBA VAE。已核对本机 `~/ai/models/Qwen-Image-2.1-bf16/model_index.json` 就是该官方 checkpoint。注意区分:Qwen-Image-2512(20B 月度迭代)与 Qwen-Image-2.0(下一代)都不是它。

### 3.1 提示词写法(官方 + 引擎实测)

- 中英文原生双语;官方示例为长结构化自然语言;**指令编辑用直接、具体的祈使句**,替换用 `Replace Y with X` 句式;模糊指令要补最小细节(类别/颜色/位置)。
- **文字一律英文双引号包裹、保留原语言与大小写**。
- 多参考(≤10 张)时**必须指明 "picture 1 / picture 2" 的元素归属**;官方编辑示例:`Change the background to a sunset beach`;多参考示例:`These three characters are sitting around a campfire in a forest`。
- **RGBA 官方模板**:`This is an RGBA image with transparency. <描述>. The image has alpha channel and the background is transparent.`
- 参数(官方):steps=40(默认);原生 2K(1:1=2048²,16:9=2752×1536 等 7 档);Quick Start **不用** negative_prompt / true_cfg_scale(SGLang 示例 guidance=1)——与引擎侧「默认 40 步、默认无 guidance、negative 仅 guidance>1 生效」一致。
- 官方配套改写模型:T2I 用 `Qwen/Qwen-Image-2.1-PE-T2I`、编辑用 `Qwen/Qwen-Image-2.1-PE-I2I`(微调 Qwen3.5-VL 9B,输出 rewritten_prompt + wh_ratio)。**官方 NOTE:不做 prompt rewriting 的编辑会不稳定,强烈推荐改写**。

### 3.2 引擎侧已确认事实(mlx-gen `docs/qwen-image-21-editing.md`,2026-09 实测)

- 三条路由:`qwen21.text`(文生图,默认 40 步、默认无 guidance)/ `qwen21.latent`(latent img2img,`--image-strength`,整图重绘,**不是**指令编辑)/ `qwen21.edit`(指令参考编辑,1–10 张参考图,原生 RGBA)。
- 编辑必须用**全量 checkpoint**(text_encoder 须含 `visual.*` 张量);8bit 社区导出无 vision tower——本 App 已统一收敛到官方 bf16。
- 硬约束:输出必须 `.png/.webp/.tif/.tiff`(RGBA);scheduler 固定 linear Euler;`--negative-prompt` 仅在 `--guidance > 1` 时生效;参考图 ≤10 张。
- App 提交侧(`packages/providers/src/mlxgen.ts`):多参考必须显式 `--i2i-mode edit`,否则 CLI 会自动推成 multi-reference 撞校验。

## 4. Qwen-Image-Edit(指令编辑 / inpaint / outpaint 存量默认)

官方来源:github.com/QwenLM/Qwen-Image(README + prompt_utils.py + Qwen-Image-Edit-2509.md)、官方博客 qwenlm.github.io/blog/qwen-image-edit/。

### 4.1 指令写法(官方 Edit Prompt Enhancer 系统提示词)

- 指令要**直接、具体**;替换用 "Replace Y with X";模糊指令补最小细节。
- **文字一律英文双引号包裹、保留原语言与大小写**:"Replace "xx" to "yy""。
- 人物编辑强调保持 identity(种族/性别/年龄/发型/表情/服装),表情妆容修改必须自然克制。
- **官方固定模板**:上色修复 `Restore and colorize the photo.`;inpainting `Perform inpainting on this image. The original caption is: `;outpainting `Extend the image beyond its boundaries using outpainting…`。
- 多图(2509 起,1–3 张最佳)必须指明 "picture 1 / picture 2" 归属。
- 指令类别(官方博客):语义编辑(IP 创作/视角旋转/风格迁移)、外观编辑(增删改元素,其余区域不变)、精准文字编辑(保留字体字号)、链式编辑。

### 4.2 参数与负面提示词

- 官方参数:初版 Edit steps=50/cfg 4.0;**2509/2511 = steps 40 / true_cfg_scale 4.0 / guidance_scale 1.0**;不用负面时传 `" "`(单空格,官方原文 "Recommended if you don't use a negative prompt")。官方建议直接用 2509 代替初版。
- 负面提示词官方中文模板(2512 发布时给出,可复用):「低分辨率,低画质,肢体畸形,手指畸形,画面过饱和,蜡像感,人脸无细节,过度光滑,画面具有AI感。构图混乱。文字模糊,扭曲。」
- 引擎侧补充(mlx-gen api.md §Negative Prompts):`--guidance > 1` 时启用真 CFG;**不传 negative 时采用官方空负面提示词行为**(真 CFG 默认仍开);显式负面提示词用于挡具体失败模式:crop、blur、text、物体状态不变、不想要的颜色。

## 5. FLUX.2 Klein 9B(多参考默认 / 全能编辑)

官方来源:docs.bfl.ai prompting 指南(共 8 篇)、help.bfl.ai、github.com/black-forest-labs/flux2(README + `src/flux2/util.py` 官方默认参数)、HF `black-forest-labs/FLUX.2-klein-4B` model card。

### 5.1 提示词写法(BFL 官方 prompting guide)

- **叙事式自然语言,不要关键词堆砌**:「Write in prose, not keyword lists — describe scenes like a novelist」;提示词上限 32K tokens;长度建议:短 10–30 词(快速探索)、中 30–80 词(多数场景)、长 80–300+ 词(复杂多主体);「Start short. Add only what changes the image. More words do not automatically mean better results.」
- **词序重要**(属性绑定):主体写前面、环境细节放后面;光影描述对画质影响最大(像摄影师一样写光源/软硬/方向/色温/交互)。
- 官方辅助模板(非硬性公式):`[SUBJECT], [LOCATION], [STYLE], [CAMERA SETTINGS], [LIGHTING], [COLORS], [EFFECT], [ADDITIONAL ELEMENTS]`;结尾可加 `Style: [style]. Mood: [mood].` 保风格一致。
- **官方支持结构化 JSON 提示词**(与自然语言理解力相同,适合生产/自动化/多主体):schema 含 `scene / subjects[{description,position,action}] / style / color_palette / lighting / mood / background / composition / camera{angle,lens,depth_of_field}`。
- **文字渲染三步法**:确切文字放引号 → 描述位置 → 指定字体风格;文字要短;品牌色用 hex 且**绑定到具体对象**(`The logo text 'ACME' in color #FF5733`;模糊的 `"use #FF0000 somewhere"` 结果不稳)。
- **不支持负面提示词**(「Most FLUX models do not support negative prompts」);替代写法:`no people` → `empty / deserted / solitary` 等正面描述。
- **klein 无 prompt upsampling**(自动扩写只属于 API 的 pro/max/flex):「what you write is what you get — be descriptive」。

### 5.2 多参考编辑(官方)

- **明确每张图的角色**,用 "image 1"、"image 2" 指代:「describe the role of each image so the model knows what to pull from where」。官方示例:`A photograph of the woman in image 2 sitting on the swing in image 1 and the cat from image 3 sitting on her lap, all in the style of image 4`。
- 编辑通用原则:**具体说明改什么,显式说明保留什么**;避免 "Make it better" / "Fix the image" 这类空指令。
- 参考图上限:**klein(4B/9B)≤ 4 张**;pro/max/flex API ≤ 8。

### 5.3 采样参数(官方源码 `flux2/util.py`,最可靠)

| 变体 | steps | guidance | 说明 |
|---|---|---|---|
| klein 4B / 9B / 9B-KV(**蒸馏版**) | **4** | **1.0** | `fixed_params={guidance, num_steps}`,CLI 层强制不可调;「guidance and timestep distilled」 |
| klein Base(未蒸馏) | 50 | 4.0 | 面向微调/LoRA,可调 |
| FLUX.2 [dev] | 50 | 4.0 | guidance 嵌入式蒸馏 |

- README 原话:「Use **Distilled** (4-step) for production apps and real-time generation; Use **Base** (50-step) for fine-tuning, LoRA training」。
- 分辨率 64×64 ~ 4MP,**宽高须为 16 的倍数**(mlxgen 现有 32 倍数校验更严,兼容)。
- **9B KV 变体**:多参考编辑缓存参考图 KV,4 张 1024² 参考 + 512² 输出加速 2.66×。
- 许可:4B Apache 2.0 可商用;9B FLUX Non-Commercial。

### 5.4 引擎侧已确认事实(mlx-gen api.md)

- base / distilled 提示词行为不同:base 全路由接受负面提示词(需 `--guidance > 1.0`,默认 4.0);**distilled 无 guidance 分支,拒绝 `--negative-prompt`**——与官方"FLUX 不支持负面提示词"在蒸馏版上完全一致。
- Klein 是本 App 唯一实测支持**无上限多参考**的路由(`flux2.multi-reference`),第一张参考图锚定几何(注意官方上限 4 张,引擎侧无硬上限,>4 张属超官方验证范围)。
- outpaint 路由有官方推荐 LoRA:`fal/flux-2-klein-4B-outpaint-lora`(capability 行 `outpaint_recommended_lora`)。

### 5.5 对 App 的落地要点

- `flux.2-klein-9b-8bit`(蒸馏)应固定 **steps=4 / guidance=1.0**,与官方 CLI 一致。
- klein 无 upsampling ⇒ 提示词必须写全(叙事段落),或 Agent 层自建扩写(官方 dev 用本地 Mistral-Small 扩写,同理可用本机 LLM)。
- 多参考提示词用 "image 1/2/3" 指代并声明角色,与 `--i2i-mode multi-reference` 逐张 `--image` 的顺序对应。

## 7. 图片编辑模式通用规范(mlx-gen `docs/image-edit-modes.md`,引擎维护方实测结论)

适用于所有走 mlxgen 的编辑路由,写提示词前先选模式:

| 目标 | 最佳模式 | 预期 |
|---|---|---|
| 改整体氛围/风格/光影 | `latent-img2img` | 整图从源 latent 重新诠释;适合变体与重风格化,不适合精确物体编辑 |
| 按指令编辑且保持构图可辨识 | `edit-reference` | 源图作为 reference 保持参与,构图保持优于 latent img2img |
| 只改局部、其余像素级稳定 | masked edit / inpaint(`--mask-path`,白=重绘,黑=保留) | 掩码外像素硬锁定 |
| 边缘图/姿态图控制布局 | structured control(`--controlnet-image-path`) | 不是源图编辑 |
| 一张给结构、一张给风格/材质/光照 | `multi-reference` | **第一张锚定几何**,后续贡献其他参考 |
| 扩展画幅 | `generative reframe` / `outpaint` | 仍是生成式,可能重绘源图内容 |

**属性外溢对策(实测结论,重要)**:指令编辑会整图重生成,改领带颜色可能把西装也带跑。对策 = 在指令里**钉住要保留的属性**:"change the tie color to red, **keeping the suit exactly the same blue color and everything else unchanged**";要硬保证就用 masked editing。

**迭代编辑稳定性**:编辑输出直接作为下一步输入时,几何保持稳定(主题位置/比例不漂移);**中途把输出缩放到非 16 倍数的尺寸会引入重采样畸变**。

## 8. 主对话 LLM(Ornith 1.5 35B / 可换远端)与视觉模型(Qwen3-VL-8B caption)

这两个是**对话模型**,"提示词规范"不在用户侧写,而是由 App 的 system prompt / 工具协议承载:

- **主 LLM**:OpenAI 兼容 chat;Agent system prompt 由 `packages/agent/src/memory.ts` 组装(画布能力、技能指令段、压缩摘要等);工具参数容错(标题当 id、`data` 字符串化)已在工具层统一处理。写节点提示词一律用 `canvas.update_node` 的**顶层 `prompt` 字符串参数**(2026-09-28 事故结论,见 CLAUDE.md)。
- **视觉模型**(`vision.caption`):指令由 `buildCaptionInstruction` 按 style 组装 —— `prompt`(通用英文)/ `zimage`(六段式中文)/ `h3`(五段式)/ `json`;请求体固定 `temperature 0.2`、`max_tokens 700`(`apps/desktop/src/main/vision.ts`)。该模型是社区微调(Qwen3-VL-8B 的 caption 微调),**无官方提示词规范**,行为以 App 组装指令为准。
