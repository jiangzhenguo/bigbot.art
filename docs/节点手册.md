# BigBotArt 画布节点手册

> 范围:画布上 11 种 `NodeKind` 节点的能力、字段、连线、显示约定、画布双模式(资产/工作流)与 PRD 出处。
> 适用范围:`packages/shared/src/domain.ts`(`NodeKind` / `CanvasNode` / `NodeDataMap` / `CanvasSnapshot`)+ `apps/desktop/src/renderer/src/pages/CanvasPage.tsx`(节点库 `NODE_TYPES`、连线白名单 `COMPAT`、演示数据)+ 主进程运行层(`RunSnapshot` / `runs/<runId>/`)。
> 状态标签:**✅ 已实现** = 代码已落 + UI 可用;**🟡 部分实现** = 数据/UI 在但 Agent 桥接未完成;**🟠 PRD/设计承诺未实现** = 写明但当前骨架未做;**📝 设计稿占位** = 仅在渲染层演示数据里出现;**🆕 v2 设计新增** = 本次迭代引入。

> 🆕 **v2 设计变化(相对原 9 节点)**:
> 1. **画布双模式**:`CanvasSnapshot.mode: 'asset' | 'workflow'`。**资产模式是缺省**(自由整理素材),**工作流模式必须有一对 `workflow-input` + `workflow-output` 节点**(明确可执行 subgraph 的边界)。
> 2. **`NodeKind` 新增 2 种**:`workflow-input`(资源入口容器,声明工作流需要的输入)、`workflow-output`(资源出口,工作流终点)。
> 3. **运行实例化**:每次点"运行"生成独立 `RunSnapshot` + `runs/<runId>/` 目录,中间产物与最终产物分开归档。
> 4. **stale 联动自然落地**:工作流模式下,DAG 拓扑变更通过 `ui.stale` 传播 + "仅重跑受影响"按钮(对应 PRD §5.1.3)。

## 1. 总览

### 1.1 节点清单(11 种)

| kind | 中文名 | 引擎 / 角色 | 优先级 | 落地状态 |
|---|---|---|---|---|
| `document` | 提示词 / 文档 | — (Markdown) | P0 | ✅ 数据/UI |
| `asset` | 资产节点 | — (引用资产库) | P0 | 🟡 数据在、`asset` kind 未进入渲染端 NODE_TYPES |
| `image-gen` | 图片生成 | mlxgen / comfyui / mock | P0 | ✅ |
| `image-edit` | 图片编辑 | mlxgen / comfyui / mock | P0 | ✅ |
| `image-upscale` | 图片增强(超分) | mlxgen(SeedVR2) | P1 | 🟡 kind 在,Provider 已有 `upscale` 命令 |
| `shot` | 镜头(视频) | h3c / comfyui / mock | P0 | ✅ |
| `director` | 导演台 | 内部(占位) | P1 | 📝 设计稿占位,功能仅 `prompt` |
| `timeline` | 时间线 / 剪辑 | FFmpeg | P1 | 🟡 kind 在,导出逻辑未接 Provider |
| `audio-ref` | 音频参考 | — (h3.c `--ref-audio`) | P0 | ✅ 作为 `shot.refs[role=ref-audio]` 角色源 |
| `workflow-input` 🆕 | 工作流入口(资源容器) | — (声明工作流需要的输入) | P0 | 🆕 设计落定、代码未落 |
| `workflow-output` 🆕 | 工作流出口(产物汇聚) | — (工作流终点,运行收口) | P0 | 🆕 设计落定、代码未落 |

### 1.2 节点按"画布模式"再切

| 画布模式 | 可用节点 | 必须节点 | 是否可执行 |
|---|---|---|---|
| **资产模式**(`mode='asset'`,缺省) | 全部 11 种 | 无 | ❌ 不触发引擎,只整理素材 |
| **工作流模式**(`mode='workflow'`) | 全部 11 种 | **恰好 1 个 `workflow-input` + 1 个 `workflow-output`** | ✅ 点"运行"按拓扑序触发引擎 |

> 自动升级规则:画布上**首次**出现一对 `workflow-input` + `workflow-output` 时,自动提示"画布已可升级为工作流模式";用户手动确认后 `CanvasSnapshot.mode='workflow'`。
> 反向降级:删除任一入口/出口节点、或用户手动切回资产模式。

### 1.3 PRD 出处

- `PRD-BigBotArt-无限画布视频图片生成Agent.md` §5.1.2(L116-127)定义全部节点的"能力"与优先级。
- §5.1.1(L113)规定连线语义是"**输入 → 调用 → 输出**"。
- §5.1.3(L129-131)承诺"**下游节点标 stale + 仅重跑受影响**"——本次 v2 设计的工作流模式正是其落地形态。
- §5.2.1(L184-188)规定**文档节点是 Agent 规划的标准产物**(不是用户手写)。
- §5.4 资产双写 + §5.6 资产中心互为镜像,本次 v2 通过"资产模式 ↔ 工作流模式"显式区分"整理"和"执行"两种语义,补上 Agent 何时该把画布当模板、何时该真正跑一遍的歧义。

### 2.5 边(连线)

**领域定义**(`domain.ts:37-43`):
```ts
interface CanvasEdge {
  id: string;
  source: string;   // 起点节点 id
  target: string;   // 终点节点 id
  label?: string;   // 语义标签,如 ref-image / first-frame / input-brief
}
```

**渲染层**(`CanvasPage.tsx:32-38`):
```ts
type EdgeClass = '' | 'stale' | 'ghost';  // CSS 类,视觉区分过期/幽灵
interface Edge { from: string; to: string; cls: EdgeClass }
```

#### 连线白名单(`COMPAT`,`CanvasPage.tsx:97-105`)

展示层把上游 id → 允许的下游 id 列了白名单。**注:`COMPAT` 用的是渲染端 `NODE_TYPES.id`,不是 `NodeKind`**。

| 上游(展示 id) | 允许下游(展示 id) | 含义 |
|---|---|---|
| `brief` | `image`, `shot`, `doc`, `director` | 提示词文档 → 生成节点 |
| `storyboard` | `edit`, `upscale`, `shot`, `timeline` | 图片分镜 → 编辑/超分/镜头/时间线 |
| `audio` | `shot`, `timeline` | 音频 → 镜头带声 / 时间线音轨 |
| `shot1` / `shot2` / `shot3` | `shot`(续), `timeline`, `edit` | 镜头接续 / 入线 / 取帧编辑 |
| `timeline` | `doc` | 时间线 → 文档(回写脚本) |
| 🆕 `wf-input` | 任何操作节点 | 工作流入口槽位 → 注入到操作节点 data |
| 🆕 任何操作节点 | `wf-output` | 操作节点产物 → 工作流出口收口 |

> ⚠️ 演示用 `storyboard` / `shot1` / `shot2` / `shot3` 在 `NODE_TYPES` 里**没有对应条目**——它们来自设计稿 canvas.js 的演示节点,目前未与 `NodeKind` 严格对齐。

#### 边的语义标签(`CanvasEdge.label`)
领域层 `label` 字段约定"ref-image / first-frame / input-brief"三类,具体值映射到下游节点参数:

| `label` | 落到下游的字段 | 适用节点 |
|---|---|---|
| `input-brief` | `data.prompt` | `image-gen` / `shot` / `image-edit` |
| `first-frame` | `shot.refs[].role = 'first-frame'` | `shot` (mode = `first-frame`/`first-last`) |
| `last-frame` | `shot.refs[].role = 'last-frame'` | `shot` (mode = `last-frame`/`first-last`) |
| `ref-image` | `shot.refs[].role = 'ref-image'` | `shot` (mode = `ref-image`) |
| `ref-audio` | `shot.refs[].role = 'ref-audio'` | `shot` (--ref-audio,带声直出) |
| 🆕 `slot-<name>` | `workflow-input.slots[name].value` → 注入下游 `data.*` | `workflow-input` → 任何操作节点 |

> `image-edit` 的输入图/遮罩图也来自上游 `asset` 节点,边 `label` 暂未在 `COMPAT` 显式列举。

## 3. 各节点详细规格

### 3.1 `document` — 提示词 / 文档 ✅ P0

**功能**
- Markdown Brief 容器,承载 H3 五段式(Context-IR)或 Z-Image 六段式提示词。
- PRD §5.2.1 规定它是 **Agent 规划的标准输出**:用户口述需求 → Agent 生成 `document` + 分镜规划 + 执行计划。

**数据字段**(`NodeDataMap.document`):
```ts
{ markdown: string }   // 完整 Markdown 文本,可含五段式 / 六段式模板
```

**显示**
- 头部:`提示词 / 文档`(无角标)。
- 体:`MarkdownText` 组件渲染 `data.markdown`,支持代码块/列表。

**连线(展示层 COMPAT)**
- 作为下游:无(暂未列入 `COMPAT` 的下游接收方)。
- 作为上游:`brief → image/shot/doc/director`(`label=input-brief` 注入下游 prompt)。

**画布模式**
- 资产模式:✅ 可自由摆放。
- 工作流模式:✅ 允许(常作为"prompt 来源"出现在 input → document → image-gen 链中)。

**与生成节点的关系**
- `label=input-brief` 的边在 PRD 里承诺会把 markdown 提取/扩写注入下游 `image-gen.prompt` 或 `shot.prompt`。**当前骨架期未自动桥接**(Agent 内核尚未消费这种边)。

---

### 3.2 `asset` — 资产节点 🟡 P0

**功能**
- 镜像资产库条目:把已生成的图/视频/音频/参考图/文档挂到画布上,作为下游的 ref 源。
- PRD §5.4 规定"画布资产节点 ↔ 资产中心**双写**,删除一侧提示联动"。

**数据字段**(`NodeDataMap.asset`):
```ts
{
  assetId: string;                        // 资产库条目 id
  mediaType: 'image' | 'video' | 'audio' | 'document';
}
```

**显示**
- 渲染端 `NODE_TYPES` **没有 `asset` 条目**(演示用 `image`/`audio`/`doc` 各自代理了部分场景)。
- 设计稿里"图片 / 音频"卡片实际扮演 asset 节点角色。

**连线**
- 作为下游接收方:无显式 `COMPAT` 项,但所有需要"参考"的节点(shot.refs / image-edit.inputAssetId / image-edit.maskAssetId)都**逻辑上**接受 asset 上游。
- 作为上游:连到 `shot`(first-frame/last-frame/ref-image/ref-audio)、`image-edit`(inputAssetId/maskAssetId)、`timeline`(媒体源)、`workflow-input`(把素材塞进工作流入口槽位)。

**画布模式**
- 资产模式:✅ 主要节点之一(整理素材)。
- 工作流模式:✅ 允许(作为 `workflow-input` 槽位的填充源)。

**实现状态**
- `asset` 在 `NodeKind` 与 `NodeDataMap` 已存在,但**未在渲染端 `NODE_TYPES` 单独列出**;后续需要把"image/audio/document 类资产卡"统一收敛为 `kind=asset` + `mediaType` 字段。

### 3.3 `image-gen` — 图片生成 ✅ P0

**功能**
- Text→Image,默认引擎 `mlxgen`(`AbstractFramework/z-image-turbo-8bit` ~3GB),备选 `comfyui` / `mock`。
- 支持多 seed 批量出图(同 prompt 多张候选)。

**数据字段**(`ImageGenParams`,`domain.ts:135-145`):
```ts
{
  engine: 'mlxgen' | 'comfyui' | 'mock';
  model: string;          // e.g. 'AbstractFramework/z-image-turbo-8bit'
  prompt: string;         // 提示词,优先来自自身,也可由 document 边注入
  width: number;          // 出图宽
  height: number;         // 出图高
  steps?: number;         // 默认 24
  guidance?: number;      // 默认 1.0
  seeds: number[];        // 多 seed 批量,生成多张 PNG
}
```

**引擎映射**
| `engine` | Provider | 实际命令/路径 |
|---|---|---|
| `mlxgen` | `MlXGenProvider`(`packages/providers/src/mlxgen.ts`) | `mlxgen generate --model <m> --prompt <p> --width/height --steps --guidance --seed ... --output <png>` |
| `comfyui` | 待实现(PRD §5.3.3) | 导入 `workflow_api.json` |
| `mock` | `MockProvider`(`packages/providers/src/mock.ts`) | ffmpeg 生成占位图,永远真实跑 |

**显示**
- 头部:`图片生成`;副标:`mlxgen · Z-Image-Turbo`。
- 节点体:展示当前 `prompt` 截断预览、模型选择、宽高、seed 列表、产物缩略图。

**连线**
- 上游可接:`brief`(document),`asset`(作为参考 prompt 来源),`workflow-input`(槽位注入 prompt/seed)。
- 下游可接:`storyboard`(演示 id,在 PRD 中对应"图片分镜")→ 接 `edit` / `upscale` / `shot` / `timeline`、`workflow-output`。

**画布模式**
- 资产模式:✅(可执行但不触发运行)。
- 工作流模式:✅ 典型操作节点之一,拓扑序由 `workflow-input` 到 `workflow-output`。

**能力边界**
- mlxgen `capabilities.aspectRatios = ['1:1','16:9','9:16','4:3','3:4','2:3']`,宽高必须落在这个范围。
- 图片槽位与视频槽位互斥(64GB 内存策略)。
- 多 seed = 多产物,每张一个 PNG,产物命名带 seed。

### 3.4 `image-edit` — 图片编辑 ✅ P0

**功能**
- 4 种编辑模式:指令编辑(Qwen Edit) / I2I(latent) / Inpaint(遮罩) / Outpaint(扩图)。
- 引擎 `mlxgen`(`qwen-image-edit` / `flux.2-klein-9b`),备选 `comfyui` / `mock`。

**数据字段**(`ImageEditParams`,`domain.ts:148-160`):
```ts
{
  engine: 'mlxgen' | 'comfyui' | 'mock';
  model: string;
  prompt: string;         // 指令编辑的文字指令
  mode:
    | 'instruction'       // Qwen Edit 指令编辑
    | 'img2img'           // latent I2I
    | 'inpaint'           // 遮罩编辑(--mask-path)
    | 'outpaint';         // 扩图
  inputAssetId?: string;  // 输入图(必填,来自 asset 节点)
  maskAssetId?: string;   // 遮罩图(inpaint 必填)
  outpaintSides?: { top: number; bottom: number; left: number; right: number };
}
```

**引擎映射**
- mlxgen submit 时按 mode 分支:
  - `instruction` / `img2img` / `inpaint` / `outpaint` 都走 `mlxgen <mode> --image-path ... [--mask-path ...] --prompt ... --output ...`
  - `inpaint` 必须有 `maskAssetId` → 导出 mask 图 → `--mask-path`。

**显示**
- 头部:`图片编辑`;副标:`指令 / I2I / Inpaint / Outpaint`。
- 节点体:模式选择、模型、`inputAssetId` 引用、`maskAssetId` 引用(inpaint 时显示遮罩缩略图)。

**连线**
- 上游:`asset`(输入图,`label` 暂未约束)、`asset`(遮罩图,inpaint)、`workflow-input`(槽位注入输入图/遮罩)。
- 下游:`upscale`(进一步修复)、`shot`(取编辑结果作首/尾帧)、`timeline`(入线)、`workflow-output`。

**画布模式**
- 资产模式:✅。
- 工作流模式:✅ 典型操作节点。

**能力边界**
- mlxgen `editModes = ['instruction', 'img2img', 'inpaint', 'outpaint']`,与 `mode` 字段一一对应。
- `flux.2-klein-9b` 支持 multi-ref / outpaint;`qwen-image-edit` 强项是 mask 区域编辑。

### 3.5 `image-upscale` — 图片增强(超分) 🟡 P1

**功能**
- SeedVR2 / SwiftVR 超分修复。视频超分待 P2。
- 引擎 `mlxgen`(`AbstractFramework/seedvr2-3b-8bit`)。

**数据字段**(`NodeDataMap['image-upscale']`):
```ts
{
  model: string;          // 默认 'AbstractFramework/seedvr2-3b-8bit'
  scale: number;          // 放大倍数,如 2 / 4
}
```

**引擎映射**

## 4. 画布运行模式(🆕 v2 核心)

### 4.1 模式字段

`CanvasSnapshot.mode: 'asset' | 'workflow'`,**缺省 `'asset'`**。

| 维度 | 资产模式 | 工作流模式 |
|---|---|---|
| 触发引擎 | ❌ | ✅ |
| 必须节点 | 无 | `workflow-input` × 1 + `workflow-output` × 1 |
| 节点库"+"弹层 | 显示所有节点 | 显示所有节点,但 input/output 是**必选**(其他全部可选) |
| "运行"按钮 | 灰显 / 隐藏 | 高亮可用,点 → 生成 `RunSnapshot` |
| 中间产物归档 | 不写盘 | 落到 `runs/<runId>/artifacts/` |
| 最终产物 | 不写盘 | 落到 `runs/<runId>/final/` |
| Agent 角色 | 把画布当**模板 / 草稿**对待 | 把画布当**可执行 subgraph**对待 |

### 4.2 模式切换规则

- **缺省**:新建画布一律 `mode='asset'`。
- **自动升级**:画布上首次同时出现 1 个 `workflow-input` + 1 个 `workflow-output`,弹提示"检测到工作流入口/出口,是否升级为工作流模式?",用户确认后置 `mode='workflow'`。
- **手动切换**:CanvasPage 顶部加一个 mode 切换 chip(`资产模式 ▾` ⇄ `工作流模式 ▾`),切换时跑一次 `validateWorkflow()`:
  - 切到工作流模式:必须已有 input/output 各 1,否则报错"需要先添加入口/出口节点"。
  - 切回资产模式:无校验,但 `RunSnapshot` 历史保留(可在时间线回看历史运行)。
- **节点校验**:每次 save canvas 时,`validateWorkflow(canvas)` 跑一次:
  - 工作流模式下,input/output 数量 ≠ 1 → 警告但允许保存(运行按钮禁用)。
  - 操作节点(input/output 之外的节点)位于 input 之前或 output 之后 → 警告。
  - 工作流模式下,删除了 input/output 之一 → 自动降级为资产模式(用户确认)。

```ts
    /** render job id(对应 RenderJob) */
    jobId?: string;
    error?: string;
  }>;
  /** 最终产物路径(相对 run dir) */
  outputs: Array<{ name: string; path: string }>;
  /** 与 CanvasSnapshot 的版本号(防止 canvas 改了之后 RunSnapshot 与画布对不上) */
  canvasVersion: number;
}
```

### 5.2 落盘目录规范

```
$BIGBOTART_HOME/
  runs/
    <runId>/
      manifest.json                # RunSnapshot(整份)
      inputs.json                  # 输入快照(冗余,便于单独查)
      artifacts/
        <nodeId>_<step>.png        # 中间产物,每个操作节点一份
        <nodeId>_<step>.mp4
      final/
        <outputName>.<ext>         # 最终产物
      logs/
        <nodeId>.stderr.log        # 引擎 stderr,失败时排查
        <nodeId>.stdout.log
```

### 5.3 与现有机制的关系

| 现有 | v2 怎么用 |
|---|---|
| `CanvasSnapshot`(JSON) | **画布 = 模板 / 工作流定义**;v2 加 `mode` 字段 |
| `Asset`(资产库) | `workflow-input.slots[].value.kind='asset'` 直接引用;不复制文件 |
| `Take`(生成历史) | v2 的 `RunSnapshot.steps[].artifactPath` 仍走 Take 链路归档 |
| `RenderQueue`(`apps/desktop/src/main/render-queue.ts`) | 工作流模式下,"运行"按钮 → 按 `RunSnapshot.steps` 拓扑序依次 `submit(req)`,中间产物的路径作为下一节点的 `references[].localPath` 注入 |
| `ExportService`(`apps/desktop/src/main/export.ts`) | `workflow-output.outputs[].kind='video'` 且需 FFmpeg 合成时,复用现有 `ExportService.submit`(把 runs/<runId>/artifacts/ 下相关节点产物喂给 concat demuxer) |
| `Skill`(`domain.ts:268-279`) | **未来方向**:工作流画布可"另存为 Skill",把 `CanvasSnapshot`(包括 input/output 节点的 slots/outputs 定义)当作 Skill 的模板 |

### 5.4 与"stale 联动"的关系

- `CanvasSnapshot` 上节点的 `ui.stale`:画布 DAG 拓扑传播,**与运行无关**。
- `RunSnapshot.steps[].status`:某次具体运行的历史,**与画布无关**。
- 工作流模式下,改上游节点 → 下游 `ui.stale=true` → "运行"按钮变 "🔁 仅重跑受影响",点 → 只重跑 stale 的下游节点,**复用 RunSnapshot 旧的输入快照**。

### 9.1 🆕 `slot-<name>` 注入规则

`workflow-input` → 操作节点 的边 `label` 形如 `slot-<name>`,其中 `<name>` 必须等于源节点的 `slots[].name`:

| 下游节点 | 注入字段 | 匹配规则 |
|---|---|---|
| `image-gen` / `image-edit` | `data.prompt` | `slot.kind === 'inline-text'` |
| `image-gen` | `data.seeds` | `slot.kind === 'inline-text'`(解析成数字) |
| `shot` | `data.prompt` | `slot.kind === 'inline-text'` |
| `shot` | `data.refs[]`(追加) | `slot.kind === 'asset'` 且 slot.name 含 `frame` / `ref` 关键字;否则按拓扑位置就近绑定 |
| `shot` | `data.refs[role='ref-audio']` | `slot.kind === 'asset'` 且 accept 包含 `audio` |
| `image-edit` | `data.inputAssetId` | `slot.kind === 'asset'` 且 accept 包含 `image`(取第一个) |
| `image-edit` | `data.maskAssetId` | `slot.kind === 'asset'` 且 accept 包含 `image`(取第二个,顺序约定) |
| `image-upscale` | `data.inputPath`(运行时注入) | `slot.kind === 'asset'` 且 accept 包含 `image` |
| `timeline` | `data.shotNodeIds`(追加) | `slot.kind === 'asset'` 且 kind=video,或上游是 shot 节点 |
| `document` | `data.markdown` | `slot.kind === 'inline-text'` |
| `workflow-output` | `outputs[].sourceNodeIds`(追加) | 不需要 `slot-<name>`,普通连线即可 |

> 桥接由主进程的 `resolveRunInputs(canvas, runInputSnapshot)` 完成,**v2 新增函数**,返回每个操作节点最终的 `params`。
