## 1. 背景与目标

完善"资源节点"与"资源管理"两条线，对应四个需求：

1. **资源节点（视频/图片/音频）不可自变**——只作为别的节点的输入，或经"产物归档"成为最终可交付资源。
2. **每个项目有自己的资源管理页面**，画布页面有入口。
3. **项目资源管理页可新建分类**（人物、场景、物品等），分类是用户可定义数据。
4. **资源可打标签**；总资源库可添加资源，并支持按分类/标签查询。

已确认的决策（用户拍板 + 设计稿评审）：

- **资源库模型 = 单库多视图**：`Asset` 增加 `projectId?` 字段，全局一张 `assets.json`；项目资源页 = 按 `projectId` 过滤的视图；"总资源库" = 全部资源合集。
- **"资源作为最后输出" = 产物入库**：生成产物可批量/单点归档为资源；`asset` 节点始终保持"只读输入源"语义。
- **画布双模式（资产/工作流）本轮不做**：设计稿的"资产模式（不触发引擎）/ 工作流模式（可运行）"记录为后续阶段（§11），本轮只做资源管理闭环 + 连接器修复 + 节点级只读约束。
- **`audio-ref` 节点与 asset(audio) 两套并存**：保留两个独立节点类型，各自维护连线语义（不合并）。
- 落地方式：先定稿，评审后再动代码。

## 3. 数据模型设计

### 3.1 `Asset` 扩展（`packages/shared/src/domain.ts`）

```ts
export interface Asset {
  id: string;
  kind: 'image' | 'video' | 'audio' | 'document';
  name: string;
  localPath: string;
  mime?: string;
  width?: number;
  height?: number;
  durationSec?: number;
  /** 归属项目;缺省 = 总资源库(全局共享) */
  projectId?: string;
  /** 分类 id;缺省 = 未分类 */
  categoryId?: string;
  /** 入库来源:手动导入 / 对话附件 / 画布产物归档 */
  source?: 'import' | 'attachment' | 'product';
  /** 来源节点 id(仅 source='product' 时,用于反查画布引用与定位) */
  originNodeId?: string;
  tags: string[];
  createdAt: string;
}
```

要点：

- `projectId` 缺省即"总资源库"资源（全局共享）；非空即"项目资源"。
- 画布 asset 节点沿用 `{ assetId, mediaType }`，**不存储 cat/bind/缩略图/路径**——这些从 Asset 实时派生（设计稿演示数据把 `cat/bind/path` 存进节点是双写，实现时以 `assetId` 引用为准，改分类/重命名后画布自动跟新，即"随源资产更新"）。`mediaType` 与资产实际 `kind` 绑定校验：空资产时可选类型，绑定后锁定（"不可自变"）。

### 3.2 新增 `AssetCategory`

```ts
export interface AssetCategory {
  id: string;
  name: string;
  /** 分类归属:项目分类带 projectId;全局分类缺省(总资源库「新建分类」= 全局分类) */
  projectId?: string;
  createdAt: string;
}
```

- 单一挂载（一个资源一个分类或未分类），与标签（多值）正交。
- 删除分类：分类下有资源时**不硬删**——资源转"未分类"，原文件保留，二次确认。

### 3.3 标签

- 维持 `tags: string[]` 自由多值，**不设强制词表**。
- 详情面板标签编辑器：输入**回车或逗号**添加；输入时按**全库 tags 频次**给联想候选（点选或"新建「xxx」"）。
- 点击标签 = 筛选轴（选中后筛选条出现标签 chips，可逐个 × 移除或清除全部）。

### 3.4 `assets.json` 持久化结构（V2）

```jsonc
{
  "version": 2,
  "assets": [ /* Asset[] */ ],
  "categories": [ /* AssetCategory[] */ ]
}
```

- 迁移：读旧 `assets.json`（数组）时包一层为 V2，兼容见 §10。

## 4. 连线语义（资源节点的输入能力）

### 4.1 端口矩阵（按 mediaType 细分，本轮实现）

`asset` 作为源，目标按其**实际媒体类型**动态判定：

| asset.mediaType | → shot | → image-gen | → image-edit | → image-upscale | → timeline | → workflow-input |
|---|---|---|---|---|---|---|
| image | `ref-image`（Ref2VA）或 `first-frame`（首帧候选） | `ref-image` | `input` | `input`（**补**） | `clip`（静帧入轨） | `slot-<名称>` |
| video | `ref-video`（**补**：参考视频） | — | `input`（取帧源，落 `inputFrameSource`） | — | `clip`（**补**：素材入轨） | `slot-<名称>` |
| audio | `ref-audio` | — | — | — | `audio-track` | `slot-<名称>` |
| document | `prompt`（**修正**：文档注入） | `prompt`（**修正**） | — | — | — | `slot-<名称>`（文本槽位） |

现状问题与修正对应：

1. **video 与 audio 共用表（`connectors.ts:145-150`）→ 拆开**：video 资产现在会被连成 `ref-audio`，语义错误。
2. **document 资产落入 image 分支 → 独立处理**：`mediaTypeOf` 默认 `image`（`connectors.ts:133`），document 资产会被当参考图。
3. 补 `image → upscale(input)`、`video → timeline(clip)`、`video → shot(ref-video)`。

实现改造点：

- `apps/desktop/src/renderer/src/pages/canvas/connectors.ts`：`resolvePort` 的 asset 分支改为四行媒体类型矩阵。
- `packages/shared/src/connector-map.ts`：`CONNECTOR_MAP` 补 asset 条目（与渲染层同构），修复 `connectorSummary` 的 `outRows` 含 asset 但映射表无 asset 的不一致（Agent 认知）。
- **`audio-ref` 节点两套并存**：asset(audio) 落 `ref-audio` 端口；`audio-ref` 节点保留独立端口规则（`shot: ref-audio` / `timeline: audio-track`），节点库两边都保留，各自维护。

### 4.2 资源节点的只读约束（本轮，节点级）

- 无输入端口（保持现状：asset 不做任何 `BY_KIND` 的**目标**角色，即没有任何边能指向 asset 节点——它只能作为源）。
- 绑定后 `mediaType` 锁定（见 §3.1）。
- 画布内 asset 节点唯一可改的操作 = **换绑资产**（右键「更换资产…」，见 §6）；换绑后下游引用同步更新。
- 画布双模式（资产模式不触发引擎）留待 §11，本轮用"asset 节点自身不发起运行"的节点级约束兜底。

## 5. 页面信息架构与导航

```
画布(canvas) ──顶栏「资源」按钮(带计数)──→ 项目资源页(project-assets)
项目资源页 ──「打开总资源库 →」──→ 总资源库(assets)
总资源库 ──「项目资源」视图段切换──→ （跳转 project-assets?projectId=…，设计稿 L1378 策略）
```

- **画布入口**：Toolbar 新增「资源」按钮（`data-od-id="toolbar-assets"`，图标 + 项目资源计数）→ 进入**当前项目**的资源页（带 projectId）。
- 项目资源页（project-assets）：上下文 = 当前项目，**无视图切换**；顶栏有"打开总资源库 →"链接 + 返回画布。
- 总资源库（assets）：跨项目聚合，视图分段（项目资源 26 / 总资源库 128）+ 项目过滤条（全部各项目/全局）；在总视图点"新建分类"= 创建**全局分类**（`projectId:null`）。
- 状态保持：URL 参数 `?projectId=&cat=&mtype=&tags=&q=`（React 实现用 state + URLSearchParams 同步，刷新不丢筛选）。
- 返回逻辑：设计稿 `goBack()`：项目资源页 → 画布；总资源库 → 首页。React 内用 onNavigate 对等实现。

## 6. 资源管理页设计（对齐设计稿）

### 6.1 项目资源页（project-assets）布局

```
┌ 项目头:返回画布 | 项目名 | 「项目资源 · 仅本项目」| 打开总资源库 →
│ 统计:资源总数 | 分类 | 画布引用 | 产物归档 | 未分类
├ 顶栏:crumbs 资源管理 | [从画布产物导入 N 待归档] [导入] | 搜索
├ 筛选:分类 chips(项目分类·仅本项目可见 + 未分类 + ＋新建分类)
│       媒体 chips(全部/图片/视频/音频/文档)
│       标签 chips(选中后出现, ×移除/清除)
├ 网格:按分类分组(sect-h + agrid) · 卡片可拖拽(draggable)
└ 详情面板:预览(视频带播放键) | 分类 select | 标签编辑器 | 属性(类型/尺寸/归属/来源/来源节点/创建) | 绑定与引用(仅本项目) | 完整参数(可复现) | [在画布使用][定位画布] [移到回收站]
```

- 卡片角标：媒体类型 / `产物`(source=product) / `附件`(source=attachment) / 时长 / 项目归属（总视图下）。
- 卡片菜单：在画布打开… / 归档到总资源库 / 重命名 / 移到回收站…（危险项分隔）。
- 空态：本项目还没有资源 → 导入资产；未分类分组存在时显示"没有归入任何分类的资源"。
- 拖拽：卡片拖到画布生成 asset 节点（`draggable` + drop 处理）。

### 6.2 总资源库（assets）差异点

- 头部：视图分段（项目资源 / 总资源库）+ 统计（资源总数/涉及项目/全局分类/产物归档/回收站）。
- 筛选增加项目轴（仅总视图）：全部 / 各项目 pill / 全局。
- 分类 chips 带归属 hint：`N 个全局分类` / `项目分类 · 仅本项目可见`。
- 卡片菜单"归档到"反向：项目视图下 = 归档到总资源库；总视图下 = 归档到当前项目（归属迁移）。
- 详情"归属"行：`projectId` 有值显示项目名，缺省显示"总资源库 · 全局"。

### 6.3 分类 CRUD

- 建：筛选条「＋ 新建分类」输入（maxlength 14），总视图下创建全局分类。
- 重命名/删除：分类 chips 右键或按钮菜单；删除前若分类下 N 个资源 → confirm「删除后转未分类，原资源文件保留」。

### 6.4 产物归档（从画布产物导入弹层）

- 触发：顶栏「从画布产物导入」（badge = 待归档数）。项目资源页对当前项目；总资源库弹层也归档为**项目资源**（设计稿 L1309）。
- 弹层：勾选画布中有产物的节点（缩略图 + meta + 「可归档」badge）+「归档到」目标分类 select → `归档 N 个产物`。
- 归档结果：`source='product'`、`projectId` = 当前项目、`originNodeId` = 源节点 id；toast 后跳到目标分类。
- 卡片菜单"归档到总库/当前项目"= 归属迁移（`projectId` 置空/置值）。
- 实现：主进程需要「列项目画布有产物节点（含产物 meta）」能力（遍历 CanvasSnapshot 节点 `data.resultPath`）+ 归档动作（复制/引用产物文件入库 + 登记 Asset）。

### 6.5 引用检查与软删除（回收站）

- **删除前引用检查**：主进程按 assetId 遍历项目画布（asset 节点 data.assetId、shot/image-edit/upscale 等节点的引用字段）计算引用列表。
- 被引用 → 详情面板红条警告：`此资源被 N 处画布节点引用 · 文件将进入回收站（7 天后清理），引用节点会标记为「资产已移除」`。
- **软删除**：文件移入 `<DATA_DIR>/trash/`，assets.json 标记 `deletedAt`；页面出现回收站 banner（撤销 / 查看回收站 / 清理）。
- 回收站为**资产库级**（全局一张表，两个页面共享视图），7 天后自动清理或手动清空。
- 项目删除不级联删资源文件（红线 R5），仅提示或解绑归属。
