## 0. 核心结论速览

1. **「分镜板直接生视频」不存在。** 逐个核对 Sora / Vidu / 可灵 / 即梦(Seedance) / 海螺 / Pika / Runway / Veo 的输入契约后:没有任何主流模型的公开 API 原生接受「一张多格分镜板」或「一张带时间轴的分镜表」。所有叫 storyboard 的能力都落在三类里:**r2v 参考图**、**首尾帧**、**编排层 UI**。分镜表的价值 100% 在编排层——它决定调几次、每次喂什么图、按什么顺序拼。
   (来源:[ArcReel 行业调研,2026-08-03](https://github.com/ArcReel/ArcReel/blob/main/docs/research/storyboard-to-video-industry-survey.md)【一手代码/文档】)

2. **「电影感」不是形容词,是字段。** 三个高星实现([shuohao-skills](https://github.com/eternityspring/shuohao-skills) 5.6k、[drama-skills](https://github.com/zenstory-ai/drama-skills) 3.4k、[visual-skills](https://github.com/smixs/visual-skills))殊途同归:**把景别、水平角度、机位高度、焦段意图、构图、视线、焦点、稳定性、光位、声音分层拆成受控词表的独立字段**,再由程序按目标模型的语法拼成提示词。堆 `cinematic, 8k, masterpiece` 是明确被禁的写法。

3. **本仓改造前处在「必然产出大白话」的位置。** `STORYBOARD_HEAD` 只有「景别」「运镜」两列涉及摄影;`assembleH3Prompt` 的默认 look 曾是 `电影感，自然光影，写实`,且 `Camera: ${size} · ${move}` 把景别与运镜压成一行;`[Shot 1]` 恒为单镜。**根因不是模型笨,是表里没有摄影字段可填。**(见 §7;形容词兜底已在第 1 步移除)

4. **最大的结构性差距是「段」与「切」不分。** 业界通行模型是 `段(一次生成,≤15s) → 切(2–5s,一次剪切)`;我们是一行 = 一个 shot 节点 = 一次生成。于是「12 秒 3 个切」被迫拆成 3 次独立生成再硬拼,节奏与连续性必然散——而 H3 本身支持单次多镜(`[Shot k]` + 切点时刻),我们的 Ref2VA 骨架已经写了一半。

5. **不同类型的分镜差异,本质是两套正交维度**:①内容形态(短剧/TVC/MV/科普/电商/游戏 CG)决定**列集合 + 镜头语法 + 节奏 + 验收门**;②生产约束(单次生成上限/参考图槽位/是否原生音频/能否多镜单次)决定**段怎么切**。给技能硬编码表格是错的,应做成 `profile` 数据。

6. **付费产品卖的是「选择」不是「措辞」**:LTX Studio 的 Element + camera-control LoRA、Runway Multi-Shot 的「3–5 镜 × 每镜 prompt+duration」、Higgsfield DoP 的 preset 即运镜蓝图、即梦的 3D 导演台。共同点:把摄影决策降维成下拉选项和参数字段。

## 2. 业界事实:分镜不是模型能力,是编排层

### 2.1 三种范式(可核对的输入契约)

| 范式 | 输入契约 | 输出 | 代表(一手/半一手来源) |
|---|---|---|---|
| **r2v 参考生视频** | 1–9 张角色/场景/道具图,**不对应具体镜头或时间段** | 一条连续视频 | Vidu `reference2video`(1–7 张);可灵参考生视频(≤7);Seedance 2.0(0–9 图 + 0–3 视频 + 0–3 音频);MiniMax `reference_image`(≤9,与首尾帧互斥) |
| **首尾帧** | 恰好 2 张,有明确起止语义 | 一条连续视频(插值) | 可灵首尾帧;Veo 3.1 `image`+`lastFrame`;海螺 `first_frame`/`last_frame`;即梦首尾帧 |
| **编排层 storyboard** | 用户/agent 按镜组织 → 系统逐镜调用底层能力 + 拼接/转场 | 多段拼接 | Sora storyboard 编辑器(多 caption 卡片 → 对外呈现「single multi-shot clip」)、Runway Multi-Shot Recipe、Google Flow Scenebuilder、即梦「故事创作」 |

### 2.2 术语辨析(为什么这个词容易骗人)

「分镜板生视频 / storyboard-to-video」**没有跨厂商一致的技术含义**,实际所指随产品分裂为:①Sora 式的「卡片按时间编排、模型输出一条多镜片段」;②即梦式的「文本拆分镜脚本 → 逐格生图 → 逐格转视频 → 拼接转场」;③Runway 式的「给 3–5 镜列表,编排层组装」;④Flow 式的「把已生成的独立镜头在时间轴组装」;⑤Pika 式**纯营销借用**(实际是单镜多图参考)。

**唯一贴近字面意思的实践**是社区工作流:强生图模型一次出 3×3 九宫格保画风一致 → 切格 → 逐格 i2v(见 §3 ArcReel 的宫格建模)。它仍是「分镜图的生产方式优化」,没有改变喂给视频模型的输入契约。

### 2.3 对本仓的三条直接推论

1. 分镜表**必须**由我们自己的代码翻译成模型提示词,不能指望模型读懂表。
2. 「一段多切」要靠模型支持的多镜语法(H3 的 `[Shot k]` + `At 00:03.000`)或靠首尾帧接续,没有第三条路。
3. 一致性只有三种抓手:参考图槽位、首尾帧、单次多镜。分镜表要显式记录「这一段用哪种」。

### 3.1 最有参考价值的 schema:`storyboard.json`

来源:[shuohao-skills / novel-storyboard](https://github.com/eternityspring/shuohao-skills)【一手代码】

```
集(episode)
└─ 段(segment) = 一次视频生成调用,Σ切 ≤ 15s(默认),不跨场次——换景必开新段
   ├─ blocking     谁在画面左/右、面朝哪、相距几厘米(一段一份,空间地基,必填)
   ├─ soundscape   环境声/动作声/非语言人声(不复述台词)
   ├─ music        配器 + 速度(没有就省略)
   ├─ h3Prompt     一段一条提示词(正文语言跟 promptLang,默认 en)
   └─ 切(cut) = 段内一次剪切,2–5s
      ├─ beats          认领剧本第几拍到第几拍;每个节拍必须被「恰好一个」切认领,按序连续
      ├─ seconds        2–5s(短剧注意力节奏是硬门;认领台词的秒数必须装得下)
      ├─ size           extreme-wide / wide / medium / close / extreme-close
      ├─ camera         H3 官方词表:Static Shot / Push In / Pull Out / Zoom / Pan /
      │                 Truck / Tilt / Pedestal / Arc / Tracking / Shake / POV / Roll
      ├─ lens           焦距 + 景深:`50mm 标准,中浅景深` / `85mm 长焦,极浅景深`
      ├─ cameraPosition 对着谁 + 什么角度:`李四 + 平视正面` / `双人 + 俯视 30°`
      ├─ composition    三分法 / 中心构图 / 对角线 / 对称(一镜一个)
      ├─ eyeline        视线落点:对方面部 / 手中之物 / 闭眼
      ├─ focus          焦点锁什么(常与视线不同:眼睛看对方,焦点在手里的刀)
      ├─ stability      stable / slight-shake / handheld(与运镜正交)
      ├─ frame          分镜图提示词(中文;可直呼角色名——它指挂上去的参考图)
      ├─ shot           镜头正文(不写角色名,用通用身份;不写秒数/编号/画风)
      ├─ sfx / lighting 本镜特有音效 / 光影(场景级之外的)
      └─ recipe         镜头配方卡 id(可选)
```

四道**确定性门**(纯函数校验,不靠模型自觉):

| 门 | 规则 |
|---|---|
| `composition` 门 | 六字段(`lens`/`cameraPosition`/`composition`/`eyeline`/`focus`/`stability`)**每镜必填** |
| `shot-recipe` 门 | 挂了配方卡就查三条:id 在卡库、卡片的 `must_phrases` 真出现在 `frame` 里、`cuts` 下限满足 |
| H3 提示词门 | 首行对齐指令由分镜秒数**推导**;每个 `[Shot k]`(k≥2)**必须带 `At 00:0X.XXX,` 且等于前面秒数累计**;台词逐字进 `<d>[Chinese]…</d>`;运镜词必须落在自己那一行 |
| 时长链门 | 台词实测秒 ≤ 镜长 ≤ 5s;Σ切 ≤ 15s;Σ段 = 目标时长 ±15% |

它还有两条反直觉的纪律,值得单独抄:

- **正文禁止写画风**。原话:「『电影感』『冷灰绿色调』『半写实』这类是渲染层的事,由调用方在出图/出片时统一附加;写进正文只会跟当时选的画风打架。」
- **构图必须量化,不能只写景别**。原话:「分镜图一直在悄悄替正文干一件事:说清多近、多满、谁在哪、眼睛看哪。纯参考图出片时没有那张图,这些信息要么写成字,要么就地消失——实测消失的正是它们:景别偏远、动作偏小、人物摆位随意。」

### 3.2 另一条同样重要的纪律:一镜一职责 + 观众何时知道

来源:[drama-skills](https://github.com/zenstory-ai/drama-skills)【一手代码】

每镜记录:`purpose`(本镜为何存在)、`information_change`(信息从哪个块到哪个块)、`audience_visibility[{fact, permission: show_now|withhold, carrier, reveal_trigger, protection_method, rationale}]`、`start_boundary`/`end_boundary`(position/facing/gaze/hands/held_props)。

配套 `coverage.json` 逐块对账:`{block_id, status: covered|intentionally_omitted, reason, shot_refs[]}` —— 剧本每个 block 要么被覆盖,要么写明为什么故意不拍。**这条能直接消灭「漏拍一场戏却没人发现」**。

它的镜头叙事学还给了一条量化经验,对我们的竖屏场景尤其重要:

> **9:16 里高度变化比横屏更贵。** 竖屏画面纵向本就长,俯仰会迅速吃掉人物可用高度,同样俯角读起来比横屏强得多。要靠角度表达权力时,先看水平角度和距离能不能承担,再动高度。

| **Google Flow** | **Scenebuilder**,官方称「your in-Flow storyboard」 | 把**分别生成**的镜头在时间轴组装;Ingredients to Video 每次最多 3 张参考图 | 【一手产品】(经 ArcReel 调研转述) |

## 5. 「电影感」的字段体系

### 5.1 三件常被写成一个的事(最贵的错误)

drama-skills 的原话最能说明代价:

> 写「俯拍」时其实想要的是「从她背后越过肩膀」(那是**水平角度**,不是高度),下游按字面给了一个从上往下的机位,**权力关系当场反了**。

| 维度 | 受控词表 | 回答什么问题 | 记在哪 |
|---|---|---|---|
| **景别** | 大远景 / 远景 / 全景 / 中景 / 中近景 / 近景 / 特写 / 大特写 | 主体占多大 | 镜 |
| **水平角度** | 正面 / 斜侧(3/4) / 正侧 / 后斜侧 / 背面 | 允许读到多少表情、站谁一边 | 镜(需注明在轴线哪侧) |
| **机位高度** | 地平 / 低(仰) / 平视 / 高(俯) / 顶视 | 谁在这一刻大于谁;**平视是主动的势均力敌,不是「没选」** | 镜 |
| **焦段意图** | 广(空间关系优先)/ 标准(接近肉眼)/ 长(压缩纵深、隔离主体) | 两人距离显得更远还是更近 | **帧级**(属关键帧,不写 mm——那是替导演做器材决定) |
| **运镜** | 固定 / 推 / 拉 / 摇 / 移 / 升降 / 跟 / 弧 / 手持 / 甩 | 注意力怎么变;**一镜一个,不叠加** | 镜 |
| **运动理由** | 一句话回答「这里什么变了」 | 没有理由就不该有运镜 | 镜 |
| **构图** | 三分法 / 中心 / 对角线 / 对称 / 负空间 / 前景遮挡 | 视线放哪 | 帧 |
| **视线落点** | 对方面部 / 手中之物 / 闭眼 | 表演的一半 | 帧 |
| **焦点** | 锁定什么(常与视线不同) | 强迫观众看什么 | 帧 |
| **稳定性** | 稳定 / 微晃 / 手持 | 与运镜正交(固定机位也能微晃) | 帧 |
| **光** | 光位 + 光比 + 冷暖对撞 + 具体光源 | 情绪与空间 | 帧(**不写色调名**) |
| **声音三层** | 台词/剧内音乐 → 正文;环境声/动作声 → 声景;配乐 → 配乐轨 | — | 切 / 段 |

三条**互不推导**的警告(同理适用):

- 仰拍 ≠ 正面。从背后仰拍是「我们跟在他身后而他正在变大」,从正面仰拍是「他正压向我们」。
- 长焦 ≠ 特写。长焦拍全景会把纵深压平,让两个人看起来贴在一起——可能是要的,也可能把「隔着半个房间对峙」拍成了「面对面」。
- 焦段写**意图**不写参数。写 `85mm` 是把创作者的器材决定替他做了。

### 5.2 结构层的四条规律(大片感真正的来源)

1. **工作景别 + 阶梯**:一场先开宽一档建立地理,第二镜落到本场「工作景别」,之后在它上下邻格来回;**宽景和特写是「离开」工作景别的标记事件,用过就回来**,场尾略放开收住。一路单调收紧的场次到中段就没余量了。
2. **切点必须带来可见变化**:景别 / 水平角度 / 人物关系**至少变一项**;都不变就是跳切或穿帮——要么合并成一镜,用调度在镜内改变关系。
3. **动作-反应是基本单元,但 70/30 配比**:常规型(动作→反应)~30%、动作并置(蒙太奇)~15%、递进组 ~15%、链式衔接 ~10%;出彩型(反应省略 / 动作隐藏 / 反应前置 / 对比并置 / 视觉奇观 / 首尾闭环)合计 ~20–30%,且 **82% 的出彩镜头前后紧挨常规镜头**——出彩靠反差,连续两个就失效。
4. **五锚定调**(短片性价比最高):一个主情绪 · 一个视觉母题 · 一个锚物 · 一个断裂 · 一个终镜。5 条锚住的 30 秒,胜过无限堆 "cinematic, 8k, masterpiece"。

### 5.3 时长:不要按字数折算

来源:[shanyin 551 镜统计](https://github.com/Shanyin-ai/shanyin-director-master)【一手文档】

- 平均 **4.2s**、中位数 **3s**、**76% 落在 1–5s**
- 按叙事目的:推进/升级 **2.5–3.5s**(最快)→ 交代/展现/氛围 4–5s → 转折 **5–7s** → 升华/主旨 **6–10s**(最慢)
- 按「观众要读取几层信息」:1 层 ≈ 2–3s,每多一层 +2–3s;综合段落 10–15s
- 按镜头组:快切蒙太奇 1–2s/镜(3–14 镜塞进 6–20s)、递进介绍 2–3s、标准叙事 3–5s、**情绪留白 5–15s**
- 格式缩放:短片 3–5s → 长片 5–8s → 剧集 4–6s;**单镜上限 15s,超过必须有镜内视觉变化**
- 台词时长要「在脑中演一遍」这个角色此刻的语速/停顿/呼吸,再加**反应时间**;不是 4 字/秒

### 5.4 节奏梯(可直接做成预设)

来源:visual-skills §12【一手代码】

| 类型 | 序列 |
|---|---|
| Slow-burn 剧情 | 4s, 4s, 3s, 2s, 1s, **pause**, 2s |
| 商业产品 | 3s, 2s, 1.5s, 1s, **0.5s(产品微距)**, 2s(hero shot) |
| 焦虑累积 | 2s, 1s, 1s, 0.5s, 0.5s, 0.3s, **pause**, 1s |
| 冲击 | pause, **0.2s(闪)**, 2s(静止余波) |

规则:**最大的那一刀之前,必须留至少一个停顿。**

### 5.5 14 字段 shot card(视觉侧最全的一份)

来源:visual-skills §11【一手代码】

`Shot ID · Beat(这里什么变了) · Emotion · Frame(wide/medium/close/macro) · Composition · Camera · Movement reason · Action(精确物理事件) · Eye trace(前 0.3s 视线落点) · Duration · Cut type(match cut/smash cut/cut on action/J-cut/L-cut) · Sound · Light/color · Production note`

配套两条检查:
- **Three-detail rule**:每一镜必须有「环境压力 + 物理微动作 + 声音或视觉母题」三样细节,缺一即返回重写。
- **Three-jobs rule**:每一镜必须同时推进「故事 / 情绪 / 视觉」三件事。

## 6. 不同类型的分镜差在哪:两套正交分类

关键认知:**「视频类型」与「分镜表结构」不是一对一,是两个正交维度。**

### 6.1 轴一:内容形态 → 列集合 + 镜头语法 + 节奏 + 验收门

| 类型 | 本仓技能 | 分镜骨架 | 单镜时长 | 独有必备列 | 一致性靠什么 | 验收门 |
|---|---|---|---|---|---|---|
| 短剧/漫剧 | **无(缺口)** | 场→段→切 | 2–5s | 台词(逐字)+声景+视线+轴线侧+观众知情权 | 角色卡 + 衍生态(服装/伤态) | 每拍被恰好一镜认领;台词零删改 |
| 品牌 TVC | `brand-promo-video` | **节拍表**(不是场) | 1–3s,收尾 2–3s hero | 文案逐字 + 时间段 + 产品锚定 | 真实产品照片 image-edit | 产品保真;单条文案;无分镜痕迹 |
| 极简产品广告 | `minimalist-product-ad` | 精确节拍表 | 单镜连续 15s 或 3–5 节拍 | 文案进入时间/颜色/单行行为 | 锚定照片(3 张) | 禁 image-gen 画产品本体 |
| MV / 音乐 | `music-video-subtitle` | **拍点轴** | 1–2s 卡点 | 歌词行 + onset 秒 + 字幕样式 | 主音轨 `ref-audio` | 切点落在句间停顿/强鼓点 |
| 科普/讲解 | `paper-collage-explainer` / `papercraft-stop-motion` | 知识节拍 | 3–5s | 知识点(每镜只解释一个) | 画风签名 | 知识准确性 |
| 3D 动画短片 | `3d-animation-short` | 镜头表 → 文本分镜 | 2–6s | 每秒指令 + 连续性衔接 + 退场人物状态 | 角色卡 + 场景卡 | 六项自检门 |
| 游戏 CG/开场 | `co-op-game-intro` | 单镜 | 15s | UI 动效层 | 角色卡 ×2 | 单镜不拆 |
| 情绪/实验短片 | **无** | **五锚** | 3–5s | 母题 / 断裂 / 终镜 | 无 | 五锚齐备 |
| 纪录片/口播 | **无** | 素材 + 旁白轨 | 3–8s | 旁白 + 素材来源 | 出镜人 | 事实可溯 |

### 6.2 轴二:生产约束 → 决定「段」怎么切

| 约束 | 取值(本机 H3 现状) | 用法 |
|---|---|---|
| `maxSegmentSeconds` | H3 档位上限;长镜可到 30s+ | 段总时长硬门 |
| `maxCutsPerSegment` | **H3 支持单次多镜**(`[Shot k]` + 切点时刻) | 一镜一行 vs 一段多行 |
| `referenceSlots` | H3 `ref-image` 1–10 张 | 决定哪些资产进段、哪些靠首尾帧接续 |
| `nativeAudio` | H3 原生音频;mlxgen 出图无声 | 有声则声音进正文,无声则留后期 |
| `firstLastFrame` | H3 FL2VA 支持(**与 ref-image 互斥**) | 跨生成接续的唯一可靠手段 |

> 两轴组合才有意义:**TVC = 节拍表 + 段内多切 + 产品图必 ref**;**MV = 拍点轴 + 段长=乐句 + 主音轨必连**;**短剧 = 场段切 + 2–5s + 台词逐字门**。所以配置应是 `profile = 形态 × 约束`,而不是给每个技能硬编码一套表。

### 6.3 「怎么分类」:三个问题定位 profile

1. **信息密度**:观众每镜要读几层?(1 层 → 2.5s;3 层 → 7s+)
2. **情绪曲线**:有没有明确转折/高潮?(有 → 动作-反应编排 + 出彩镜配额;没有 → 节拍表 / 拍点轴)
3. **一致性压力**:同一张脸或同一处空间跨几镜?(≥2 镜 → 必须建卡 + 参考图槽位预算;1 镜 → 可纯文生)

答案直接映射到:列集合、节奏梯、段上限、验收门。**改分类 = 改 profile 数据文件,不是改代码。**

## 8. 改造方案(四步,按性价比排序)

### 第 1 步:删掉「电影感」兜底,改成量化光照(✅ 2026-10-28 已完成)

`assembleH3Prompt` / Z-Image 六段式的 `look` 默认值,已从形容词堆换成共用的 `DEFAULT_QUANTIFIED_LIGHT`;**风格词只允许来自 `basePrompt`(技能风格锁)**,不再内置「电影感 / 写实」兜底。实际落地的中性描述为:

```text
主光从主体右前方 45°、略高于视线照入，左后侧形成阴影；主体与背景保留明暗层次
```

`basePrompt` 经 `trim()` 后优先且原样进入提示词;显式「提示词(可选)」仍不覆盖。回归测试同时锁定 H3 与 Z-Image 的缺省量化兜底、`basePrompt` 优先级和旧文案消失。

⚠️ **桌面端验证必须重建并重启(2026-10-28「剧本生成测试」实测)**:Vitest 直接执行 `packages/shared/src`,而桌面端通过包入口加载 `packages/shared/dist`;只改源码、不重建时,单测全绿但 App 仍逐字输出旧兜底。`pnpm --filter @bigbotart/shared build` 后,直接 import dist 的 H3/Z-Image 验证通过;还需重启 Electron 让运行中进程加载新模块,并重新铺节点或重写提示词——**既有节点里的历史 prompt 不会被追溯修改**。

理由:§3.1 的「正文禁止写画风」。风格由渲染层/技能统一附加,per-shot 再写就会两边打架。

### 第 2 步:表从 10 列扩到「核心 10 + 扩展 12」(✅ 2026-10-28 已完成)

新增列**全部可选**,老表按表头映射,缺列不报错(保持 GFM 解析兼容):

`焦段` `水平角度` `机位高度` `构图` `视线` `焦点` `稳定性` `光位` `声景` `配乐` `站位(blocking)` `节拍`

同时把 `Camera: ${size} · ${move}` 拆成:

```text
Shot Size: 中景
Horizontal Angle: 斜侧 3/4(轴线左侧,与她同侧)
Height: 平视(势均力敌)
Lens Intent: 标准,中浅景深
Movement: 缓慢推近 20cm —— 理由:把观众从「她在看」推到「她看到了什么」
```

实际落地口径:

- `STORYBOARD_CORE_HEAD`(原 10 列)+ `STORYBOARD_EXTENDED_HEAD`(12 列)合成 22 列;旧表缺列/短行均由 `rowCell` 返回空串,不按新下标猜值。
- `storyboard.plan` 的 LLM JSON schema、行映射与确定性兜底均支持扩展字段;LLM 输出预算由 2400 提到 4000 tokens,降低多字段长表被截断的概率。
- H3 不再输出 `Camera:`;`Shot Size / Horizontal Angle / Height / Lens Intent / Movement` 独立成行,`构图 / 视线 / 焦点 / 稳定性 / 站位 / 光位`按非空值接入,声景与配乐分别进入正确的声音段。
- Z-Image 静帧六段式同步继承焦段、角度、机位、构图、视线、焦点、站位与光位;不把声景/配乐误写进图片提示词。
- 「节拍」只作规划与审阅元数据,不注入生成提示词;显式「提示词(可选)」仍尊重作者原文。
- 验证:`pnpm typecheck` 通过;`pnpm test` = 173 文件 / 2359 用例通过(7 个按原配置跳过);`pnpm build:packages` 后直接加载 dist 的 22 列与提示词冒烟通过。桌面端仍需重启 Electron 才会加载新包,既有节点中的历史 prompt 不会被追溯重写。

### 第 3 步:新增 `storyboard-schema.ts` 纯函数门(2–3 天)

放 `packages/shared/src/`,与 `shot-duration.ts` / `storyboard-materialize.ts` 同层,零依赖、可单测。先实现最便宜的三道:

| 门 | 规则 | 失败处置 |
|---|---|---|
| `composition` 门 | 同一段内每镜六字段(`焦段/机位/构图/视线/焦点/稳定性`)必填 | 拒绝并**指名缺哪镜哪字段** |
| 切点变化门 | 相邻两镜「景别 + 水平角度 + 人物关系」三项全同 | 警告「这个切点没有存在理由」,建议合并 |
| 时长链门 | 台词实测秒 ≤ 镜长 ≤ 段上限;Σ段 ≈ 目标时长 ±15% | 拒绝并给建议值 |

单测照 drama-skills 的门测试写;不新增外部依赖。

### 第 4 步:引入「段」,解锁单次多镜(1 周+)

`storyboard` 节点加可选 `segments[]`;同一段的多行 → **一次 `engine.submit`**,H3 prompt 走已有的 Ref2VA 骨架,把 `[Shot 1]` 扩成 `[Shot 1..k]` 且**每镜带 `At 00:03.000`**(切点时刻 = 前面秒数累计)。

- **收益**:跨切点一致性从「靠多张图硬拼」变成「模型内部连续」,硬切节奏可控。
- **代价**:单镜失败 = 整段重跑 → 必须先 preview 档 + 提供**段级重拍**(对齐即梦「片段重拍」)。
- **风险面**:`h3c-command.ts` 的参数面不动(仍是 32 倍数/档位/时长上限),只改 prompt 组装与提交粒度;需回归 `submit-ref-audio` 与 `queue-dedupe` 两组门(去重键要不要从 nodeId 变成 segmentId,是一个独立决策)。

### 附:技能侧怎么接(等前三步稳定后再做)

给技能加一个**声明式**字段 `storyboardProfile: 'short-drama' | 'tvc' | 'mv' | 'explainer' | 'product-ad' | 'animation' | 'mood-piece'`,由 `memory.buildContext` 注入摘要,由 `storyboard.plan` 读取对应 profile 的列集合/节奏梯/门阈值。**不要在 9 个技能正文里各写一套表**——那正是当前 `3d-animation-short` 六列镜头表与 `STORYBOARD_HEAD` 十列并存的成因。

## 9. 对照示例:同一句话的两种写法

原文:「女主推开门,看到桌上有一封信,震惊」。

**现在的表(必然产出大白话)**

> 画面描述:女主推开门,看到桌上一封信,表情震惊 · 景别:中景 · 运镜:推 · 提示词:`Scene: … Camera: 中景 · 推` `Look: 电影感,自然光影,写实`

**按新字段填(一段两切)**

| 字段 | 值 |
|---|---|
| 段 blocking | 她站在门口(画面左,距桌 3 步),桌在画面右后,信在桌面偏左三分交点 |
| 切 1 · 2.4s | 中景 / 斜侧 3/4 / 平视 / 标准·中浅景深 / **固定**(理由:让她自己走完这一步,观众等) |
| 切 1 构图·视线·焦点 | 门框做前景负空间框住她 · 视线先落桌面 · 焦点跟门把手 |
| 切 1 光 | 走廊冷白顶光打亮额头;室内暖台灯只照亮信纸一角(冷暖对撞 = 外部世界 / 秘密) |
| 切 1 声音 | 门轴吱响 → 冰箱嗡鸣;无人声 |
| **切点理由** | 从「她在看」切到「她看到的」——制造信息落差 |
| 切 2 · 1.2s | 特写 / **正俯** / 高 30° / **长焦·极浅景深**(把信从背景里"捏"出来)/ 微推向信纸抬头 |
| 切 2 构图·焦点 | 信居下三分,桌面木纹做引导线 · 焦点锁信纸抬头,她的手虚在前景 |
| 切 2 声音 | **J-cut**:纸张摩擦声比画面早进 0.4s |
| 切 2 光 | 只有暖台灯一角,其余压到近黑 |
| 节奏 | 2.4s → 1.2s(下一个动作要更快,为后面「转身找人」让速) |

同一句话,信息量差 6–8 倍。真正决定电影感的是 **「固定 + 理由」与「切点理由」这两栏**——不是任何一个形容词。

## 10. 风险与不做的事

1. **不要把 14 字段全塞进 prompt**。字段进表(给人看、给校验用),prompt 只取该模型能读的部分。H3 官方运镜词表是离散的(Static/Push In/Pull Out/Zoom/Pan/Truck/Tilt/Pedestal/Arc/Tracking/Shake/POV/Roll),写「缓慢推近 20cm 并轻微上升」它只会挑一个。
2. **焦段写意图不写 mm**。写 `85mm` 是替导演做器材决定,写「长焦压缩」是意图。
3. **画风必须收口到一处**(技能风格锁 / basePrompt),per-shot 再写就会打架。
4. **别为「景别多样性」增加切点**。切多少镜由动作边界、听者反应、信息变化解释;`切点变化门`是「已经决定切了,就必须变一项」,不是「必须切」。
5. **证据等级**:数据结构(§3)是一手代码;产品行为(§4)中即梦/可灵为二手实测;Sora storyboard 底层机制、Seedance 2.5 参数为未核实。不要把这些当验收标准。
6. **本次不做**:①不改 `h3c-command.ts` 参数面;②不引入外部依赖;③不改 `storyboard.plan` 的行→节点映射(第 4 步单独评审)。
