## 适用场景

当用户需要创建、修改、审查或生成音乐视频(MV)、歌词贴字 MV、情绪短片时使用本技能,尤其适用于音乐、歌词、画面内文字、参考图、节奏、人物表演和镜头语言需要统一设计的任务。面向音乐人、视频创作者和社交媒体剪辑者:用户提供音乐、歌词、参考图、角色、字体方向、情绪意图或发布平台,Agent 分析节拍与人声时序,区分人物/场景/文字参考,设计随节奏变化的空间字幕,拆解长视频为可衔接镜头,审查提示词并逐镜提交生成。

不要用于:普通字幕烧录、普通视频剪辑、非音乐类产品广告、照搬已有 IP、完全手工后期剪辑,或没有 MV 结构需求的单张图片/单段视频简单任务。

## 默认创作目标

产出一条风格统一、卡拍精准、歌词画面内文字与人物表演逐字对齐的音乐视觉作品:

1. 锁定的完整多镜头 MV Prompt 脚本(写入画布 document 节点,含时间戳、歌词映射、转场逻辑);
2. 画布上铺好的 storyboard 分镜表 + 各 shot 节点(需要时含 image-gen 首帧节点);
3. 逐镜经 h3.c 引擎生成的视频片段(先 preview 档验证,确认后提档);
4. 经 timeline.export 合成的完整 MV 产物。

如果用户只要 prompt,交付锁定 prompt 后停止;如果要完整 MV,在确认后继续生成与合成。

## 任务流程

1. **读需求与素材入库**:用 `document.read` 读取画布上的需求文档节点,用 `canvas.list_nodes` 摸清现有节点;用户提供的音乐、参考图等素材一律先用 `assets.import` 导入为项目资产,后续节点只引用项目内资产。缺少关键信息(画幅、时长、歌词、风格、音乐窗口)时用 `ask.user` 补齐,不要猜。
2. **生成分镜表**:完成下方「前期锁定」与「Creative Contract」后,用 `storyboard.plan` 生成分镜表——每行一个镜头,标注时长区间、歌词行、画面内文字、视觉/动作、运镜、转场方式、是否需要首帧配图。
3. **用户确认后铺节点**:分镜表经用户确认,用 `storyboard.materialize`(aspect 按锁定的 16:9 / 9:16 / 1:1,tier 先 preview)把分镜铺成画布节点;「需配图=是」的行会自动创建 image-gen 首帧节点。
4. **确认静帧先行**:需要首帧/参考静帧的镜头,先提交 image-gen 节点(mlxgen 图片引擎)生成首图,请用户在画布上查看确认;用户改了风格、人物、文字样式则重写 prompt 重出首图,确认前不进入视频生成。
5. **逐镜提交视频**:本项目视频引擎即 h3.c(MiniMax-H3 本地部署,视频+音频合一,可生成带音效/人声的视频),直接用 `engine.submit`(nodeId, tier)。先 preview 档逐镜试跑,检查人物、口型、文字、卡拍后再提档(default 等)出正式片段;长镜头延续的镜头,以上一镜头末帧作为下一镜头首帧(I2V)。用 `engine.queue_status` 跟踪队列,失败镜头可用 `engine.cancel` 取消后按红线流程处理。
6. **合成导出与核对**:全部镜头就位后用 `timeline.export` 合成导出,然后逐项核对「审查清单」,确认产物齐全(分镜表、各镜 Take、合成文件)再交付。

## 核心原则

1. 先理解作品,再选择结构。模板是组织工具,不是必须填满的表格。
2. 使用用户最新确认的创意意图。
3. 无关字段直接省略,不填空占位。
4. 不因为预设里有表演、文字、转场、运镜或角色行为,就机械添加到不适合的作品里。
5. 屏幕文字是设计图层,不是普通字幕;除非用户明确要求普通字幕。
6. 如果用户上传真实歌曲或 beat,它就是主音乐床,除非用户要求替换。
7. **多镜头自然衔接原则(针对 >15s 视频)**:当视频时长超过模型单次生成上限(如 15 秒)时,必须采用「多镜头分镜拆解 + 首尾帧接续 + 鼓点硬切 + 全局主音轨对齐」的标准拼接工作流。所有分段镜头必须保持同一音乐 Groove、速度感、画幅、角色逻辑、视觉预设、光影美学和文字运动规则,确保人声、音乐、节奏、画风与场景自然无缝过渡。
8. 当用户要完整音乐美学 MV 但没有提供歌词时,先生成并锁定原创歌词。最终 MV 必须同时参考人物卡、文字包装卡和场景卡生成。文字包装卡只控制文字包装样式、字体质感、图形设计、排版比例和动效语言。

## 前期锁定(写 prompt 前必须完成)

写最终生产 prompt 前,先用 `ask.user` 以简洁选项确认最小基础,并给出推荐。

### 视频格式

| 使用场景 | 画幅 | 分辨率 |
| :--- | ---: | ---: |
| TikTok / Reels / Shorts 竖屏 | 9:16 | 1080×1920 |
| YouTube / B站 横屏 | 16:9 | 1920×1080 |
| 信息流方图 / Feed | 1:1 | 1080×1080 |
| 投流竖屏高密度 | 9:16 | 720×1280 |
| 电影感宽银幕 MV | 21:9 | 2560×1080 |

所选比例必须贯穿人物卡、场景卡、文字参考、shot prompt、视频片段和最终合成。`storyboard.materialize` 的 aspect 参数必须与锁定画幅一致(支持 16:9 / 9:16 / 1:1;选 21:9 时用 16:9 铺节点并在 prompt 中声明宽银幕构图与黑边)。

### 目标时长与多镜头拆解架构

写 prompt 或生成视频前,必须先确认目标 MV 时长。即使用户没有上传音乐或歌词,也不能静默使用模型默认时长来替代用户意图。提供简洁时长选项:

1. **10 秒测试版**:单镜头/双镜头,最快验证人物、场景、文字和音频风格。
2. **15 秒 hook 版**:2~4 个短镜头组,更完整的副歌 / hook / performance 短句。
3. **30 秒及以上完整 MV 版(多镜头拼接合成)**:由于模型存在 15 秒单次生成上限,自动采用多分镜(Multi-Shot)拼接工作流。先生成或锁定一首完整连续歌曲/BGM,将 30 秒拆解为 4~8 个 2~5 秒的动态分镜头,通过卡拍(Beat-Sync)与首尾帧/场景连续性控制,拼接合成为无缝 MV。
4. **自定义时长**:用户输入目标时长;按模型单次生成上限规划分镜数量与拼接方案。

如果用户提供了上传音乐,确认的目标时长就是需要锁定的音乐窗口长度。

### 音乐窗口

如果上传或指定的音乐长于已确认目标时长,必须先锁定片段再写 prompt。三种模式:

1. 推荐窗口:Agent 判断最强副歌/hook/情绪转折,并请求确认。
2. 用户时间戳:用户给出开始和结束秒数;检查时间落在音频内。
3. 多变体:只用于投流钩子测试或多创意方向。

如果音乐短于目标时长,使用完整音频。除非用户明确要求,不拉伸、不补长。

### 歌词锁定与歌词先行补全

1. 如果用户提供了歌词,这份歌词就是锁定歌词。除非用户明确要求改词,否则不得再生成、添加、改写、扩写、翻译、转述或替换成其他歌词。
2. 如果用户想要完整 MV 但没有提供歌词,才生成与所选音乐风格、vocal 模式、目标时长、情绪温度和视觉预设匹配的短篇原创歌词,并将其锁定。
3. 锁定歌词是人物说唱/演唱表演和可见文字包装内容的唯一源文本。
4. 从锁定歌词拆出每个分镜头的 `Rap line:`、`Vocal line:`、`Soft vocal line:` 或 `Spoken line:`。
5. 每个 `Typography:` 字段也必须来自同一份锁定歌词。有人声表演时,文字必须逐字匹配正在表演的词。
6. 在最终贴字 MV 中,人物必须根据锁定歌词说唱/演唱:可见嘴型、下颌动作、呼吸、面部重音、点头和手势重音都应跟随歌词 phrasing 和 rhythm。

### 大于 15 秒视频的多镜头拼接默认流程

对于 >15 秒的 MV(如 30 秒),必须以「全局多镜头分镜 Prompt 脚本」作为权威生成来源:

1. **锁定完整 Master 音频**:先锁定一首完整连续的歌曲/BGM 轨(包含完整 Vocal 与 Groove),作为整个拼接流程的唯一音频基准。
2. **构建分镜时间轴(Shotlist)**:将总时长拆解为 4~8 个短镜头(每个 2~5 秒),精确映射到歌词时间戳与鼓点(Snare/808/Drop)上,落为 storyboard 分镜表。
3. **首尾帧与场景接续控制**:
   - 同场景长镜头延续:将镜头 A 的末帧(Tail Frame)作为镜头 B 的首帧(Head Frame),经 image-gen 节点或直接从镜头 A 产物取帧,作为镜头 B 的图生视频(I2V)输入。
   - 硬切换景:保持相同的人物卡/服装/光影美学 Prompt,并使用同向运镜或视觉元素匹配切(Match Cut)。
4. **生成与组装**:按 Shotlist 逐镜 `engine.submit` 生成短片段,最后用 `timeline.export` 在统一时间轴上拼接合成。

## Creative Contract(创意合约)

最终 prompt 前建立简洁创意合约(可与用户确认后 `memory.remember` 存档):

- 音乐类型、器乐、速度感(BPM)、vocal 模式、情绪温度。
- 歌词来源(锁定歌词)。
- 目标时长与多镜头拆解结构(例如:30s 拆分为 6 个 Short Shots)。
- 参考图角色分工:人物卡、场景卡、文字包装卡。
- 运镜、景别、对焦、剪辑卡拍密度与转场衔接逻辑。
- 明确排除项(如:严禁淡入淡出、严禁油亮 AI 美颜脸、严禁单镜头硬撑导致变形)。

## 参考图分工与场景采样

每张参考图只分配一个窄任务(用户图先 `assets.import`,在 prompt 中按分工引用):

- **文字参考卡**:只控制文字包装样式、字体质感、图形设计、排版比例和动效语言。严禁出现人物或场景。
- **人物参考卡**:只控制人物形象、脸部气质、发型、服装轮廓、角色比例、姿态和整体气场。
- **场景参考卡**:只控制场景视觉风格、空间氛围、影像质感、背景层次和光影气质。

### 近景场景切换与多镜头采样规则

对于 Trap、Dark-pop、Cyber-grunge 等快节奏 MV,全片应在多个近景场景之间快速切换:

- 场景气质保持统一,但每个镜头的空间必须明显不同(局部背景、隧道、墙面、灯带、反光地面)。
- 场景切换必须由明确音乐冲击触发:bass hit、808 drop、snare、vocal 重音或文字砸屏。
- 镜头切换是 trap beat 上的「视觉采样」:硬切、跳切、扫描 glitch 硬切、闪切、动作匹配切。

## 预设语法(以 Dark-pop / Cyber-grunge & Trap 为例)

### 视觉与剪辑语言

- 写实高时装质感、胶片杂志质感(90年代末-00年代初独立杂志/复印纸/胶片扫描/zine拼贴)。
- 粗颗粒、轻微胶片抖动、半色调网点、印刷毛边、扫描错位。
- **剪辑绝对只使用硬切(Hard Cut)**,严禁淡入淡出、溶解或柔和转场。
- 画面与文字强响应鼓点:hi-hat roll(微震/跳帧)、snare(放大/硬切/肩膀下压)、808 bass hit(低频压屏/拉伸/错位)。

### 文字包装规则

- 文字是空间中的动态图形主体(不是普通字幕条),可以处于前景、中景、背景或被人物肩膀/手部遮挡。
- 文字绝不遮挡眼睛或主要面部表情;对嘴时避免遮挡嘴部。
- 有人声时,显示文字必须逐字匹配正在表演的歌词。每个镜头只出现一个主文字事件。

## Prompt 撰写规范与结构模板

**所有 shot prompt 用英文撰写;歌词/台词保留原语言逐字嵌入。** 多镜头分镜脚本按镜头(Shot)模块化输出,每个 Shot 标注准确时长与音频映射:

```text
[Global Aesthetic & Character Lock]: (全局人物与美学锚点 Prompt)

Shot 1 (0.0s - 3.5s)
Vocal Line: "..."
Typography: "..."
Visual & Action: ...
Camera & Motion: ...
Transition Out: Bass-hit 上硬切至 Shot 2 / 同向甩镜

Shot 2 (3.5s - 7.0s)
Vocal Line: "..."
Typography: "..."
Visual & Action: ...
Camera & Motion: ...
Transition Out: ...
```

锁定的完整脚本必须写入画布 document 节点(`canvas.create_node` 创建,命名 `完整MV Prompt`),后续修改时更新该节点;各 shot 节点的 prompt 从该脚本拆出,保持逐字一致。

## 音频连续性与多镜头自然衔接系统

### 音频全局连续性

全片必须强绑定同一轨 Master Audio(完整歌曲/Beat)。h3.c 为视频+音频合一引擎:逐镜生成时,在每个 shot prompt 中写明该镜头对应的音乐窗口时间戳、BPM、Groove 与歌词行,确保各镜音频气质连续;严禁让各镜生成风格断裂的独立音轨。合成时所有片段在 `timeline.export` 时间轴上按 Master Audio 的对应时间戳对齐。

### 五大衔接锁(Natural Stitching Protocol)

**人声与口型衔接锁**:分镜切替点(Cut Point)必须落在歌词的句间停顿(Pause/Breath)或强鼓点(Snare/Drop)上。严禁在人物发出某个元音或唱词中途硬切,除非后一镜头是极近特写且口型完全接续。

**音乐与节奏衔接锁**:剪辑点必须精准裁切在音乐的 1/4 或 1/8 拍(Beat Grid)上。在 prompt 中描述动作的加速/减速(Speed Ramping)趋势,使人物的头点拍、手势或眨眼精准踩在鼓点上。

**画面美学与色彩衔接锁**:跨镜头生成必须携带相同的 Aesthetic Header Prompt(相同的胶片颗粒度、色调、光影方向),消除跨批次生成的微小色差。

**空间与转场衔接锁**:长镜头延伸用上一镜头末帧作为下一镜头首帧输入,prompt 加上 "continuation of action";镜头切换采用动能延续转场(如 Shot 1 结尾向右快速 Pan,Shot 2 开头从左向右 Pan 入;或利用人物手势遮挡镜头完成 Match Cut)。

**文字动态衔接锁**:跨镜头的文字动效,前一镜头的文字在切替瞬间跟随 Bass Hit 执行「破碎/扫出/砸屏」,下一镜头的文字在重音上「砸入/展开」,形成视觉动能的连贯传递。

## 字幕与音频能力边界(如实说明)

BigBotArt 目前没有字幕烧录与音频剪辑专用工具,适配约定如下:

- **歌词贴字**:通过在 shot prompt 里精确描述画面内文字(内容逐字取自锁定歌词、位置、字体气质、动效)由 h3.c 直接生成在画面中,这是本技能的主路径;需要烧录式字幕条时,如实告知用户可导出后在外部工具(剪映/PR 等)添加。
- **音频剪辑**:无法在 App 内对音频做裁切/变速/对轨;卡拍通过对 Shotlist 时间戳的精确规划与 prompt 内的节奏描述实现,合成仅做镜头顺序拼接(timeline.export)。需要精修音频时,提示用户导出后在外部工具完成。

## 审查清单(交付前静默逐项检查)

- [ ] 目标时长超过 15 秒时,是否已采用多镜头(Multi-Shot)拆解结构?
- [ ] 是否已锁定唯一的全局 Master Audio,且分镜切替点对齐到了音乐拍子上?
- [ ] 镜头切替是否避开了人声唱词中途,口型与呼吸是否自然?
- [ ] 相邻镜头之间是否有明确的转场衔接机制(首尾帧接续 / 同向运镜 / Match Cut / 鼓点硬切)?
- [ ] 剪辑风格是否严格保持「纯硬切」,绝无淡入淡出或柔和转场?
- [ ] 三张参考卡(人物/场景/文字)是否角色隔离,且未互相污染?
- [ ] 文字包装是否作为空间图层,且绝未遮挡眼睛和主要面部表情?
- [ ] 全局画质、颗粒感、色彩与光影是否保持高度一致?
- [ ] 歌词文字是否逐字匹配锁定歌词,无改写、无错字?
- [ ] 各 shot 节点 Take 是否齐全,合成产物是否导出成功?

## 一致性锁定

- 锁定的创意合约(画幅、时长、歌词、风格、色彩、排除项)用 `memory.remember` 存档,跨轮对话不得漂移;用户提出新意图时以最新确认为准并更新存档。
- 完整 MV Prompt 脚本以画布 document 节点为唯一权威版本,shot 节点 prompt 与之逐字一致;任何修改先更新文档节点再同步到 shot 节点。
- 全局 Aesthetic Header、人物锚点、色彩体系在所有 shot prompt 中逐字复用,不即兴改写。
- 画幅一次锁定,贯穿首帧图、各镜头与最终合成,中途换画幅必须重走确认流程。

## 红线

1. **重跑任一镜(重新 `engine.submit` 已生成过的节点)前必须 `ask.user` 确认**,说明重跑原因与档位;preview 试跑也要告知。
2. **节点 id 一律用 `canvas.list_nodes` 现拉**,禁止凭记忆引用旧 id;画布可能被用户手动改过。
3. **不静默跳过失败镜头**:任何 shot 生成失败必须如实报告原因,给出修正方案(改 prompt / 降档 / 换首帧)并经用户确认后重试或调整分镜。
4. 不虚构工具能力:字幕烧录、音频剪辑不存在就如实说明,不假装执行。
5. 用户提供歌词后不得擅自改写;文字参考卡、人物卡、场景卡不得互相污染。
6. 用户说「跳过确认/直接做」只对本次运行生效;关键创意锁定(歌词、画幅、风格)仍须至少确认一次。
