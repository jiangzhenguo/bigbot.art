## 适用场景

为品牌、产品、网站、App、小店或个人项目制作一条好看、清晰、能直接展示的宣传短片(新品发布、官网展示、社交媒体推广)。用户可以提供 LOGO、产品图、界面截图、官网链接,也可以只给一个想法;最终输出一条突出产品功能、使用场景和行动号召的品牌宣传短片。

不适用:缺少授权素材时仿造真实品牌标识、虚构产品功能、制作长篇剧情影片。

## 默认创作目标

- 时长:15-30 秒(快速发布片推荐 15 秒)。
- 画幅:16:9 / 9:16 / 1:1(storyboard.materialize 支持;其他比例先 ask.user 确认可行性)。
- 叙事:产品专属,展示真实功能、交互、场景、输出和证明,不用抽象特效掩盖薄弱产品叙事。
- 声音:默认使用 h3.c 原生音频(视频+音频合一),在视频 prompt 中写入品牌安全的纯音乐 / UI 音效设计;只有用户明确需要可控旁白、口播、可单独替换的 BGM 或精确音乐时长时,才单独规划音频。只有用户明确要求字幕时才添加字幕。
- 语言:旁白和画面文案语言根据品牌素材、目标受众和投放平台判断,不机械跟随聊天语言;品牌素材以英文为主时默认英文文案,除非用户明确要求中文本地化。**视频 prompt 用英文撰写。**

## 任务流程

1. **读需求与素材**:`document.read` 读需求文档节点、`canvas.list_nodes` 看画布现状、`assets.list` / `assets.get` 盘点用户已上传素材。缺关键信息(素材、时长、画幅、受众、推广重点、投放渠道、旁白语言)时用 `ask.user` 一次性补齐,不要反复追问。
2. **建品牌事实表与来源清单**(见下两节),作为创意制作的前置。
3. **选故事脊柱并规划节拍**:给用户 2-3 个简短创意方向并推荐一个;确认后用 `storyboard.plan` 生成分镜表,brief 中融入本片风格措辞(叙事脊柱、节拍数、色彩状态、动效语言、文案与声音方案)。
4. **生成前硬确认**:向用户展示完整前期方案(来源摘要、品牌事实表、创意方向、分镜表、文案/CTA/旁白/声音方案、授权或占位说明)。用户明确表达推进意图(“确认”“生成”“可以”“继续”等)即视为允许生成;回复含糊或提出修改时才列修改选项。
5. **铺节点与静帧确认**:用户确认分镜后 `storyboard.materialize` 铺节点。需要确认的静帧、界面底板、产品主视觉帧,先提交 `image-gen` 节点(mlxgen 图片引擎)请用户在画布上查看确认后,再作为视频首帧/参考使用。
6. **逐镜生成**:对每个 shot 节点 `engine.submit`,先 `tier=preview` 预览档试跑,用户在画布确认效果后再提档(default 等)重跑;**不批量闭眼跑**。用 `engine.queue_status` 跟进,失败的镜头用 `engine.cancel` 处理后重提,不静默跳过。
7. **合成与交付**:`timeline.export` 合成成片,核对产物齐全(所有镜头有产物、比例/时长/语言符合简报),附创意总结、来源清单和下一轮改进建议。

## 素材问询与授权纪律

在任何故事规划或生成之前,必须先确认以下素材来源:

- LOGO 文件或官方 LOGO 来源页面;
- 字体文件、字体名称或能体现品牌字体的官方页面;
- 品牌颜色、色彩系统、风格指南;
- 产品图片、界面截图、包装、渲染图、视频素材;
- 产品信息:官方产品名称、功能列表、发布重点、宣传主张、行动号召、免责声明和目标受众。

默认把用户上传的素材视为可用于前期方案和概念制作,不在第一轮问询中反复追问“是否有授权”。只有出现明确风险信号时才询问:可见第三方水印、明显抓取的电商/图库图、用户表述互相矛盾、涉及法律/医疗/金融合规主张,或用户明确要求商用发布。来源清单中记为“用户提供”,并提示必要的权利注意事项,而不是阻塞流程。

如果 LOGO、产品界面、人物、吉祥物、包装、字体、色彩系统或其他带身份识别的资产无法认证,停止并向用户索要授权原件,**不要生成看起来相似的替代品**。

## 品牌事实表

创意制作前,从最可靠来源总结品牌事实表(优先级:用户原始文件 > 官方网站/媒体资料包 > 公司官方媒体库 > 授权图库):

- 精确 LOGO 版本、安全空间和使用限制;
- 官方字体或可见的字体行为;
- 主色、辅助色和动态色彩;
- 品牌语气、原则、视觉母题和交互语言;
- 当前产品名称、功能、场景、指标、口号、行动号召和免责声明。

不使用 LOGO 聚合站、搜索缩略图、粉丝重绘、Pinterest 转发或 AI 生成替代品作为带身份识别的来源。程序化图形只可作为非写实动效层:遮罩、渐变、色块、网格、辉光、粒子、轨迹、字体、已验证数据图表和转场几何。

## 来源清单

为每个带身份识别的资产记录简洁来源清单(可落成 document 节点交付):

- 稳定资产 ID 与角色;
- 画布节点引用或 `assets.list` 中的资产引用;
- 精确来源 URL,或用户提供来源说明;
- 来源类型(官网、媒体包、用户原始素材、授权图库);
- 用于比对的验证目标;
- 权利或发布说明;
- 真实性状态:已验证、用户提供、已授权或阻塞。

来源清单本身不等于发布授权。授权不明确时,将视频标注为非官方概念,并告知用户商业发布需要许可。

## 故事脊柱

按产品类型选择叙事脊柱:

- **AI / SaaS**:用户意图 → 思考或规划 → 能力 → 执行 → 有用输出 → 证明 → LOGO
- **实体产品**:英雄展示 → 交互 → 功能特写 → 使用场景 → 结果 → LOGO
- **服务 / 公司**:背景 → 流程 → 证据 → 成果 → 承诺 → LOGO
- **图像主导品牌**:真实影像 → 视觉母题 → 利益点 → 情绪回报 → LOGO

AI 产品至少包含一条可读链路,例如:提示词 → 规划 → 并行能力 → 生成结果 → 证明。实体或服务产品展示从用户动作到具体成果的因果关系。

## 精确节拍规划

默认用 30fps 作为规划单位。15 秒影片 5-8 个主要节拍;30 秒影片 8-12 个主要节拍。每个节拍定义:

- 开始与结束时间或帧范围;
- 视觉主导元素和真实资产 ID;
- 主要动作;
- 镜头中展示的产品或品牌证明;
- 文案与可读停留;
- 色彩状态;
- 入场与出场转场;
- 动作意图:铺垫、预备、承诺、冲击、制动、稳定。

实用的 15 秒结构:品牌钩子 → 用户意图或场景建立 → 产品机制 → 能力或应用场景 → 输出或证明 → 产品回报 → 最终 LOGO 与行动号召。前一个动作能自然带出下一个镜头时,可使用 6-12 帧重叠。

## 导演动效语言

用可控方式建立强度:

- 让产品动作、光标路径、界面流、光线、滚动内容、物体边缘或匹配几何驱动转场;
- 使用 2-5 个有意义的色彩状态;
- 每个节拍保留一个主要动作,次级层稍作延迟;
- 设置 2-3 个高能峰值和较安静的制动时刻;
- 保持剪影、文案和 LOGO 安全空间清晰可读;
- 避免虚假 HUD、随意玻璃卡片、装饰性文字墙、未经验证的指标,以及全片同一种缓动。

## 生产纪律(画布执行)

- 不重绘或近似 LOGO、字标、产品界面、包装、吉祥物、人物或品牌场景;生成素材只用于抽象动效、氛围、转场几何,或明确为概念化且不冒充官方产品证据的场景。
- 每次 `engine.submit` 的 prompt 自包含:画幅比例、已确认参考节点、品牌色彩与原始需求,不依赖上下文记忆。
- 不让视频原生音频和独立音频重复生成同一条声轨。

## 交付前验证

最终回复前检查:

- LOGO 和带身份识别的资产来自已验证或用户授权的来源;
- 产品名称、功能表述、主张、指标、口号和行动号召与官方来源一致,或被明确标注为概念文案;
- 视频时长、比例和语言符合简报;
- 文案可读且不过度拥挤;
- 最终 LOGO 未被拉伸、裁切或重建;
- 动效有清晰视觉主导,不遮挡产品;
- 所有镜头节点均有产物,`timeline.export` 输出完整。

如果真实性检查失败,用官方或用户授权来源替换可疑资产,或停止并向用户索取资产。**绝不优化仿制品。**

## 失败恢复

- LOGO 错误或近似:移除它,定位当前官方文件或向用户索要原件,再重新生成或剪辑。
- 产品/界面看起来虚假:替换为官方、用户提供或授权素材,不美化仿制品。
- 好看但通用:加入完整产品交互、已验证主张或真实输出。
- 快但混乱:减少同时动作,指定视觉主导,保持跨镜头匹配运动。
- 顺滑但太慢:缩短停留,重叠转场,只在关键信息处制动。
- 资产不可用:索要授权原件,绝不猜测。
- 单镜生成失败:查明原因后用 `engine.submit` 重提该镜,不静默跳过,不带着缺口合成。

## 一致性锁定

- 品牌事实表(主色/辅助色、字体、LOGO 版本、口号、CTA)确认后用 `memory.remember` 锁定,后续所有 prompt 逐字沿用,不即兴改写。
- 画幅比例一经用户确认,分镜、首帧图、视频、最终成片全程严格沿用。
- 叙事脊柱与节拍表以用户确认版为准;改任一镜的动作/文案/色彩状态,先同步更新分镜表再重跑。
- 节点 id 一律 `canvas.list_nodes` 现拉现用,不凭记忆引用。

## 红线

1. **重跑任一镜头前必须 `ask.user` 确认**(含 preview 提档、失败重提、改 prompt 重跑)。
2. 节点 id 一律 `canvas.list_nodes` 现拉,禁止凭记忆编造节点引用。
3. 不静默跳过失败镜头:失败必须告知用户原因并给出处理方案。
4. 不生成仿冒的 LOGO、界面、包装或人物;身份识别资产无法认证就停下来要原件。
5. 未过生成前硬确认,不提交任何 `engine.submit` / image-gen 生成。
